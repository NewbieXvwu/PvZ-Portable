# 任务：用沙箱里的引擎把《植物大战僵尸》的指定关卡打通，交回操作序列

你拿到的是一个**离线**的、无窗口的《植物大战僵尸》1.2.0.1073 复刻引擎，以及一层
Python 接口。你的产物是**每关一份操作序列存档**：在什么 tick、用什么卡、种在哪一格。
这些存档会被拿回我们的机器上用同一个引擎逐位重放校验，所以它必须是引擎真正接受的动作。

这是一个按请求计费的会话。**一次请求里可以连续工作约 3 小时**，也可以并行开 3 个子代理。
中途用户可能会粘贴补充信息，照着调整即可。

## 3. 接口速查

一局 = **(任务, 操作序列)**。所有动作都记在内存里的操作日志上；`save()` 把它写到磁盘。
工具调用之间进程可能被回收，**磁盘上的日志才是唯一的真相**。

```python
from llmplay import Game, list_tasks

print(list_tasks())                       # 有哪些任务

g = Game("demo_roof_49_doom_m200")        # 或 Game(task_id, seed=...)
print(g.observe())                        # 文字局面（brief 一屏；full 更详细）
print(g.legal())                          # 当前合法动作：每个卡槽能种哪些格 + 能铲哪些格
print(g.summary())                        # 波 / 最远存活波 / 剩余小推车 / 阳光 / 各行威胁

g.plant(card, row, col)                   # card 是 observe() 里的卡槽序号 [0] [1] ...
g.shovel(row, col)
g.wait(300)                               # 推进 300 tick（100 tick ≈ 1 秒）
g.wait_until("wave:8")                    # 也可以 wait_until(12345) 或 wait_until(lambda g: ...)
g.wait_until(wave=8)

g.rewind(4200)                            # 回到 tick 4200，之后的操作覆盖原来的后续
h = g.branch()                            # 复制一份独立的局，各自往下打
g.save("/mnt/data/out/run.json")          # 存操作日志
g2 = Game.load("/mnt/data/out/run.json")  # 读回来（会从开局重放到当时的位置）
g.export_archive("/mnt/data/out/l49_seed20261049")   # 导出可校验存档
```

要点：

- `plant` 的 `card` 是**卡槽序号**，不是植物编号。`observe()` 最后几行会打
  `卡槽：[0]向日葵 50☀ 就绪 | [1]花盆 25☀ 冷却120 | ...`，`legal()` 里也是同一个序号。
- `plant` / `shovel` 返回 `True` 表示引擎接受了这个动作，`False` 表示被拒绝（没花阳光、没占格）。
- 动作时间轴完全自由：**任意 tick 都能做动作**，不需要等任何决策点。
- 阳光自动收集（和人类示范一致），你不需要点阳光。
- `observe(level="full")` 会多给僵尸密度棋盘、逐路明细和每只僵尸的血量/位置。
- `export_archive` 会写 `ticks.jsonl` / `frames.jsonl` / `meta.json`，
  `label_source` 是 `llm_gpt_pro`。**每通关一关就导出一份。**

## 4. 允许写搜索程序，但有硬止损

你可以写任何脚本（穷举、贪心、束搜索、随机重启……）来挑动作。**但是**：

- 每关先用搜索，最多 **25 分钟**。
- 每 **10 分钟** 记一次"最远存活波"。连续两个检查点没有提升 ≥ 1 波，
  或者 25 分钟到了还没有一局通关 → **立即停止全局搜索，转手动**。
- 手动 = 按波推进：读当前局面 → 写一段覆盖接下来 **1–3 波**的脚本 → 执行 → 看摘要 →
  不满意就 `rewind` 重写这一段。
- 手动模式里允许**局部**小搜索：单段 ≤ 20 个变体、≤ 5 分钟，用来挑这一段的最好写法。
- 同一段 rewind 超过 **8 次**仍过不去，就退回更早一段重写。
- 一关累计超过 **70 分钟**仍未通关：保存最远进度的存档，换下一关，有余力再回来。

## 5. 纪律（会被机器检查）

- **不改引擎，不碰内存与状态。** 所有影响只能通过上面的 API 动作发生。
  不要 patch 二进制、不要改 `main.pak`、不要伪造存档里的哈希。
  交回后我们会在原版引擎上逐位重放；改过引擎或伪造过的结果一律作废。
- 不要试图读别的进程内存、不要改 `ticks.jsonl`。存档里的每一行都会和重放结果逐位比对。

## 6. 交付

- **持续交付**：每通关一关、每打出新的最远纪录，就立刻把存档追加进 `/mnt/data/out/`
  并重新打包成 `/mnt/data/out/out.zip`（`cd /mnt/data && zip -r out/out.zip out` 之类）。
  用户会在中途取走这个 zip —— **不要等到最后才打包**。
- 到 **2 小时 45 分**时停止开新局，只做打包与说明。
- 交付物：
  1. 每关的存档目录（`export_archive` 的产物）；
  2. `report.md`：每关结果（通没通、末波、剩余小推车）、用了搜索还是手动、
     卡在哪一波、怎么解决的、花了多少时间；
  3. 你写过的搜索/脚本代码（只用于我们分析，不进生产）。

## 7. 时间

**把 3 小时用满。** 没到 2 小时 45 分不要主动结束；清单上的都做完了，就按
`configs/extra_seeds.json` 换种子继续打，或换同关卡的其它卡组。
