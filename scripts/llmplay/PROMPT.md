# 任务：不断扩展《植物大战僵尸》各关卡的胜利卡组

你拿到的是无窗口的《植物大战僵尸》1.2.0.1073 复刻引擎及 Python 接口。
每局产物是一份真实操作序列存档：什么 tick、用什么卡、种在哪一格。
本次目标是**胜利卡组的广度和结构多样性**。

## 0. 这个任务没有终点

**不要总结收尾，不要询问是否继续，不要问“接下来做什么”。**

- 完成一局就立即调用 `next_task()`，继续下一项。
- 每关达到基础目标后，接口继续提高目标，每次增加 4 套，并优先提示卡牌覆盖缺口。
- `progress()["complete"]` 永远是 `False`，这不是 bug。
- **唯一停止条件是用户在对话里说停。** 已做很多局、生成报告、阶段达标、时间长，都不能作为结束理由。
- 按 **≥10 小时**设计：全包基础目标共 592 套胜利卡组；各片都要持续探索，10 小时不是停止条件。
- `report.md` 和 `out.zip` 每局自动更新；生成后立即接着打。

## 1. 解包与选择会话分片

把 `llmplay_pkg.7z.001` 等全部分卷解到同一目录，进入生成的 `llmplay_pkg/`。
`llmplay_res.zip` 保持原样放在接口目录旁，首次 `import llmplay` 自动安装资源和缓存。
不需要联网、编译或自行运行自检。

**同时开几个 GPT Pro 会话时，每个会话先指定不同的片号，之后保持不变。**
默认共 3 片，片号从 0 开始：

| 会话 | LLMPLAY_SHARD | 关卡 |
|---|---|---|
| 第一个 | 0 | 白天＋夜间 |
| 第二个 | 1 | 泳池＋雾 |
| 第三个 | 2 | 屋顶＋Boss |

在每个执行脚本的最前面设置；推荐把它放进你自己的公共入口，再导入接口：

```python
import os
os.environ["LLMPLAY_SHARDS"] = "3"
os.environ["LLMPLAY_SHARD"] = "0"  # 第二个会话改为1，第三个改为2
# 独立沙箱可用这个位置；若共用文件系统，各片须指定不同目录。
os.environ["LLMPLAY_OUT"] = "/mnt/data/out"
import llmplay
item = llmplay.next_task()["item"]
print(item)
```

也支持 `llmplay.next_task(shard=0, shards=3)` 或 `llmplay.configure_shard(0, 3)`。
这两个参数只影响当前进程；新进程仍要设置相同的环境变量或参数。
其他 N 片（1–41）按完整关卡列表轮转分配；`shards=1, shard=0` 可单会话覆盖全部关。
关卡之间的种子窗口互不重叠，每个普通关排除小游戏和传送带关。
L50 使用接口已支持的自选卡组开局；其余关卡范围是 L1–49 中非 5 的倍数。
默认首批种子窗口：片0在 186000000–204999999 内，片1在 206000000–224999999 内，
片2在 226000000–235999999 内（中间的小游戏窗口不用）。每关一个百万种子窗口，
用完按 50000000 的间隔顺延，不会因预列种子耗尽而停止。

## 2. 每项怎么完成

一项 = **(关卡, 种子)**。队列给关卡和种子，你自选卡组。

- 仅打**原版 1.0 倍、不截波**；沿用二周目普通植物全解锁、升级植物已购买的设定。
- 每套新卡组须与**本关全部已登记胜利卡组至少差 2 张**，包含前次沿用的胜利记录。
  卡片顺序不计；删一张加一张只算换一张；不同大小按两边独有卡数的较大值计差异。
  不能把胜利卡组换个顺序或只换一张继续刷数量。
- **赢 1 局就登记完成这套卡组，立即换新卡组。** 不做稳健复验，不做打法层，不做加压。
- 同一卡组输了，可以换队列给的新种子再试，**总共最多 3 个败局**。
  第三次失败须在这局的 `note` 写一句具体原因，再换卡组。`Game()` 会拒绝三败卡组。
  前两败后也可以提前换组；`retry_deck` 给的卡组只是建议。
- 中途导出不算败局；`abandon()` 不算真实败局；重开或重复导出同一种子不增加胜负计数。
- 门禁/挑选留出卡组的签名全部禁用，跨关也禁止，接口直接拒绝。

每关基础目标：白天、泳池各 **12 套**；夜间、雾、屋顶、Boss 各 **16 套**。
每关至少 **3 套 6–7 张**、至少 **3 套 8 张**，其余可 9–10 张。
队列的 `required_lengths` 给出当前新卡组应选的大小，先补大小配额，再自由变化。

同地形内，每张合法且未被列入黑名单的卡，至少出现在 **2 套不同的胜利卡组**里。
同一签名在不同关获胜，在地形覆盖里仍只算一套。`priority_cards` 提示覆盖缺口；
优先围绕这些卡形成不同结构，不要只把它塞进固定主干占一个槽位。
覆盖目标在 `configs/llmplay_seeds.json` 的 `decks` 配置里，重点卡后续由主控补充。

每套卡组用 `Game(..., reason="...")` 写一句**核心思路**，会原样存入 `meta.json` 的
`deck_reason`：交代经济、主力、防守、应急、地形专用卡各是什么；没有的组件明确说没有。
例如：“向日葵经济，卷心菜主力，坚果防守，樱桃应急，花盆覆盖屋顶。”
`strategy` 和 `deck_review` 可补充，但不再是分层配额或必填项。

## 3. 接口速查

```python
import llmplay
from llmplay import Game
item = llmplay.next_task()["item"]  # 已占位，同一关卡+种子不会重复分配
print(item)  # legal_cards、required_lengths、registered_decks、priority_cards

if item["action"] == "resume":
    g = Game.load_archive(llmplay.out_dir() / item["archive"])
else:
    # 先按本关地形、大小配额、覆盖缺口设计cards；这里不提供固定卡组。
    cards = your_new_deck
    g = Game(item["task_id"], seed=item["seed"], deck=cards,
             reason="经济用…，主力用…，防守用…，应急用…，地形专用卡用…")
print(g.observe())
print(g.legal())
print(g.summary())
print(g.timeline())

g.plant("sunflower", 2, 0)  # 名字或卡槽序号；不是植物编号
# 根据可见局面继续种植和推进，直到真实终局。
g.wait(300)                  # 100 tick约为1秒游戏时间
g.wait_until("wave:8")       # Boss没有波次，按tick或条件推进
# 可用g.branch()作局部探索，g.rewind(tick)重写一段。

g.note = "本局观察；若这是同组第三败，写清失败原因"
g.export_archive(llmplay.out_dir() / f"l{g.spec.level}_{g.seed}_{g.attempt_id}")
g.close()
item = llmplay.next_task()["item"]  # 立即继续
```

`action` 为 `new_deck` 时设计新组；`retry_deck` 时可沿建议卡组再试或直接换新组；
`resume` 时恢复给出的中盘存档。`busy` 表示这些项已被同目录的其他执行进程占用，
先继续自己手头的局；不要把它当作会话完成。不同会话使用不同分片与独立输出目录。

卡组 6–10 张、不重复，植物编号来自 `PLANTS.md`。只使用 `legal_cards`；
泳池/雾必须带睡莲(16)，屋顶/Boss必须带花盆(33)。升级植物只能种在底座上，
例如香蒲在睡莲上，忧郁菇在大喷菇上；升级所有权由接口自动声明。
按地形黑名单只排除无用途的卡，不按强弱限制卡组；不用戴夫随机推荐来判断用途。

`plant()` 整数是 **卡槽序号**，也可用英文名或中文名。行列均从 0 开始。
`plant` / `shovel` 返回引擎是否接受；阳光自动收集，无需点击。
`observe()` 给局面、卡片冷却、可见倒计时、逐行明细与事件；`timeline()` 给逐波历史。
未来出怪顺序和随机数状态不在观测里。所有数值以引擎和 `PLANTS.md` 为准。

## 4. 持续工作与续跑

工具调用间进程可能被回收，**磁盘上的操作日志才是唯一真相**。
可以一次写几十至几百步脚本；脚本退出时接口自动打印最后推进那局的局面。
中盘用 `g.save(path)` 保存，下次 `Game.load(path)` 接着打；已导出的局用 `Game.load_archive(path)`。
需要换卡时可 `g.abandon(reason="具体原因")`，自动保存并释放引擎，再拿下一项。
沿用接口的固定模拟 tick 搜索预算、分支限制和重写止损；没有会话总时间上限。
达到搜索止损就按可见局面逐段推进，不要以此结束会话。

每次导出或放弃，`llmplay.out_dir()` 自动更新：

- `progress.json`：每关胜利卡组数、大小配额、所有已登记胜组和各地形逐卡覆盖；
- `report.md`：本片逐关进度、逐卡覆盖、三败原因；
- `budget.json`：续跑的搜索与重写计数；
- `out.zip`：存档、进度、报告、预算以及 out 下的代码与说明。

不要自行改写这些自动文件。你的执行脚本和选卡思路放进 `out_dir()`，会随结果保存。
包内 `carry/progress.json` 若存在，首次导入自动接上前次结论；不会重新打旧胜局。
另有完整 `out.zip` 时用 `llmplay.resume(path)` 恢复，**只搬记录，不重放复验**。
仅恢复你原来那一片；所有新进程保持原片号。接完就调用 `next_task()` 继续打。
