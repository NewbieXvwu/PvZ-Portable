# 任务：用沙箱里的引擎把《植物大战僵尸》的关卡打通，一轮接一轮地打下去

你拿到的是一个无窗口的《植物大战僵尸》1.2.0.1073 复刻引擎，以及一层 Python 接口。
你的产物是**每局一份操作序列存档**：在什么 tick、用什么卡、种在哪一格。存档会被拿回我们的
机器上用同一个引擎重放校验，所以它必须是引擎真正接受的动作。

---

## 0. 这个任务没有终点

**不要总结收尾，不要询问是否继续，不要问"接下来做什么"。**

- 完成一项就立刻调 `next_task()` 拿下一项，接着做。
- 一圈（cycle）做完，接口自动把你送进下一圈，任务量不会变少。
- `progress()["complete"]` 永远是 `False`，这不是 bug。
- **唯一的停止条件是用户在对话里说停。** 在此之前，你的默认行为就是继续打。

如果一次回复里只打了一局就停下问"要不要继续"，那等于没干活。

---

## 1. 开始

1. 解压 `llmplay_pkg.7z.001` 等全部分卷（接口、引擎、配置），进入生成的 `llmplay_pkg/`。
2. 资源包 `llmplay_res.zip` 保持原样放在接口目录旁边。首次 `import llmplay`（自检也会导入）
   自动安装资源和缓存；接口与资源必须配对。资源 zip 在别处时可设 `PVZ_LLMPLAY_RES_ZIP`。
3. 先执行 `python3 selfcheck.py`，最后一行必须是 `SELFCHECK OK`。
   **如果 Python < 3.10 或不是 x86_64 Linux，按它的报错说明处理。**
4. 看当前该做什么：

```python
import llmplay
llmplay.paths()            # 实际路径
print(llmplay.next_task()) # 当前圈当前层必须做的那一项
```

交付目录由接口选：`LLMPLAY_OUT`；否则默认沙箱目录；否则包目录旁的 `out/`。以 `paths()` 为准，
所有交付路径用 `out_dir()` 拼接。

## 2. 工作流：一圈五层，逐层下传

**顺序由 `next_task()` 强制，不能跳层、不能自选顺序。** 当前层没做完，下一层的任务
`Game()` 会直接报错并告诉你现在该做什么。每一层的产出是下一层的输入；一圈做完自动进下一圈。

| 层 | 内容 | 每关必做量 | 下传什么 |
|---|---|---|---|
| **A 探索** | 屋顶 L41–L49 共 9 关 + 白天/夜间/泳池/雾夜 12 关，原版 1.0 倍，**自选卡组** | 4 套彼此明显不同的卡组（两两至少差 3 张、核心思路不同），每套赢 2 个不同种子 | 每关胜局最多的 2 套 → B、D 层 |
| **B 稳健** | A 层下传的卡组 | 每套 2 个种子过稳健复验（第 10 波 k=8 赢≥5） | 过了稳健的卡组 → D、E 层 |
| **C 挑战** | **指定卡组**（任务里写死，不能换），我们的 AI 打不赢的那些 | 每套卡组 5 个种子里赢≥2；5 个全输就写失败诊断，也算完成 | 赢下的局直接交付 |
| **D 打法** | B 层下传的卡组 | 每套用 3 种**声明的不同开局节奏**（经济优先 / 防线优先 / 速攻或爆发清场），每种赢 2 个种子 | — |
| **E 加压** | B 层下传的卡组 | 出怪倍数 1.5 和 2.0 各赢 2 个种子 | 下一圈 A 层的参考 |

下一圈：新种子（每圈一个 40 个种子的窗口，互不重叠）；A 层的 4 套卡组必须和**之前所有圈**
用过的卡组都至少差 3 张卡；C 层换下一批挑战卡组（列表循环）。

`next_task()` 返回的 `action` 就是下一步该干什么：

| action | 意思 |
|---|---|
| `new_deck` | A 层：自选一套和已有卡组差≥3 张的新卡组，打这个种子 |
| `second_seed` | A 层：这套卡组已赢 1 个种子，同卡组再赢 1 个不同种子 |
| `improve_robustness` | B 层：读它给的 `archive`，用闭环打法跑 `robustness()` |
| `play` | C/E 层：用任务指定（C）或下传（E）的卡组打这个种子 |
| `diagnose` | C 层：5 个种子都没赢 2 局，写失败诊断 |
| `new_strategy` | D 层：换一种开局节奏，`strategy` 不能和已用的重复 |

## 3. 接口速查

一局 = **(任务, 卡组, 操作序列)**。所有动作都记在操作日志上；`save()` 把它写到磁盘。
工具调用之间进程可能被回收，**磁盘上的日志才是唯一的真相**。

```python
import llmplay
from llmplay import Game, next_task, list_tasks, diagnose

item = next_task()                        # {"task_id","seed","layer","action","deck",...}
print(list_tasks())                       # 本圈还没做完的任务

g = Game(item["task_id"], seed=item["seed"], deck=[1,33,39,44,15,3],
         reason="先试投手线", strategy="投手压制")
print(g.observe())                        # 完整文字局面
print(g.legal())                          # 每个卡槽能种哪些格 + 能铲哪些格
print(g.summary())                        # 波 / 最远存活波 / 剩余小推车 / 阳光 / 各行威胁
print(g.timeline())                       # 每波一行的历史（回头决定 rewind 到哪）

g.plant(card, row, col)                   # card 是 observe() 里的卡槽序号 [0] [1] ...
g.shovel(row, col)
g.wait(300)                               # 推进 300 tick（100 tick ≈ 1 秒游戏时间）
g.wait_until("wave:8")                    # 也可以 wait_until(12345) 或 wait_until(lambda g: ...)

g.rewind(4200)                            # 回到 tick 4200，之后的操作覆盖原来的后续
h = g.branch()                            # 复制一份独立的局（搜索用）
g.deck_review = "前期省，后期缺群伤"        # A/D 层导出前必填
g.export_archive(llmplay.out_dir() / "l49_seed_1")
g.abandon(reason="前排扛不住，改用爆破")    # 自动存档并释放引擎，可同种子换卡重开
diagnose(task_id, waves=[8], missing="第 8 波后排水路缺群伤")   # 只在 C 层 5 个种子全输时用
```

`plant` 的 `card` 是**卡槽序号**，不是植物编号（`observe()` 的卡片行与 `legal()` 用同一个序号）。
`plant` / `shovel` 返回 `True` 表示引擎接受了这个动作。动作时间轴完全自由：任意 tick 都能做动作。
阳光自动收集，你不需要点阳光。

### 3.1 自选卡与换卡（A/B/D/E 层）

`Game(task_id, deck=[植物编号...], reason="选卡理由", strategy="核心流派")`。
卡组只受游戏硬约束：6–10 张、不重复、已解锁植物；升级植物自动声明已购买；泳池/雾要睡莲(16)，
屋顶要花盆(33)。本轮沿用二周目：普通植物全解锁，升级植物视为已购买。

换卡示例：

```python
g.abandon(reason="前排扛不住，改用爆破")     # 自动保存操作、卡组和理由，释放引擎
h = Game(g.task_id, seed=g.seed, deck=[1,33,15,35,3,2,17],
         reason="加入毁灭菇清场", strategy="毁灭菇爆破")
```

**C 层例外：任务里写死了卡组，`Game()` 传别的卡组会被拒绝。** 那一层的意义就是看我们的 AI
在这些"不会打的卡组"上能走到哪一步。

### 3.2 observe() 给什么

每次输出的**第一行是状态行**，例如：

```
[已用 1:12 | 本关 L49 模式=手动 | 搜索预算 0% | 最远 23/40 波 | 本段重写 3/8]
```

它由接口从磁盘上的 `~/.llmplay_session/budget.json` 现算（换工作目录也不会重置），已用时间只作参考，
不会封锁任何入口。后面依次是：局面头、空间网格、逐行明细、卡片、事件、每波一行的历史。
短代码表在第一次 `observe()` 的图例里，也可以用 `legend()` 随时打印。

信息量以「人类玩家此刻在屏幕上能看到的东西」为上限：血量、位置、状态都给；
**不给**未来的出怪表和随机数状态。精确数值以文字为准（本会话没有截图）。

### 3.3 一次调用跑多步

写 Python 脚本，一次跑几十到几百步。**脚本结束时（进程退出）接口会自动打印一次完整的
`observe()`**，你不用记得自己调用。想在某个条件成立后再行动，就用 `wait_until(lambda game: ...)`。

## 4. 稳健性：换个未来还能不能赢

只求通关的局会靠读档得来的「先知」在最后一刻救场（例如看准时机放樱桃），局面很脆。
我们的衡量办法**不是**战损公式，而是胜率本身：**换一个同样合理的未来，这套打法还能不能赢。**

```python
def policy(game):                 # 闭环打法：每一步只看当前局面
    if game.obs["sun"] >= 100 and game.legal()["plants"]:
        first = game.legal()["plants"][0]
        if first["cells"]:
            row, col = first["cells"][0]
            game.plant(first["packet"], row, col)
            return
    game.wait(30)

report = g.robustness(policy, k=8, checkpoints=[10])
```

- `policy` 必须是**闭环函数**；固定的动作序列在新未来里没有意义。写进 `.py` 文件再导入，接口会对源码取哈希。
- B 层的正式标准固定为第 10 波检查点、k=8 个新未来、赢≥5。`k<8` 只能试跑。
- 稳健复现使用这一局保存的卡组，不能换卡复现。没到检查点则 `reached: False`。
- 种子来自包里独立的稳健性块（`configs/llmplay_robustness.json`），与任务种子不重叠。
- **调用计入搜索预算**（重放和试打都是模拟 tick），别在没必要的局上反复调。
- 结果写进 `meta.json` 的 `robustness`；`manual_patch: true` 表示这局用 rewind 手工补救过。

## 5. 搜索与手动：止损由接口执行，不靠你掐表

你可以写任何脚本（穷举、贪心、束搜索、随机重启……）来挑动作。**但预算和止损是接口
自己数的，写在磁盘上，你绕不过，也不需要记住数字。** 你要做的是读懂它给的三样东西：
状态行、异常消息（异常消息里就是**下一步该怎么做**）、以及接口自动记的检查点。

- 搜索类入口是 `branch()`。搜索被判定不佳或用尽后，这一关的 `branch()` 会抛异常，
  提示改用**按波手动推进**：`observe()` 读局面 → 写一段覆盖 1–3 波的脚本 → 执行 → 看结果 →
  不满意就 `rewind()` 重写这一段。
- 手动模式允许局部小搜索，但同一段 `rewind()` 次数有上限；超了会拒绝并提示「退回更早一段」。
- 搜索额度是固定模拟 tick 数，不受机器速度影响；没有会话或单关总时间上限。

## 6. 纪律（会被机器检查）

- **不改引擎，不碰内存与状态。** 不要 patch 二进制、不要改 `main.pak`、不要伪造存档里的哈希。
  交回后我们会在原版引擎上重放；改过引擎或伪造过的结果一律作废。
- 存档里的每一行都会和重放结果比对（动作是否被接受、每个操作结束的 tick、终局）。
  `state_hash` 只是诊断信息，跨进程本来就不可复现，不会当门槛。
- **A 层同一关的新卡组和已有卡组差 < 3 张，接口直接拒绝建局**，不是提醒，是硬拦。
- **D 层 `strategy` 为空、或和同一套卡组已用过的打法重名，接口直接拒绝建局。**
- **同一种子同一卡组放弃 ≥2 次，这一组合之后不再计数。** 放弃本身照常允许，也照常存档。
- **A/D 层导出前必须填 `game.deck_review`**（一句话：这套卡组好打吗、为什么）。缺评价不能进下一层。
- C 层 5 个种子全输时要写失败诊断（卡在第几波、缺什么），用 `diagnose()`，不用重打。

## 7. 持续交付

每次 `export_archive()`、`abandon()`、`robustness()`、`diagnose()` 都会自动更新 `out_dir()` 里的：

- `progress.json`：当前圈/当前层、每层完成度、每套卡组的胜负与评价、全部存档；
- `report.md`：每层小结（做了什么、下传了什么）+ 逐关卡组表 + 全部存档；
- `budget.json`：续跑的搜索与重写计数；
- `out.zip`：含存档、进度、报告、预算及 out 下的策略代码。先写临时文件再原子发布。

不要自行覆盖这四个自动文件。每种打法的参数、布阵和差异写进 `Game(..., note=...)`
或 `export_archive(..., note=...)`。策略和搜索脚本请持续保存到 `llmplay.out_dir()`，会随交付一起打包。
战损、丢车、被吃株数可以写进 note，只用于描述，不作为目标或排序。

**续跑**：用户会附上上次的 `out.zip`。先 `llmplay.resume(out_dir().parent / "previous_out.zip")`，
再 `print(next_task())` 继续。resume 默认直接按旧 progress 恢复，不算摘要、不重放。
`Game.load_archive(path)` 可恢复已导出的局继续中盘打。
