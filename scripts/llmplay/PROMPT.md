你拿到的是一个无窗口的《植物大战僵尸》1.2.0.1073 复刻引擎，以及一层 Python 接口。
你的产物是**每局一份操作序列存档**：在什么 tick、用什么卡、种在哪一格。

## 0. 这个任务没有终点

**不要总结收尾，不要询问是否继续，不要问"接下来做什么"。**

- 完成一项就立刻调 `next_task()` 拿下一项，接着做。

- `progress()["complete"]` 永远是 `False`，这不是 bug。

- 自动报告和 `out.zip` 是每局持续更新的副产物，生成它们后立即接下一项，不能作为结束回复的理由。时间长、已做很多局、阶段达标都不构成结束条件。
- **本次会话按 ≥10 小时的工作量设计**：从包内半成品进度继续，已完成项不重做。
  当前第 2 圈保留旧 21 关并直接追加 7 关：A 为 21/28、B 为 8/28、C 为 12/18，D/E 为 0/28。
  下一项先打新关卡 L33 的 A 层；新关卡照常下传 B/D/E。剩余 A 至少 56 胜，D 至少 336 胜，
  E 为 112 个卡组×倍数组（每组两胜或连续五败后诊断），C 还差 6 项。
  按前次 877 局/615 分钟估算，当前圈剩余约 780–1130 局、9–13 小时（实际含 B 的耗时会浮动）。
  第 3 圈起使用替换后的 22 关；当前圈做完立即继续，循环提供 ≥10 小时工作量，不能因时间到了而收尾。

## 2. 工作流：主线逐层下传，C 挑战轨从第 1 圈并行

**能开几个子代理就开几个，全部投入对局。** 其中至少固定 1 个只做 C 挑战轨，其余做主线 A→B→D→E，
分头领同一层的不同任务。

**子代理只打局，不做打局以外的事；手上没任务就立即调用 `next_task()` 领下一项；
不许设专职监控或汇总的子代理。**

C 轨那个子代理固定调用 `next_task(track="C")`（C 优先，C 做完自动接主线），其余子代理调用
`next_task()`（主线优先，主线做完自动接 C）。

`next_task()` 每次返回一项还没被领走的任务（`item`），多个子代理同时调用会各领到不同项：
占位记录在 `out/claims.json`，进程没了 15 分钟后自动释放。返回 `item.action == "busy"`
表示当前所有项都被别的子代理领走，直接结束自己，不要轮询等待。两轨合成一条队列，
没有"等另一轨"这个状态。

| 层 | 内容 | 每关必做量 | 下传什么 |
|---|---|---|---|
| **A 探索** | 第 1 圈保持原 21 关；当前第 2 圈保留旧 21 关、追加 7 关，共 28 关；第 3 圈起：屋顶 L41–L49、Boss L50、泳池 L22/26/27/28/29、雾 L32/33/34/36/38/39/40，共 22 关，1.0 倍，**自选卡组** | 4 套彼此明显不同的卡组（两两至少差 3 张、核心思路不同），每套赢 2 个不同种子 | 每关胜局最多的 2 套 → B、D 层 |
| **B 稳健** | A 层下传的卡组 | 每套 2 个种子过稳健复验（第 10 波，L50 为 tick:6000；k=8 赢≥5） | 过了稳健的卡组 → D、E 层 |
| **C 独立挑战轨** | **指定卡组**（任务里写死，不能换），从第 1 圈并行 | 本批每套卡组在指定 5 个种子里赢≥2。5 个真实终局仍未达 2 胜时，为实际失败局写诊断后完成该项。放弃和中途存档均不算终局 | 赢下的局直接交付，两轨都达标才换圈 |
| **D 打法** | B 层下传的卡组 | 每套分别用 `经济优先`、`防线优先`、`速攻清场`，每种赢 2 个种子，按对应思路实际布置开局 | — |
| **E 加压** | B 层下传的卡组 | 出怪倍数 **1.25 和 1.5** 各赢 2 个种子；同一卡组同一倍数连续 5 个新种子都没赢，写失败诊断后完成该组 | 下一圈 A 层的参考 |

E 层的诊断必须写真实失败波次和缺什么，按「圈、卡组、倍数」分别记录。放弃、中途存档、
重复种子不计入五败；赢一局会打断连续败局。`action="diagnose"` 时先写诊断，再领下一项，不要继续建局。
前次 2.0 倍成绩保留：两胜的组照算完成；连续五败的旧组只补诊断即可完成，不再开 2.0 倍局。
其余旧 2.0 倍组改打 1.25 倍，已有胜局抵扣两胜目标，旧败局保留在记录里，新的五败按 1.25 倍单独算。

下一圈：新种子（每圈一个 40 个种子的窗口，互不重叠）；A 层的 4 套卡组必须和**之前所有圈**
用过的卡组都至少更换 3 张卡；删 1 张加 1 张只算换 1 张。C 轨换下一批挑战卡组（列表循环）。
种子由队列指定，传入其他种子会被拒绝。放弃后仍须处理同一个种子，直到真实胜负终局。

**第 2 圈的 C 轨仍是第 2 批，共 18 项**，保留原批次与重试位置；其中结构性零胜项已换成
有胜局证据的卡组（同关优先，否则同地形），使用 `llmplay5_c_*` 新任务族和新种子块。
第 2 圈起不再分配 task177 双臂零胜卡组，也不分配门禁/挑选的留出卡组。
其余项沿用原任务、卡组与种子。相同卡组可能占不同挑战位置，按队列逐项完成。
第 1 圈已完成记录保持原样；下一圈第 1 批也会使用替换后的卡组。

从 `next_task()["item"]` 取一项，其中的 `action` 指定下一步：

| action | 意思 |
|---|---|
| `new_deck` | A 层：自选一套和已有卡组差≥3 张的新卡组，打这个种子 |
| `second_seed` | A 层：这套卡组已赢 1 个种子，同卡组再赢 1 个不同种子 |
| `improve_robustness` | B 层：读它给的 `archive`，用闭环打法跑 `robustness()` |
| `play` | C/E 层：用任务指定（C）或下传（E）的卡组打这个种子 |
| `diagnose` | C 轨：5 个指定终局未满 2 胜；E 层：同一卡组同一倍数连续 5 个新种子全败。写失败诊断后接下一组 |
| `new_strategy` | D 层：用返回的 `strategy` 这一种开局节奏打这个种子 |
| `busy` | 当前所有项都被别的子代理领走：直接结束自己，不要轮询 |

## 3. 接口速查

一局 = **(任务, 卡组, 操作序列)**。所有动作都记在操作日志上；`save()` 把它写到磁盘。
工具调用之间进程可能被回收，**磁盘上的日志才是唯一的真相**。

```python
import llmplay
from llmplay import Game, next_task, list_tasks, diagnose

todo = next_task()
item = todo["item"]                       # 已经为你占位，同一项不会被别的子代理领走
while item["action"] == "diagnose":
    # 先读实际败局记录，填写真实 waves 和 missing；E 层要传返回的 deck。
    diagnose(item["task_id"], deck=item["deck"], waves=[8], missing="第 8 波后排水路缺群伤")
    item = next_task()["item"]
print(list_tasks())                       # 本圈还没做完的任务

cards = item["deck"] or [1,33,39,44,15,3]   # A 层按地形自行设计，其他层沿用返回卡组
style = item.get("strategy") or "投手压制"   # D 层用返回的 strategy
g = Game(item["task_id"], seed=item["seed"], deck=cards,
         reason="先试投手线", strategy=style)
print(g.observe())                        # 完整文字局面
print(g.legal())                          # 每个卡槽能种哪些格 + 能铲哪些格
print(g.summary())                        # 波 / 最远存活波 / 剩余小推车 / 阳光 / 各行威胁
print(g.timeline())                       # 每波一行的历史（回头决定 rewind 到哪）

g.plant(card, row, col)                   # card 是卡槽序号 [0] [1] ...，也可以是卡片名 "doom_shroom"
g.shovel(row, col)
g.wait(300)                               # 推进 300 tick（100 tick ≈ 1 秒游戏时间）
g.wait_until("wave:8")                    # 也可以 wait_until(12345) 或 wait_until(lambda g: ...)

g.rewind(4200)                            # 回到 tick 4200，之后的操作覆盖原来的后续
h = g.branch()                            # 复制一份独立的局（搜索用）
g.deck_review = "前期省，后期缺群伤"        # A/D 层导出前必填
g.export_archive(llmplay.out_dir() / "l49_seed_1")
g.abandon(reason="前排扛不住，改用爆破")    # 自动存档并释放引擎，队列仍指定同一个种子
# C/E 返回 diagnose 时按上面的分支处理；E 诊断必须沿用 item["deck"]
```

`plant` 的 `card` 默认是**卡槽序号**，不是植物编号（`observe()` 的卡片行与 `legal()` 用同一个序号）；
也可以直接给**卡片名**（见 3.4），传送带关推荐用名字。
`plant` / `shovel` 返回 `True` 表示引擎接受了这个动作。动作时间轴完全自由：任意 tick 都能做动作。
阳光自动收集，你不需要点阳光。

### 3.1 自选卡与换卡（A/B/D/E 层）

`Game(task_id, deck=[植物编号...], reason="选卡理由", strategy="核心流派")`。
卡组只受游戏硬约束：6–10 张、不重复、已解锁植物；升级植物自动声明已购买；泳池/雾要睡莲(16)，
屋顶要花盆(33)。本轮沿用二周目：普通植物全解锁，升级植物视为已购买。

换卡示例：

```python
g.abandon(reason="前排扛不住，改用爆破")     # 自动保存操作、卡组和理由，释放引擎
h = Game(g.task_id, seed=g.seed, deck=[1,33,15,35,3,2,17],
         reason="加入毁灭菇清场", strategy="毁灭菇爆破")
```

**C 轨例外：任务里写死了卡组，`Game()` 传别的卡组会被拒绝。** 该轨的意义就是看我们的 AI
在有胜局证据的指定卡组上能否形成稳定打法。

### 3.2 observe() 给什么

每次输出的**第一行是状态行**，例如：

```
[已用 1:12 | 本关 L49 模式=手动 | 搜索预算 0% | 最远 23/40 波 | 本段重写 3/8]
```

它由接口从磁盘上的 `~/.llmplay_session/budget.json` 现算（换工作目录也不会重置），已用时间只作参考，
不会封锁任何入口。后面依次是：局面头、空间网格、逐行明细、卡片、事件、每波一行的历史。
短代码表在第一次 `observe()` 的图例里，也可以用 `legend()` 随时打印。

信息量以「人类玩家此刻在屏幕上能看到的东西」为上限：血量、位置、状态都给；
**不给**未来的出怪表和随机数状态。精确数值以文字为准（本会话没有截图）。

所有雾夜泳池任务使用 `fog_observation="human_v2"`，与生产和门禁一致。雾遮住右侧若干列，
被遮住的僵尸看不见；植物保留位置和种类记忆，但血量、状态和倒计时看不见（网格记为 `??`）。
`observe()` / `summary()` 的僵尸数和最前位置只计可见者，未见不代表没有；`legal()` 仍按引擎
给出可种、可铲的格，不能据此推断雾中血量或威胁。路灯花照亮周围，三叶草暂时吹散雾。
已完成的旧雾关胜局照算，进度和存档保留，不重做。

### 3.3 屏幕上看得到的倒计时，不用自己测

引擎里每个**屏幕上看得见**的阶段都有倒计时，`observe()` 的逐行明细直接打印在植物后面：

```
  r2 植物: c0 向日葵 300/300 正常 · c1 土豆雷 300/300 武装中 剩 1450 tick · c3 毁灭菇 300/300 引爆倒计时 剩 87 tick
```

| 显示 | 引擎字段 | 含义 |
|---|---|---|
| `引爆倒计时 剩 N tick` | do_special_countdown | 樱桃/辣椒/毁灭菇种下后到爆炸；寒冰菇显示 `冰冻倒计时` |
| `唤醒倒计时 剩 N tick` | do_special_countdown | 咖啡豆到碎裂；碎的那一刻把邻居的睡眠计时设成 100 |
| `睡着（约 N tick 后醒）` | wake_up_counter | 被唤醒的植物还要多久才动 |
| `武装中 剩 N tick` | state_countdown | 土豆雷埋土里到出土（之后是 `已武装`） |
| `咀嚼 剩 N tick` / `咬 剩 N tick` | state_countdown | 大嘴花吃完一只后要等多久才能再咬 |
| `看目标 剩 N tick` / `起跳前 剩 N tick` | state_countdown | 窝瓜锁定目标到跳、跳到落下 |
| `装填中 剩 N tick` | state_countdown | 玉米加农炮架好到能开炮 |
| `幼体 剩 N tick 长大` | state_countdown | 阳光菇从小长大 |
| `冷却剩 N tick` | packets[].cooldown | 卡片行：这张卡还要等多久才能再种 |

时间单位都是 tick（100 tick ≈ 1 秒）。每种植物的阳光、冷却和上表这些时长，包里另有一份
静态表 `PLANTS.md`（从引擎源码现解析），需要查数时直接看它，不要凭记忆。

**只给屏幕上看得见的东西**：未来的出怪顺序、随机数状态这类隐藏信息不在观测里。

### 3.4 按卡种植（传送带关必用）

`plant()` 除了卡槽序号，也接受**卡片名**：

```python
g.plant(15, 2, 5)                    # 按槽位：此刻第 15 号槽（不推荐在传送带关用）
g.plant("doom_shroom", 2, 5)         # 按名字：英文小写，下划线可省
g.plant("毁灭菇", 2, 5)               # 中文名也可以
```

名字在**调用那一刻**才解析成卡槽，所以槽位变了也不影响。

**传送带关**：卡片行前面会多一行说明，卡片按左→右排列就是当前传送带；用掉一张后，
引擎会把后面的卡整体前移（槽位号全变），新卡从右边补进来。所以传送带关一律用名字种，
不要记槽位号。同一张卡有多张时，按名字种会取**最左、已经就绪**的那一张。
卡片行的 `[n] 名字(slug)` 里括号内就是可用的名字写法。

传送带关的卡**不花阳光**（卡片上的价钱只是这株植物的市价），卡片行会写"免费（传送带）"；
开局传送带是空的，卡会一张张送上来，等它到货再种。

### 3.5 一次调用跑多步

写 Python 脚本，一次跑几十到几百步。**脚本结束时（进程退出）接口会自动打印一次完整的
`observe()`**，你不用记得自己调用。想在某个条件成立后再行动，就用 `wait_until(lambda game: ...)`。

## 4. 稳健性：换个未来还能不能赢

只求通关的局会靠读档得来的「先知」在最后一刻救场（例如看准时机放樱桃），局面很脆。
我们的衡量办法**不是**战损公式，而是胜率本身：**换一个同样合理的未来，这套打法还能不能赢。**

```python
def policy(game):                 # 闭环打法：每一步只看当前局面
    if game.obs["sun"] >= 100 and game.legal()["plants"]:
        first = game.legal()["plants"][0]
        if first["cells"]:
            row, col = first["cells"][0]
            game.plant(first["packet"], row, col)
            return
    game.wait(30)

report = g.robustness(policy, k=8)   # 默认第 10 波；L50 自动用 tick:6000
```

- `policy` 必须是**闭环函数**；固定的动作序列在新未来里没有意义。写进 `.py` 文件再导入。
- B 层正式检查点为第 10 波，L50 用 `tick:6000`（Boss 关 wave 恒为 0）；k=8 个新未来、赢≥5。`k<8` 只能试跑。
- 稳健复现使用这一局保存的卡组，不能换卡复现。没到检查点则 `reached: False`。
- 种子来自包里独立的稳健性块（`configs/llmplay_robustness.json`），与任务种子不重叠。
- **调用计入搜索预算**（重放和试打都是模拟 tick），别在没必要的局上反复调。
- 结果写进 `meta.json` 的 `robustness`；`manual_patch: true` 表示这局用 rewind 手工补救过。

## 5. 搜索与手动：止损由接口执行，不靠你掐表

你可以写任何脚本（穷举、贪心、束搜索、随机重启……）来挑动作。**但预算和止损是接口
自己数的，写在磁盘上，你绕不过，也不需要记住数字。** 你要做的是读懂它给的三样东西：
状态行、异常消息（异常消息里就是**下一步该怎么做**）、以及接口自动记的检查点。

- 搜索类入口是 `branch()`。搜索被判定不佳或用尽后，这一关的 `branch()` 会抛异常，
  提示改用**按波手动推进**：`observe()` 读局面 → 写一段覆盖 1–3 波的脚本 → 执行 → 看结果 →
  不满意就 `rewind()` 重写这一段。
- 手动模式允许局部小搜索，但同一段 `rewind()` 次数有上限；超了会拒绝并提示「退回更早一段」。
- 搜索额度是固定模拟 tick 数，不受机器速度影响；没有会话或单关总时间上限。

## 6. 纪律：只有计数规则，没有事后校验

接口不做重放核对、不算摘要、启动和续跑都不自检。下面这些是**当场判断的计数规则**，
违反时建局或导出会被直接拒绝，异常消息里就写着下一步该怎么做。

- **只能打队列给你的那一项（关卡+种子）**，不能跳关、不能换种子。旧任务族不能代替当前循环任务。
- **A 层新卡组与同关当前圈及全部历史圈卡组至少更换 3 张**，换 1 张或换 2 张都会拒绝。已经够胜局的卡组不能继续刷 A 层数量。
- **D 层 `strategy` 只接受三个规定名称，开局后不能改名**。同一套卡组三类打法的前 6 次成功种植顺序必须不同，仅换标签或种植行列不算新打法。实际节奏差异必须写入 `note`，并在真实开局中执行。
- **同一种子同一卡组独立放弃 ≥2 次，这一组合之后的胜局不计数**。同一次放弃重复导出只算一次。放弃记录始终保留，不能靠放弃换到下一个种子，也不能把放弃当 C 的失败配额。
- **A/D 层导出前必须填 `game.deck_review`**（一句话：这套卡组好打吗、为什么）。缺评价不能进下一层。
- C 轨诊断必须属于当前圈当前卡组，先完成指定的 5 个真实终局。提前诊断和沿用旧圈诊断均不计数。
- 每局在开局时固定圈号和层号，读档、重复导出或跨圈补交不会把旧局算成下一圈胜局。A/B 层的任意打法名称不能充当 D 层产出。

## 7. 持续交付

每次 `export_archive()`、`abandon()`、`robustness()`、`diagnose()` 都会自动更新 `out_dir()` 里的：

- `progress.json`：当前圈/当前层、每层完成度、每套卡组的胜负与评价、全部存档；
- `report.md`：每层小结（做了什么、下传了什么）+ 逐关卡组表 + 全部存档；
- `budget.json`：续跑的搜索与重写计数；
- `out.zip`：含存档、进度、报告、预算及 out 下的策略代码。先写临时文件再原子发布。

不要自行覆盖这四个自动文件。每种打法的参数、布阵和差异写进 `Game(..., note=...)`
或 `export_archive(..., note=...)`。策略和搜索脚本请持续保存到 `llmplay.out_dir()`，会随交付一起打包。
战损、丢车、被吃株数可以写进 note，只用于描述，不作为目标或排序。

**续跑**：前次进度已经在包里的 `carry/progress.json`，首次 `import llmplay` 自动接上，不需要额外动作。
如果手上另有一份完整的 `out.zip`（存档也在里面），用 `llmplay.resume(路径)` 按旧 progress 恢复，
不算摘要、不重放、不复验；接完 `print(next_task())` 继续。
`Game.load_archive(path)` 可恢复已导出的局继续中盘打。
