# 07 · 快速强化学习：小网络让 RL 便宜了 80 倍，但夜间仍然学不会

> 读完应该能回答：为什么现在 RL 跑得起来了、它在夜间关卡上为什么还是学不会、下一步该怎么做。

## 1. RL 为什么突然变便宜了

原来的 PPO 训练的是 790 万参数的 π，100 万个决策要跑 7 个多小时，所以从零学根本学不动（完整第 7 关 0%）。
[05](05-fast-rollout-policy.md) / [06](06-expert-iteration.md) 的学生网络只有约 50 万参数，每局约 4 秒。
在它上面实现的 PPO（`scripts/fast_ppo.py`）**每分钟约 20 万个决策，快了大约 80 倍**。
这恢复了 DESIGN §1 最初的前提：“让环境的速度决定架构”。

## 2. 夜间第 12 关的三次尝试（卡组 d1，从第二代学生出发）

| 尝试 | 轮数 / 耗时 | 结果 |
|---|---|---|
| 完整关卡，熵系数 0.01 | 60 轮 / 3.7 分钟 | 0 胜，一直停在第 9.3 波 |
| 完整关卡，熵系数 0.05 | 约 110 轮 | 0 胜；**向日葵从每局 6–7 株降到 1 株，退化成“只用土豆雷拖延”** |
| 只打 10 波（课程起点），熵系数 0.02 | 约 90 轮 | 0 胜，平均波次反而从 8.8 降到 8.0 |

**根本原因：它从来不买豌豆射手**（每局 0–0.2 株）。夜里天上不掉阳光，阳光都花在便宜的土豆雷和向日葵上，
没有任何火力，到第 9 波前后必死。**它从没赢过一局，赢输信号永远是 −1**，每推进一波的那点奖励只会鼓励拖延。

## 3. 读法和下一步

这不是“PPO 调一调”能解决的问题：

1. **卡组是首要嫌疑**（AGENTS.md §8：打不过先看卡组）。夜间真正的玩法要靠**小喷菇（0 阳光）和阳光菇（25 阳光）**。
   d1 没有蘑菇，在夜里经济太紧，可能本来就极难。下一步应该在 DESIGN 里登记一个带蘑菇的夜间任务族。
2. **课程要从真的能赢的地方起步**：10 波都还赢不了，应该从 5–7 波开始（白天的经验是，低波数靠割草机就能兜住）。
3. 可以考虑加入击杀 / 伤害这类密集奖励，让“种射手”这个动作能被学到。
4. 有了快速 RL，以上每一种尝试都只要几分钟，可以系统地试。
