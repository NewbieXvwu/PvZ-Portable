**从 `update_history[*].losses.entropy` 逐次轨迹看，**"瘟疫"至少有四种发作模式**：

| run | 轨迹 | 模式 |

| criticwarm | `[0.005, 0.003, 0.004, 0.004, 0.012, 0.009, 0.005, **0.285**, 0.333, 0.313, 0.300, 0.156]` | **前 7 次完全正常，突然爆** |

| **v3 seed0（好）** | 84 次：长期在 **0.002~0.037** 波动，**第 27~50 次一度升到 0.015~0.037**，第 51 次孤立尖峰 **0.0851**，之后回落到 0.004~0.019 | **会升高，但能回落** |

**★ 结论：**
1. **没有找到"一个共同的第一推动"** —— 四种模式不像同一件事。
2. **但共同点是"一旦持续在高位就回不去"**；**v3 是唯一"升上去又落回来"的例子**
   → **关键不是"爆没爆"，是"能不能回落"**。
3. **"单步 log-prob 跳变大"这个假说彻底作废**：v3（好种子）更新 0/1 的
   `max_log_prob_change` = **7.75 / 10.10**，**比 C2 的 5.15 / 3.79 更大**。
4. **梯度量级相关但不充分**：C2 第 2 次更新 `gradient_norm` 0.313→**2.754**（8.8 倍）、
   旧 v2 0.144→**7.048**（50 倍）；但 `G2 = seed0+守卫` 的更新 0 也有 **7.532** 的大梯度却没崩。
5. **C2 第 2 次更新只走了 2 步就被 KL 刹车停住，熵已经跳了 8 倍**
   → **KL 刹车挡不住熵爆炸**（它管的是"改了多少"，不是"改歪了没有"）。

**★ 是"架构的病"还是"训练的错"？→ 证据指向训练/优化设置，不是架构**：
同一个模型、同一个起点检查点，**只换采样种子 → 差 34 个点**；
同一个种子，**只加一道回滚保险 → 从 50.78% 回到 84.38%**。**模型没变过。**

**可疑的三个设置**：`rollout_episodes=16`（标定值 2000，样本极少→优势噪声大）、
`gae_lambda=1.0`（纯蒙特卡洛→方差拉满）、`lr=1e-4`（配 2000 局标定的，用在 16 局的批上）。
**叠加"BC 起点极尖"（熵 0.005，99.9% 概率压在一个动作上）→ 对梯度噪声的敏感度被放大**
（非首选动作的概率从 0.09% 涨到 0.6% 只需要 ~2 nat 的 logit 变化）。

**区别在于"能不能扑灭"。**

**★ 假设 H2（正反馈环）**：
`一批 16 局大多输 → 优势几乎全负、方向单一 → 梯度把策略从当前动作推开 → 熵升高 →
表现变差 → 下一批输得更多 → 回到起点`
- **好种子**：环被"KL 刹车 + 后续批次转好"打断，熵回落（v3 第 51 次 0.085 → 回落）
- **坏种子**：环锁死，熵一路爬
- **→ 这解释了：为什么守卫有效（它直接掐断第 3~4 步）、为什么 KL 刹车无效
  （它管"改了多少"，不管"改歪了"）、为什么"照打但防不住"（策略弥散→该种时犹豫/选错→落点变差）**

**③ 熵最大那次的字段（vs 该 run 中位）**：
`optimizer_steps` 普遍**很小**（B10 1 步 / B8 2 步 / criticwarm 1 步 / v3 5 步 vs 中位 21）
→ **熵跳发生在头几步内**，KL 刹车是"事后"才停的。
`gradient_norm` 只在部分模式里异常（B10 **61.2** vs 中位 4.9；criticwarm **9.9** vs 2.4），
**v3 和 C2 的熵峰值那一步梯度反而低于中位** → **大梯度不是普遍机制。**
