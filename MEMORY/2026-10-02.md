### 方法栈（代码事实）

- 环境是**真实 PvZ 二进制**（`build/pvz-portable` + 真资源包），胜负由游戏本体判定。
- 观测 → token（11 类：global/profile/cell/plant/zombie/projectile/defense/
  grid_item/seed_packet/zombie_roster/lane），32 维特征，fp16 打包存储、fp32 计算。
- 模型 `GameplayModelV1`：kind/category/variant/feature/row/col 嵌入相加 →
  N 层 `RelationLayer`（带关系偏置表，CUDA 上 `torch.compile` 融合）→ LayerNorm →
  取 global token + 上一动作嵌入 + log2(tick 间隔) + 事件特征 → GRU → 分解动作头。
- 动作是**分解式**：类型（plant/shovel/wait）→ 卡片 → 54 格落点；wait 只有
  {60,150,300} tick 三档。执行器只做合法性掩码，不做代选。
- PPO：CPU 8 worker 采样（200 局/批），CUDA 更新，128 步窗口、2 epoch、
  GAE λ=0.95、clip 0.2、target_kl 0.03、**FP32**（cuDNN TF32 关闭）。
  价值网络是**特权**的（读波次计时与出怪名单），策略只看公开观测。
- 奖励四变体：R0(γ .99+塑形) / R1(γ .99 无塑形) / R2(γ 1.0 无塑形) / R3(γ 1.0+塑形)。
- 每 125k 决策做一次冻结评估：35 任务 × 64 种子 × greedy/sampled = 4480 局/节点。

## 网络结构与四奖励诊断（同日补充）

### 结构要点（代码位置）

- 关系偏置四项，全部 **per-head**：`kind_pair_bias (heads,11,11)`、
  `row_bias Embedding(12,heads)`（行差 clamp(-5,5)+5，未知落 11）、
  `col_bias Embedding(18,heads)`（列差 clamp(-8,8)+8，未知落 17）、
  `same_cell_bias Embedding(2,heads)`。见 `pvz_agent_model.py:427-531`。
- 偏置索引 `relation_bias_indices` **只依赖离散布局（kinds/rows/cols），跨层共享一次算好**；
  装配链 `relation_bias_from_indices` 被 `torch.compile(dynamic=True)` 融合
  （CUDA 反向 906 ms → 5.1 ms，177x）。`--attention-backend auto` 解析为 **dense 不是 flex**
  （dense 8.25 ms vs flex 22.40 ms，1.54x）。
- GRU 输入维度 = width + 128，128 = 上一动作 64 + log₂(Δtick) 32 + 事件 32。
- 分解动作：type(3) → packet(≤10) → cell(54)（`plant_cell_query` 拼 belief+选中卡片 token，
  所以落点打分依赖卡片）；联合空间 597，分解后 log_prob 与熵可加。
- 训练窗口 128 步 TBPTT：每个截断 minibatch 用**当前参数无梯度重算前缀**，
  隐藏态**不跨优化步**。`target_kl=0.03` 早停，grad clip 1.0，AdamW lr 1e-4。
- **PPO 的价值损失只训 `privileged_critic`，不训 `self.value`**（rollout 存的 value 也是特权值）。
  `self.value`（tanh 头）在这条路径上没有被用到。
- 特权输入只有 16 float：`wave_timer/6000` + 15 类僵尸计数各 +0.1
  （原 privileged_state 76.9 KiB，99.7% 字节没用上）。

### 折扣与势函数

- 折扣按**真实游戏时间**：`discount = γ^(ticks/300)`，GAE 的
  `trace_discount = discount × λ^(ticks/300)`。所以 γ=1.0 时 discount 恒为 1，
  但 trace 仍随 λ 衰减。参考时长 `DISCOUNT_REFERENCE_TICKS = 300`。
- 势函数 `potential()`（train_pvz_ppo.py:36）：
  `Φ = (sun/1000 + wave/wave_count + 存活植物平均血量比例) / 3`，**终局 Φ=0**。
  塑形奖励 `= w × (discount·Φ(s') − Φ(s))`，终局再叠加 ±1。

## 128 步截断 TBPTT 的实际代价（重要更正）

`train_pvz_ppo.py:245-282`。之前说"梯度只能回传 128 步"**对当前这批 run 不成立**。

- **当前训练任务是单波 cap1，单局决策数均值只有 45–83**
  （R0/i0 = 500004/11151 = 44.8；R2/i0 = 79.7；R3/i2 = 83.3；分片样本 22–60）。
  全部小于 span=128 → **每局只切成 1 块，L=1** → 既没有截断、也没有前缀重算，
  实际等价于**整局反传**。（无本地逐局原始数据，无法证明"零个"episode >128，
  逐局分片在台式机；但按均值判断尾部占比极小。）
- 前缀重算开销通式：`开销比 = (L−1)/2`。L=1→0、L=2→50%、L=4→150%、L=8→350%。
  推导：第 k 块要用当前参数无梯度重跑前 k×128 步，总前缀 = 128·L(L−1)/2。
- 额外低效：前缀重算是 **一个 episode 一次 `forward_sequences`、batch=1**，
  没有跨 episode 批处理（`minibatch_chunks=2` 时第 k 层要做 2k 次 batch=1 前向）。
- **进 T7 完整关卡才会变贵**：脚本策略在完整关卡 day7 均值约 122 决策/局（且早死），
  训好的策略只会更长；叠加 token 数从 ~70 涨到 121（注意力按 token²）。
- 为什么必须重算而不是复用采样时的 hidden：采样 hidden 是**采集时旧参数**的产物，
  而一个 update 有 2 epoch × 几十个优化步，参数一直在变；用旧 hidden 当起点梯度是偏的。
  同理隐藏态不能跨优化步传递。

**结论：现在不要改**（RESEARCH_EXECUTION 已把它写进冻结协议；TODO §7.2 明说
"循环训练窗口以记忆任务为依据，性能测试只提供成本信息"；且当前代价为零）。
但 **T7 前必须重新决策**，TODO T5-C 已列为未完成，且原文禁止沿用任何固定窗口值。
若真要动，顺序是：① 先把前缀重算批处理化（纯工程；注意会引入 ~1e-6 的
GEMM blocking 差异，需确认不破坏严格等值门禁）→ ② 再动 `sequence_length`
（它同时改梯度跨度和显存，必须分开评估；`sequence_length=0` 是天然整局对照）。

## 三个辅助头的信息增量核查（用户质疑"敌人构成已是公开输入，设计还合理吗"）

结论：**三个头里两个现在是零增量**，`DESIGN.md` §4.4 写在 `input_flags=7` 合并之前，

  **只是本关允许出现的僵尸类型集合，没有每波数量**。
- **逐波构成 `zombies_in_wave` 在 `hidden` 段**（`LawnApp.cpp:1815`），是特权；
  critic 那 16 维里后 15 维就是当前波的各类计数。
- 行级威胁：`pvz_observation_features.py:41-84` 的 `row_context` 按 (行, 僵尸类型)
  分组给出数量/血量/护甲/盾/最左 x/平均速度 —— **"每行威胁量"已经是公开输入**。

**逐头判决**

1. `aux_lane_threat`（256→6）：**零增量，不该接**。公开行上下文比 6 维威胁向量更细，
   训练它只是用 belief 重建已看到的东西，纯加梯度噪声。
2. `aux_next_spawn`（256→**1**）：名义标签（`zombies_in_wave[wave+1]`）确是特权，
   但 ① **输出只有 1 个标量，装不下 15 类分布**，形状本身就不对（强证据：从没被当成
   可训练目标设计）；② 波表是每关固定的（`mNumWaves` 全表），公开输入含 `wave`/`wave_count`/
   `scene` → 它是**公开信息的确定性函数**，不是不可观测随机量。接了最多是加速记波表，
   不是特权蒸馏。
3. `aux_outcome`（256→2）：终局胜负标签，**非特权**，且 critic 已在回归回报；
   提案 §1 明令不能在不相容的回报语义下顶替 critic。

## 用户提问："要不要对种后即铲做专门惩罚？" —— 判决（大概率馊主意，但有窄的合法版本）

**反对理由（按强度）**

1. **违反本项目明文规则**：`TODO.md:109` 已写"区分合理拆除与重复无效操作，
   **不以固定禁铲规则替代可学习决策**"。DESIGN §2 判据：梯度能不能推翻它？不能 → 硬编码。
2. **种铲 ≠ 零 tick 等待，不能套用 progress_v1 的范式**。零 tick 等待是**可证明的空转**
   （推进 0 tick、什么都不发生），所以硬掩码（select_action 里把 logits 置 -inf，
   采样/PPO 回放/克隆三处共用）不改变有意义选项。种铲**消耗阳光、改变棋盘**，是真实动作。
3. **误伤正当战术**：止损拆被吃的植物、拆向日葵换火力、腾格子。
4. **若做成奖励惩罚，形式有问题**：DESIGN §6 明确否定 `_transition_reward` 那种
   "任意常数惩罚"（非势函数形式、会改变最优策略）。要加必须是 `γ·Φ(s')−Φ(s)` 形式。
5. **因果未定（最要命）**：种铲率高与输强相关，但很可能是"快输了→策略乱来"
   （R2/i0 价值 EV −113.8 支持这个方向）。若是果，惩罚它=惩罚绝望，模型只会学会
   "安静地输"，且从此无法再诊断真因。
6. **归因代价**：R0–R3 已在比，再加一个交叉因素违反 TODO §1"不能同时改多个因素"。

**窄的合法版本**：若证明种铲真是零收益空转，正确形式是**可配置的硬掩码**
（照 `wait_mask=progress_v1` 的范式：可关闭、可做配对对照），**不是奖励惩罚**。
掩码="动作不存在"（会剥夺能力），惩罚="动作存在但我不喜欢"（不剥夺但污染目标）——
各有代价，所以**先做探针再选形式**。

**定分止争的只读探针（30 分钟量级，不改训练、不碰门禁）**：拿固定第 13 更新检查点，
同任务同种子跑三组：A 原样 / B 硬掩码禁"刚种即铲" / C 奖励加反种铲惩罚，
比胜率、决策数、种铲率。B≫A → 种铲是有效策略空间里的浪费，可采纳掩码；
B≈A 只是种铲率降 → 是症状不是病因，回头查价值估计。这正是 wait mask 那次的
同款套路（20 任务短诊断 → 确认 19708 次空转 → mask → 9/20→13/20 → 才合入主线）。

**另一个层面**：旧诊断 action_counts（500027 决策）= wait 348132 / plant 85978 /
shovel 65917，等待占 70%。若真问题是"决策预算被浪费"，那是预算/课程层面的事，
与"惩罚铲"不是同一层。

## 严肃问题："是不是什么都没学会？" —— 答案：不是，但有三个真问题（全都不是架构）

### 决定性数据 1：旧 R0 seed0 在 cap1 上的学习曲线是真的

| 节点 | 局数 | 胜率 | plant/局 | 种后即铲率 |
|---|---|---|---|---|
| 125k | 2049 | 5% | 10.60 | 25.9% |
| 250k | 4424 | **1%** | 9.65 | 11.0% |
| 500k | 11151 | **57%** | 8.97 | **6.8%** |

**学习是真实的**：种后即铲率单调下降（26%→11%→6.8%），胜率在 250k 后才起飞。
**代价是 500k 决策，250k 时才 1%。** 这是全项目最重要的一个表。

### 决定性数据 2：主线训练量差一个数量级

frontier seed0/1 只跑到 **47,856 决策（23 更新）**，完整 level7 是 **31,863 决策（43 更新）**。
而旧数据表明 250k 时仍只有 1%。**现在连"看得出学习"的位置都没到。**

### 决定性数据 3：γ=1.0 家族不稳定（12 run 全表）

| run | seed0 | seed1 | seed2 | 价值EV |
|---|---|---|---|---|
| R0 γ.99+塑形 | **57%** | 42% | 26% | 全正(+0.58/+0.38/+0.21) |
| R1 γ.99 无塑形 | **59%** | 35% | 16% | 全正(+0.72/+0.27/+0.14) |
| R2 γ1.0 无塑形 | **0%** | 41% | **0%** | −113.8 / +0.57 / −66.3 |
| R3 γ1.0+塑形 | 26% | 28% | **0%** | +0.17 / +0.15 / −0.86 |

γ=1.0 的 6 局里 2 局归零、3 局 EV 为负。**完整 level7 阶段用的正是 R3（γ=1.0+塑形）**
→ 它"一个都不种"很可能就是这个选择造成的，不是架构问题。

### 结论

- **架构/参数量不是瓶颈**（有反证）：未训练模型就会种 7–10 次/局；训够的旧 R0 种 8.97 次/局
  且赢 57%。7.87M 参数足够表达目标行为。
- **唯一值得警惕的结构性风险**：分解动作头的概率 compounding —— P(种植)=P(type)×P(card)×P(cell)，
  一旦 P(type=plant) 塌到接近 0，熵系数 0.01 极难把它推回来。这是训练动力学问题，不是容量问题。
- **三个真问题**：① 训练预算差一个数量级；② 任务池/评估指标是空尺子（cap3 空操作 8/8、
  cap5 7/8）；③ 完整关卡阶段选了已被证伪的 γ=1.0 档（R3）。
- **建议顺序**：① 完整关卡改回 **R0**（从已有 12-run 直接读出，不需新实验）；
  ② 把"必须跑到 500k 再评判"当作硬约束，或缩短单局决策数；③ 进度指标换 cap10+（桥梁课程已在做）；
  ④ **不要先扩参数**。
- **caveat**：do-nothing 与 initial-vs-trained 对比跑在**本机 macOS 重编译二进制**上，
  需在生产机复核；但"学得会但要 500k"这条由旧 12-run 数据本身支撑，不太会翻转。
