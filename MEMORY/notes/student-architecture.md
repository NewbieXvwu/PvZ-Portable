# 学生 / 价值网架构的远期升级：个体 + 注意力（2026-10-26 用户确认要记住）

## 现状

- 学生和价值网的输入：6×10 格子通道（植物种类与血量、僵尸按 80 像素取整），加上标量与任务背景向量（`pvz_value_net.context_vector`：只有出怪倍率和本关僵尸名单，**没有关卡模式标记**）。
- 主干是格子卷积。

## 什么时候会成为瓶颈

凡是要回答“A 和 B 的精确相对位置 / 运动关系”的关卡，格子卷积都吃力：

- **L5 坚果保龄球**：滚动坚果的位置、方向（引擎里的 `STATE_BOWLING_UP/DOWN`）和横向速度。
  - 速度由动画速率决定，每颗坚果在 12–18 之间随机，大坚果 6–10 再乘 2；上下方向固定每刻 2 像素。所以每颗坚果的斜率各不相同。
  - 坚果从第 1 列一路斜滚到第 8 列，会撞上哪只僵尸，取决于跨越整块草坪的空间关系。
  - 按现在的编码，滚动坚果会被记成“出生那一列的一颗坚果（种类 3）”，和普通关站着的坚果混淆。
- **L45 蹦极**：可见落点红靶与蹦极阶段。
- 屋顶投掷类、雾夜可见范围等，也有类似的空间关系问题。

## 方向（按顺序，不跳步）

1. **先补输入，不改架构。**
   - 滚动坚果走独立通道（像子弹一样），带精确位置、方向、横向速度；
   - 任务背景加“关卡模式”标记；
   - 只放玩家在画面上看得到的东西，随机拐弯、随机速率之类还没发生的结果不放。
2. **用记分板量差距**：task103 的 `adventure_scoreboard.py`，在该关比较学生和老师的胜率。差距小就到此为止。
3. **差距大就上个体 + 注意力**：
   - 每颗坚果、每只僵尸、每株植物都作为一个带精确坐标和状态的个体（token），用注意力处理两两关系，可与现有格子通道并存；
   - 需要 GPU 训练，并新开输入版本；旧检查点维度保持不变；
   - 与 DESIGN / 计划 §2 第 9 项“出战学生与续走学生拆开（大模型 / 实体 + 注意力）”是同一件事，合并推进。

## 不做的事

- **不手写轨迹特征**，比如“算出每颗球会经过哪些格子”。这等于把物理公式喂给模型，属于用户明确不要的手写规则或公式。
- 物理推演交给老师搜索用真实引擎做；学生只学老师的选择，价值网学输赢。

## 历史：这条路以前走过一半（2026-10-29 补）

- PPO 时期的策略 π（`GameplayModelV1`）就是个体 token + 关系注意力 + GRU，790 万参数，带“种类对 / 行差 / 列差 / 同格”相对偏置。代码 10-19 删除，tag `pre-cleanup-20261019`。
- 在 L7 固定卡组上，约 50 万参数的无记忆 CNN 模仿它上场 56/64（π 58/64），快 4.7 倍；从零模仿“π + 搜索”的 CNN 学生 974/1024，π 937。见 `learn/05`、`learn/06`。
- 当时的代价：完整关卡 token 中位 121、最多 150；Python 逐步组装 token 3.3 ms/步；GRU 让 PPO 每次更新从 9 s 涨到 110 s。
- PPO 线失败的原因是环境胜利判定 bug 和一次改太多；蒸馏失败是因为在 π 原参数上微调。都不是结构的问题。
- **结论**：只证明了“L7 固定卡组上注意力多余”。没见过的卡组和空间关系类关卡从未比过，这正是现在的短板。

## 怎样判断有没有收益（task153，10-29 起）

1. 先在 Mac 上小规模对照，三臂同数据同轮数：现行 64 宽 CNN、等参数量的宽 CNN、个体 + 注意力。
2. 指标按“训练见过 / 没见过的卡组”和地形分开。注意力必须赢过宽 CNN 才算结构收益，否则只是参数多。打不赢就写结论停手。
3. 赢了才做 C++ 前向，再放进生产的 alternate-recipe 槽位，与现行架构同轮竞争，由门禁裁决。

## 速度

- 推理不是采集大头：10-16 实测一局模拟 35 s、学生推理 2.7 s。注意力约是卷积的 3 倍，整局估计慢 15–20%（需重测）。
- **不用 LLM 稀疏注意力**（NSA / DSA / MoBA / InfLLM-v2 等）：它们针对上万到百万 token，DSA 每个 query 就选 2048 个，比我们整局 token 还多；在 n≈150、batch=1、CPU 上，开销主要在投影和 FFN（随 n 线性），QKᵀ 约占三成，加速核也都是 GPU 大批量的。以后若要整局几千步的长记忆，再看线性 / 稀疏注意力。
- 省时手段，按优先级：
  1. **角色拆分**（首选）：老师根节点出手、生成候选用大模型，续走里的上千次前向仍用小 CNN（AlphaGo 的策略网络 / 快速走子分工，即计划里“出手学生与续走学生拆开”）。续走速度不变。若续走也需要更强，再把大模型蒸馏回小 CNN。
  2. 只做实体 token（格子交给卷积分支）、按行局部注意力加少量全局 token、Perceiver 式潜变量瓶颈。
  3. 老师比较多个候选时把续走凑批计算（工程量大，1、2 不够时再做）。
  4. 减宽减层、int8。

## task153 第一次对照结果（10-29，小样本，暂停）

- Mac 本地白天 L7–L10 扰动卡组示范 152 局（训练 96 局 / 23 套卡组；未见卡组 32 局 / 32 套），单种子，12 轮。
- 未见卡组完整动作准确率：CNN64 91.2%、等参 CNN81 90.6%、实体注意力 84.7%；种植动作 20.1% / 21.6% / 21.5%。注意力在“种不种”上明显退化，种植选择与等参 CNN 持平。按停止条件不做 C++ 前向。
- 局限：数据小（注意力通常更吃数据）、只有白天、旧存档缺像素 y 和滚动坚果位置，实体分支可用的额外信息有限。代码保留在 `origin/entityattn`（`arch: entity_attn`，`scripts/compare_entity_student.py`）。
- 调用比例实测：一局 L7 根节点前向 882 次、续走 116,190 次（1 : 132，根节点占 0.75%），CNN 每次约 61 μs。角色拆分后速度不是问题。
- 以后若重开：用生产规模数据、含屋顶 / 保龄球等空间关卡、补齐像素 y 等字段，在显卡空档跑。

## 用户 10-29 决定：花大功夫改网络结构和输入 → 学生 v3（task157）

- 旧 `GameplayModelV1` 的设计明显优于 task153 半成品：12 种 token、种类 / 类别 / 变体嵌入、行列嵌入、4 层 192 宽 6 头、种类对 + 行差桶 + 列差桶 + 同格 + 目标链接的关系偏置、卡包 / 格子指针头（卡包不进全局池化）、富公开输入（植物状态计数、僵尸精确 x/y 与护甲相位、投射物 xyz 速度、割草机、坟墓、僵尸名单、行摘要 token）。
- 它当年“输给 CNN”只限 L7 固定卡组；慢主要是 Python 组装 token，以及 GRU / PPO。
- v3 路线：C++ 产出富 token 输入（采集随帧写入；旧存档能否重放回填另测）→ 移植旧编码器（去 GRU / PPO）→ 四臂 × 多种子对照（见过 / 未见卡组、分地形）→ 根节点用 v3、续走仍用 CNN → 生产 B 槽位竞争。
