# ★★ 主问题：训练会"熵爆炸"崩溃，而**是否崩溃由随机种子决定**

（10-13/10-14 查实；完整数据见 `2026-10-14.md`、`docs/codex-report-v6.md`。）

- **同一配方、同一起点、只换随机种子**：v3（seed 0）1M → **92.58%**；`bc_seed1_v1`（seed 1）100k →
  **50.78%（贪心）/ 39.06%（采样）**。**→ 种子方差（≥34pp）远大于 256 局的评估噪声（±4.07pp）。
  单种子结论一律不可靠。**
- **崩溃不是"不玩了"**：C2 峰值火力与 v3 相同、花阳光更多，但**被吃 2.4 倍、割草机 2 倍** → **"照打但防不住"**。
- **★ 熵末值是"会不会崩"的「候选」预测器 —— 但前瞻检验已把它削弱**：样本内 12/12（后扩到 15/15）看着完美；
  **在 3 个新种子上只有 2/3**（seed3 末熵 0.02381 越阈、成绩却 82.42% 不显著 → **假阳性**）。
  **→ 降级为"待验证的预警候选"：不许当失败判据、不许外推成崩溃概率。**
  （基准 v3 稳定 0.0047→0.0065；C2 涨到 **0.113**、criticwarm **0.333**。）
- **★★ 因果已由干预钉死（10-14 v6）**：给已知会崩的 seed1 加"**熵守卫**"（`optimizer.step()` 后在**同一
  minibatch** 重算熵，超 `ppo.entropy_guard.max_entropy` 就**恢复本次 train_update 开始时的模型参数 +
  AdamW 状态**并停止该次更新）。三档阈值全部极显著救回：无守卫 50.78%/39.06% → **0.01**：84.38%/85.16%；
  **0.02（推荐）**：84.38%/84.38%；**0.05**：86.33%/81.25%；**vs 无守卫 +33~+46pp（Holm p ≤ 1e-15）**，
  三档两两不显著（p≥0.729）。**→ 熵爆炸是崩溃的「因」，不只是「果」。** 守卫对好种子**无副作用**
  （`seed0+守卫0.02` vs v3 @100k：贪心 −0.78pp p=0.856、采样 +3.52pp p=0.422）。
- **⚠️ 反例**：v3 的熵**最大**也到过 0.0851（单次尖峰）却没事 → **看末值/持续性，不看单次尖峰**。
  **⚠️ 时序钉不死因果**（C2/B10 熵先于成绩下滑，criticwarm/B5 成绩先降，B8 同节点后恢复）→ **只有干预能定因果**。
- **★ 这改写了整个项目的解读**：**6 个"变差"的 run 熵末值全部 > 0.015**（seq32 / val2 / gae95 /
  criticwarm / seed1 / 旧 v2）→ **它们可能是同一个失败模式，不是各自参数的问题**；**必须给它们都加守卫重跑**，
  才能分开"参数效应"与"崩溃效应"（v7 轨道 B）。**无守卫多种子 100k（v6 最终）**：seed0 84.77%、
  seed1 50.78%、seed2 63.67%、seed3 82.42%、seed4 87.89% → **非基线 4 个里 2 个显著崩，点估计 50%，
  Clopper–Pearson 95% 区间 [6.8%, 93.2%]**（样本小，区间很宽）。
- **★ 假设 H2（正反馈环）**：一批 16 局大多输 → 优势几乎全负、方向单一 → 梯度把策略推开 → 熵升高 →
  表现变差 → 下一批输得更多。**好种子能被"KL 刹车 + 后续批次转好"打断，坏种子锁死。**
  **`won=0` 是点火源但不是充分条件**；**KL 刹车挡不住熵爆炸**（它管"改了多少"，不管"改歪了没有"）。
- **★ 中间环节已证实（10-14 v7 §E1a）**：C2@100k（崩）vs v3@100k（好）的**落点错配三指标全部显著更差**
  （Holm p = 3.4e-5 / 0.0034 / 9.6e-4）→ **"熵崩溃 → 决策/落点质量下降 → 掉分"这条链接上了**
  （详见 `notes/lane-mismatch.md`）。⚠️ 但它是两检查点间的配对机制证据，**不识别熵是唯一原因**。
- **★ 熵涨在哪类决策上（10-14 v7 §E1(b)，已实证）**：把熵按动作类型拆开（**只加日志、行为零改变** ——
  该 run 与无日志 C2 的 9 次更新 episode digests / 所有 PPO loss / optimizer steps **差值全为 0**，
  100k 评估逐 seed 相同、最终 checkpoint 张量 `torch.equal`）：
  **首次跃升（update 2）是 `wait` 主导**（wait 0.0578 vs plant 0.0190）；**update 6–9 才转为 plant 偏高**
  （update 9：plant 0.2624 vs wait 0.1063，约 2.47×）。
  **→ "熵涨 = 种植时犹豫"这个简单机制不成立**；顺序是**先等待策略分化、再扩散到种植选择**
  （与 §E1(c) 首次分叉就在 wait 一致）→ **不能把 wait 熵当旁观指标**。
  ⚠️ update 9 的 plant 只有 110 个样本（wait 1,064），要按小样本解释。
- **★ 守卫触发率（10-14 v7 §C，v6 @100k）**：seed0/.02 = **6/9（66.7%）**、seed1/.01 = **10/10（100%）**、
  seed1/.02 = **8/10（80%）**、seed1/.05 = **2/9（22.2%）**。**seed1/.01 已逐次全触发 → 有"锁死 PPO 更新"
