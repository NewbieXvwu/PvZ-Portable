## 为什么
- 小丑、橄榄球、气球、海豚这些强对策型僵尸（屋顶还有蹦极、投石车）靠随机碰撞学不会。用户 10-23 提出这一点。
- 主控方案第 3 步：LLM 从预训练里知道 PvZ 的对策，让它在关键局面提议 1–3 个动作，**只进老师的候选集**，用不用由模拟推演决定。先验来自 LLM，对错由模拟器判，不是手写规则。
- 计划见 `MEMORY/docs/student-bottleneck-plan.md` 2026-10-23 22:05 那条。
- 现有 LLM 教师诊断工具链：`teacher-diag-*.md`、`scripts/episode_query.py`。场景渲染成文字用 `_fmt_scene`。

## 要做的
1. **接口**：
   - 给 `search_play.py` 的候选生成加一个来源"llm"：在指定的决策点，把当前局面用 `episode_query` 同一套文字渲染交给 LLM（`$GEMINI_API_KEY`，模型照 teacher-diag 文档），要求输出 ≤3 个合法动作；
   - 合法性用引擎的合法动作表过滤，非法的丢弃并计数；
   - 结果并入候选，与静态 / 学生候选一起推演、减半、复核；
   - **这是实验臂**，只在比较脚本里打开，不进正式路径（同 task42 的做法）；
   - LLM 回答要缓存：按局面哈希落盘，重跑不重复花钱。
2. **在哪些决策点问**：不是每步都问（太贵）。先用两种触发，各报成本：
   - (a) 学生首选的候选叶值都低于某个分位（老师"没主意"时）；
   - (b) 本行或相邻行出现了本关的新僵尸类型。
   - 触发条件写成可调参数，**不写打法规则**。
3. **测量**（预登记后再跑）：
   - 场地：白天 L7 d7（老师已经会打，看 LLM 会不会帮倒忙）；屋顶 L41（task46，老师 15/16）；雾区 L31（老师 0 胜）。
   - 每处 16 局，A = 现行老师，B = 现行 + LLM 候选，同种子配对；
   - 报这些数：LLM 候选被推演选中的比例、选中时的叶值 / 终局差、胜率与末波配对差、每局 LLM 调用次数与费用、非法率；
   - 雾区要另报 LLM 提议里开雾植物与对策卡（磁力菇 / 仙人掌 / 三叶草 / 高坚果）的比例。
4. **结论**：
   - 写进 `MEMORY/docs/llm-candidates.md`；
   - 建议是否值得接进关键时刻宽搜索 / 对策练习局（计划的第 2、4 步）。主控决定。
