# task45 追加D：LLM教师诊断的独立复核

本阶段只诊断，不决定倍率课程起点，不改生产策略、搜索门槛或训练配方。Gemini 原文分别保存在 [human](teacher-diag-fog-l31-human.md) 与 [xray](teacher-diag-fog-l31-xray.md)。原文的判断并不自动成为项目结论。

## 可核对的事实

原版 L31–34 每关首个评估 seed，师生 × 两种观测共16局；每臂4局。8对师生的全部动作逐条相同。5946个根节点，正式 Python 学生与原生续走学生的动作全同，非法动作0。16局的终波、终tick、决策数及种植类型与第一阶段冷启动原记录一致。详见 [逐局量化证据](task45-fog-timelines.json) 及任务书结果表。

这些样本全局射手数为0，香蒲数为0；只种阳光菇、睡莲、部分土豆雷。每行火力采用引擎 `SUBCLASS_SHOOTER` 的活株计数，土豆雷另列，不能把射手数当成所有伤害的DPS。原始时间线在 ignored 的 `artifacts/task45/phase-d/`，按每个决策的实际引擎tick记录；未观测的中间tick没有插值。

L31 human：阳光菇/睡莲/雷种植7/5/2，初始50、产出345、支出350、末余45，最高60。L31 xray：2/3/0，初始50、产出90、支出125、末余15，最高50；末只阳光菇消失后9098tick没有生产者。阳光收支逐局严格守恒。这是实测最高值，不是引擎阳光上限。

L32、L34 human曾到110阳光，引擎分别给出34、33个合法豌豆落点，仍等待或买便宜植物。故“所有时候都是买不起”不成立；也没有证据支持“卡组缺睡莲，导致水路种植全部非法”。实际水路种植只有睡莲，存在底座却未升级或架火力。

L31 human/xray 实际搜索31/10次，均0次推翻。档案四位小数的有限候选叶值中，最大“候选减学生”分别0.0112/0.0084，最高候选叶值0.0264/0.0212；均未越过当前0.02锚定门槛。此数字支持“当前搜索没有给出足够分差”，不证明这些价值是校准后的通关概率，也不证明调低门槛会改善。其他关可能有不同采样次数的已剪枝候选，不能把所有有限候选最大值当成最终获胜候选。

## 透视臂原文中的错误或证据不足处

- **`branch1` 不是单分支搜索参数。** 它是静态候选价值网的检查点名称。实际配方是每卡保留1个静态落点，加等待、学生动作与最多2个学生候选，随后多样本续走/减半筛选，并在拟推翻时追加9个独立未来核验。L31 xray首根节点就记录了5个有限候选。原文反复以“单分支锁死在学生候选顶部”为主因的论断不成立；不能据此接受其 `branch=4/8` 建议。
- **“50阳光上限”只是本局最高观测值。** 不能误作引擎封顶值；另外两局已经观测到110。香蒲未出现与经济不足一致，仍不能证明换卡组或换落点即可通关。
- **反事实末波更高不等于存活时间更长。** 例如第44步改土豆雷到(0,8)，末波由7到9，但终tick为20721，早于原局21134。更快清怪会改变波次推进；末波、tick、丢车、被吃数量必须并列，不能只凭末波称“生存延长”。
- **机制叙述需要单独证据。** 单步变更之后学生重新决策，后续很多动作都可能变化；“延缓丢车”“保留阳光因此形成持续火力”等不能只从末波反推。确定性whatif能证明该动作在这一续走条件下改变整局结果，不能把每一条解释都视作已验证。

## 不透视臂原文中的错误或证据不足处

- **“8张卡有5张100+费”算错。** f8中100+费只有豌豆100、樱桃150、寒冰175、香蒲225这4张；坚果是50，另3张是25。L31 human实际有13个决策根节点可合法种坚果（首次tick19601，阳光60），但0次种坚果。不能把全部不补防解释为支付掩码禁止。对应逐卡合法决策数已加入量化JSON。
- **晚期“单步已无法逆转”超过测试范围。** 教师测的是12个枚举落点及另一个(4,3)土豆雷落点，未穷举所有动作或多步组合；只能说这些候选没有改善。原文还将 `wait:60` 写入其第365步测试清单，原工具轨迹并未在此点测等待；本次独立复核另补等待，确认同为8波/22436tick/丢车5，仍不支持普遍无解结论。
- **静态网和叶值网职责要分开。** branch1筛选刚种下时的候选落点，v4给续走叶局面打分。原文所谓“叶值方差极小”是待检验假设，本阶段从档案核对的是候选均值与相对学生的分差，未测每个候选跨未来样本的方差。
- **12000tick是长大过程的倒计时。** `UpdateSunShroom` 之后还有生长动画，不能把恰好12000tick直接等同于已经完成长大并开始25阳光产出。当前原局的每笔阳光产出事件实际都是15。

## 反事实的复核口径

`scripts/fog_verify_whatif.py` 独立重放教师提出的关键候选。每个候选都核对分叉前的所有公共物理帧与原存档相同（JSON数组统一后逐字段精确比较），并记录动作是否被拒绝、末波、末tick、丢车与植物被吃数，见 [复核数值](task45-fog-whatif-verified.json)。原动作基线也以同一学生续走重跑，避免拿“老师续走原局”与“学生续走变体”混为一谈。

透视第32步（tick1800）阳光菇(4,5)原动作：7波/21134tick；改为(1,3)：10波/28588tick。透视第44步（tick2460）睡莲(3,8)原动作：7波/21134tick；改等待60：9波/24646tick。它们都是仍然输局的单种子局部改进，不能作为新政策、通关证明或训练标签质量的总体担保。

不透视第48步（tick2700）睡莲(2,2)基线为8波/22436tick；改土豆雷(0,2)为10波/30441tick（丢车同为5），改等待为8波/19986tick（丢车4）。第365步（tick20696）原土豆雷(1,3)、替换(4,3)或等待均为8波/22436tick/丢车5；替换(4,3)被吃植物由6增至7。该晚期样本未见改善，早期样本有局部可纠正信号，均未通关。

## 交主控决定的下一步

目前没有发现该区的动作合法性、卡组所有权或Python/原生学生输入执行错位；这不等于排除了全部工程问题。下一步优先补足原版夜间泳池“经济→防御转换”的可区分数据，并检查候选及叶值是否能识别这些局部改进，暂不直接训练当前0纠正标签。

数据需求具体是：L31–34原版开局0–8000tick，25–110阳光下阳光菇落点、等待积累与空睡莲投入的配对续走；水面已有底座但尚无攻击植物的过渡状态；阳光菇被吃前后、零生产者低阳光的终局状态。用完整续走/终局结果标记候选差异，再核验现有2500tick叶值与候选筛选丢失了哪些可改善动作。这里的落点只是诊断候选，不能写成硬编码规则。

可用L11–19夜间草地的阳光菇经济及L21–30泳池的底座/火力状态做迁移对照，但不能声称dw4i“从未见过夜间”：task23已有夜间训练且夜间面板592/1152胜。当前更准确的假设是夜间与泳池组合及f8卡组的覆盖不足，仍需数据审计和配对验证。换卡组另开任务族并预登记，保留旧档案语义。倍率只能用于诊断“开始守住时实际做了什么”，未经主控批准不设为采集起点；不启动qc。
