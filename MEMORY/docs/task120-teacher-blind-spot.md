# task120：老师盲点诊断——学生没用过的卡，老师为什么也从不选

主控 2026-10-27 派给 Mac codex-plus2b。分支 `blindspot`，基于 `origin/pvz-env`。Mac 跑，最多 8 个游戏进程。

## 背景

- task118（`MEMORY/docs/task118-balloon-decks.md`）：气球关把樱桃换成仙人掌 / 香蒲后，老师 48 局里仙人掌、香蒲各种了 0 次；高坚果换仙人掌也只种了 3 株。
- task102：屋顶 L42 老师候选均值 0–0.007，最大增益 0.003，过不了 0.02 的换动作门槛，从不推翻学生。
- 两件事可能是同一个结构问题：老师的候选来自学生前 k + 静态网每卡挑格，评估靠学生续走 + 叶值。学生和静态网从没见过的卡，候选可能根本没生成、生成了格子也差、或者续走里学生不会配合，增益被低估。

## 要回答

1. 气球关（L33/34，cactus 卡组，task118 的面板与种子）：仙人掌是否进了候选？进了的话，候选格子、续走价值、与学生动作的增益分布是什么？卡在哪一环（没生成 / 格子差 / 续走低估 / 门槛）？
2. 用同一套方法看屋顶 L42 一两局，确认是否同一环。
3. 基于 1、2 提一个**结构性**改法（例如候选生成覆盖所有合法卡的若干格、门槛按不确定度定、续走里的探索），预登记一个小 A/B（气球关 16 种子配对 + 一个对照关防退步），跑完给结论。不写手写规则或公式。

## 结论（一）：两处盲点是同一环——引擎的合法动作集按当前阳光过滤（2026-10-26，Mac，分支 blindspot）

**一句话：仙人掌和西瓜不是"老师不选"，是它们从来没有进入候选集。引擎给出的合法种植动作只包含当前买得起的卡；r11 的消费策略在决策时通常只剩 30–40 阳光，125 以上的卡在 20/32 局里一次都没出现过。进了候选的那 26 个决策里，它又排在中游（与最佳差中位 0.020，正好压在 0.02 门槛上）。**

### 方法

- 用 scripts/roof_teacher_diagnostic.py（task102 的原样生产搜索，不改算法）逐决策记录：合法格、静态网对每张卡的格子与分值、候选集、续走值、实际动作。
- 新脚本 scripts/teacher_blindspot_analysis.py 把这条链拆成漏斗：搜索决策 → 有合法格 → 进候选 → 候选第一 → 实际执行 → 种下株数，并按卡组逐卡输出"阳光够的决策 / 合法 / 候选"。
- 参数与 task118 老师臂逐项一致：r11 1cf82f5e、v5 叶值 8a636d33、branch1 静态网 24858410、Mac 引擎 6f7d2c3f、beta=1 / verify=9 / student-candidates=2 / per-card=1、halving。8 进程并行。
- 气球：L33/L34 cactus 卡组，task118 面板种子 16–31，共 32 局、4 758 个搜索决策。屋顶：L42 记分板卡组，种子 103410016/017，2 局、120 个搜索决策。

- **候选集不是瓶颈**：每张卡"进候选"与"有合法格"逐卡完全相等（per-card 1 的每卡保底一直在生效），所以问题不在"候选只取前 k 张"。
- **卡在合法动作生成**：legal_actions.plants 只给买得起的卡。决策时阳光中位 30–40，单局最大阳光中位 120（最小 80、最大 280），13/32 局曾达到 125，其余 19 局仙人掌一次都没成为合法动作。仙人掌在 4 758 个决策里只有 26 个（0.5%）有合法格，分布在 12/32 局。
- **同价对照说明这不是"卡本身没人要"**：同为 125 的高坚果在同样 32 个可负担决策里有 22 次合法、被选中 13 次；仙人掌 0 次。所以在能付得起的那一刻，搜索是在仙人掌和高坚果之间做比较，选了高坚果。
- **进了候选之后也基本赢不了**：26 个候选决策里，仙人掌与最佳候选的续走差中位 0.020089（门槛 0.02），p10 0.000047，p90 0.2799，最大 0.4246；价值排名中位 5/10。也就是说绝大多数时候它不是"差很多"，而是"刚好压在门槛上"，另有约 10% 的决策与最佳几乎并列（<5e-5）。
- 静态网给仙人掌选的格子集中在最后两列（(8,5)×4、(7,4)×4、(8,0)×4、(7,2)×3…），不是明显的前置/无效格。
- 胜率与 task118 逐格吻合：L33 3/16、L34 0/16（合计 3/32）。同一批种子、同一套模型，诊断没有改变对局行为。

### 屋顶 L42（同一方法）

- 120 个搜索决策里，决策时阳光从未达到 150（两局最大 125 / 50）。
- 西瓜投手 39（300）、冰西瓜 44（200）、樱桃 2（150）：合法 0 次、候选 0 次、种下 0 株；高坚果 23（125）2 次可负担、2 次都被选中。两局都输（第 12 波、第 4 波）。
- task102 当年测到的"候选均值 0–0.007、最大增益 0.003"是在便宜卡上测的；贵卡根本不在候选里，所以那个结论不能读成"西瓜的增益小"。

### 判读

1. 两处盲点是同一环：候选生成继承引擎的"当前可负担"过滤。学生的消费型经济让决策时余额长期低于贵卡价格，于是贵卡对搜索永久不可见——不是静态网格子差，不是续走低估，也不是门槛，是"没生成"。
2. 可见之后还有第二道坎：仙人掌与最佳候选的差正好落在 0.02 门槛附近，即使把门槛按不确定度调低，也只能在少数决策上翻转，且 task118 已证明种下去不改善胜负。
3. 因此结构性改法必须针对"看得见"：让搜索能评估"攒够再种"的候选，而不是继续在当前可负担集合里挑格子。具体设计与预登记 A/B 见下一节。


## 预登记：结构性改法与小 A/B（2026-10-26，写于跑对局之前）

### 改法

**让搜索能评估"现在买不起、但攒一会儿就买得起"的卡**，实现为测量臂 scripts/save_candidate_arm.py，不改 search_play：

1. 在每次决策的候选评估之后，取卡组里当前买不起、但阳光已达其价格 50% 的卡（每决策最多 1 张，同卡 600 tick 内只探一次）。
2. 从决策根快照出发，在引擎里按 300 tick 步长等到该卡可负担（上限 1800 tick），在该未来状态用静态网选它最好的合法格，再用 12 个未来（与正常候选的 samples+verify 同量）做续走评估，终点 tick 与正常候选一致。
3. 若未来值比当前最佳候选高过同一 0.02 门槛，本决策改为执行等价的 wait；下一个决策该卡已经合法，原搜索自然可以在它和其他动作之间比较。

这一步只改变"搜索看得见什么"，不写任何卡/格/时机的规则，也不改学生。

### A/B

- 格：L33、L34（task118 cactus 卡组，种子 103320016–031 / 103330016–031）+ 对照 L7（记分板 day 卡组，种子 103060016–031）。
- 两臂同种子配对：baseline = 原样 search_play；save = 上述测量臂。参数与 task118 老师臂一致（r11 1cf82f5e、v5 8a636d33、branch1 24858410、引擎 6f7d2c3f、beta=1 / verify=9 / student-candidates=2 / per-card=1、halving）。
- 主判据（先定后跑）：气球两关合计胜局比基线 **+3 局以上**，且配对 McNemar 精确检验 **p < 0.10**；同时对照关 L7 **不得少 2 局以上**。两条都满足才算"值得上线评估"，否则记为无效。
- 次要读数：save 触发次数、累计等待 tick、贵卡（≥100）种植数、每局决策数与墙钟。

- 配对 McNemar 精确检验：7 个不一致对全部朝 save 方向，**p = 0.0156**。
- 预登记判据（+3 局且 p<0.10、对照关不掉 2 局）**全部满足**，按事先约定记为"值得上线评估"。
- 机制核对（种下株数，32 局合计）：三叶草 40 → 115，高坚果 13 → 31，**仙人掌 0 → 3**。也就是说，改法主要救活的是 100 阳光的三叶草和 125 的高坚果；仙人掌仍然几乎不被选（3 株），与结论一里"它进候选时也排在中游、差 0.02"一致。
- 代价：L33 +51%、L34 +77% 墙钟（每决策最多一次等待探针 + 12 个未来）。对照关 L7 的行为与胜率都不变（决策数 1063 → 1057），说明探针在便宜卡组上基本不触发。

### 判读与限制

1. **盲点是真的，而且能被一个不改学生、不写规则的搜索改动补上**：只要让搜索看见"攒一会儿就买得起"的卡，气球两关合计 3/32 → 10/32，对照关零退步。收益来自三叶草（唯一真正管用的对空牌）能更早进入比较，而不是仙人掌。
2. **仙人掌本身仍然不是答案**：即使可见性修好，它 32 局只种 3 株；这与 task118（换卡组无效）和结论一（进候选时差 0.02）互相印证。贵卡的问题分两层——125 以上要"攒得住"，而这张学生的经济攒不住；100 左右的卡只要让它可见就够了。
3. 限制：这是老师臂、单卡组、每关 16 种子的测量，L34 基线在地板（0/16），+3 局里有多少是方差无法从 32 局里分辨；上线前需要在生产课程的任务族上复测，且 save 臂每局贵 50%–80%，要先确认采集预算。
4. 该臂是测量实现（探针会推进引擎再回滚、计划不跨决策绑定），不作为生产代码；若主控决定上线，应把它做成 search_play 的一等选项并补测试与导出兼容性检查。
