- task116 交付学生输入 `v2bungee`（蹦极可见状态），task130 交付 `v2sleep`（再加蘑菇睡眠 / 唤醒中两通道）和价值编码器 v4。两者都只做了代码与对拍，没有上线。

## 要做的

1. 建分支 `obsup`：`origin/pvz-env` 合入 `origin/sleepinput`，解决冲突。
2. **函数保持的加宽热启动**：课程训练器拿到旧输入版本的父检查点、配方 `obs=v2sleep` 时，把所有依赖输入维度的层加宽，新增通道的权重置零，其余权重原样拷贝。要求：新通道全零时，加宽后模型的输出与原模型逐位（或 float32 误差内）一致。用小测试证明。不需要改结构的其余部分。
3. 旧训练行：旧帧没有 `bungee` / `sleep` 字段，按新版本打包时新通道为零。说明课程的行缓存签名变化后会怎样（是否全量重打包；若是，在台式机上估计耗时、内存与磁盘）。能增量就增量。
4. 引擎：在台式机按现有构建方式把 `obsup` 编进**新目录** `build7`（不动 `build6`），用 `nice`，先看 `free -g`。旧学生、旧价值网仍能被 build7 加载（task130 已声明，抽一个现役学生跑一局即可）。

   - 激活：可执行文件切 build7，配方切 `obs=v2sleep` 的新配方文件（另起名字，不改旧配方），学生加宽热启动；
   - 基线校验对 14i 与 14g 两种在役状态都成立（14i 可能还没上线）；
   - 部署前检查要便宜（AGENTS §6.5）：不要全量重放、不要整套测试。
