# task133：LLMPlay 第二轮任务清单：原版难度的屋顶关与门禁卡组

主控 2026-10-27 定。实现交给 agent，分支 `llmplay2`，基于 `origin/pvz-env`，需要已合入的 gate v5 配置（`configs/adventure_scoreboard.json`、`configs/gate_v5_panel.json`，来自 task128 / 58872f22）。

## 背景

- GPT Pro 第一轮（run 438cb30a）打完 29/31：屋顶 2–3 倍、雾夜 2 倍、L30/L40/L50 原生传送带全部达标。只剩 L47/L49 的 4 倍没过；用户与主控决定**不再死磕 4 倍**。
- 门禁 v5 只按冒险模式**原版 1.0 倍、记分板卡组**判。它的面板里屋顶只有 L41 和 L46 两关：其余屋顶关老师和学生在记分板卡组下都**一局没赢过**，所以没能进门禁。
- 现在真正缺的是屋顶 L42–L45、L47–L49 在原版难度下的赢局，而且要用门禁实际用的卡组。按 AGENTS §8：打不过时先查是不是卡组的问题。高倍数数据并不缺。

## 要做的

1. 在 `configs/human_demo_tasks.json` 里新增任务族（新名字，不改旧任务）：
   - **F 层**：屋顶 L42、L43、L44、L45、L47、L48、L49，原版 1.0 倍，卡组用 `configs/adventure_scoreboard.json` 里该关的冻结卡组。L45 是蹦极闪电战，沿用现有 `demo_roof_45_orig_m100` 的设置。
   - **G 层**：同样这几关，再各加 1 套按卡组规则 v5（`MEMORY/docs/deck-rules-v4.md` 末尾）手选的卡组。要求和记分板卡组明显不同，例如投手类型不同、有没有毁灭菇。卡组在 DESIGN 里登记。
   - **H 层（卡组泛化）**：白天 L2/L6/L8、夜间 L12/L16/L18、泳池 L22/L26/L28、雾夜 L32/L36/L38，共 12 个任务，原版 1.0 倍。每关配 1 套按 v5 规则生成的卡组，要和记分板卡组以及课程常用卡组明显不同：白天和泳池的记分板卡组都是 `[0,1,2,3,4,5,7]` 加地形卡，学生对卡组过拟合，留出卡组连续否决就是这个原因。task129 的生成器已出结果时就用它生成，否则手选。卡组在 DESIGN 里登记。
   - 用户 10-27 要求：任务量要够 GPT Pro 跑满一次会话，三层合计 26 个任务。第一轮 31 个任务跑了十几个小时。
2. 改 llmplay 包里的 `PROMPT.md`：
   - 把五层表换成 F、G、H 三层，按顺序推进；子代理可以各拿同一层里的不同任务并行；
   - 达标标准沿用：每任务 5 个种子通关，其中 3 个稳健；
   - 某个记分板卡组连续 3 个种子都打不过时，允许直接报告“卡组打不过”并跳到下一个任务，报告里写出缺什么（例如没有投手打不到撑杆、没有处理蹦极的手段）。这本身就是我们要的诊断。
3. 重新打包 `llmplay_pkg`（7z 分卷，每卷 < 100 MB），包里带上新任务配置。资源包不变。
4. 本地用 1 个种子把 F、G、H 各层第一个任务的开局跑通（`Game(task_id)` 能建局、能存档），不要做别的验收。
5. 包做好后把 7z 分卷放到台式机 `~/pvz-llmplay2/`，并在本文件末尾写清楚用户要上传哪些文件。
