## 背景

r36 训练包（详见 `task156-data-mix-census.md`）：60% 行是课程开始前的历史 DAgger，L7 一关占 47%；随机卡组格（task137）只占 0.2%。卡组泛化是头号短板（老师在 54 套陌生卡组上 14.6%）。GPT Pro 两轮打出了 50 套以上不同的胜利卡组（task105 导入，`origin/llmimport`），task148 整理了屋顶候选卡组（`origin/gatev6`）。

等 deploy16 的 v2timer 基线出来后，要逐项做单变量对照，所以先把开关准备好。

## 要做的

1. **历史行降采样**：配方新字段（如 `label_keep: {"<标签前缀或正则>": 0.25}`），按存档稳定哈希决定保留（同一局整局保留或整局丢弃，跨轮次结果一致），已有不可变段尽量复用，说明重打包代价。先查现有 `label_weight` / `source_weight` / `level_balance` 能否直接实现同样效果；能的话只写配置示例，不新造字段。
2. **随机卡组格的卡池扩充**：task137 的 `make_random_deck_cells.py` 现在怎么生成卡组？加一个可选卡池来源：
   - GPT Pro 胜利卡组（从 task105 导入账本里读通关存档的卡组，按多重集去重）；
   - task148 的屋顶候选卡组；
   - 都必须过 AGENTS §8 的地形覆盖和黑 / 白名单（`scripts/pvz_tasks.py`），升级植物所有权照规则处理；
   - 每轮配额可配（现为 4 格 × 24 局）。门禁 / 挑选用的留出卡组绝不能进训练卡池，写防重叠的检查（便宜的集合比较即可）。
3. 小测试：开关关闭时训练行与课程逐位不变；降采样确定性；卡池去重与留出不重叠。
