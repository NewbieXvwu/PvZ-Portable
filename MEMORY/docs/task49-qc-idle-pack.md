### 数据契约与内存

- `packs/<key>.npz` 是小索引，指向 `packs/segments/<label-options-source-key>.npz`；行选项从训练配方解析，无增量/全量切换开关。`pack_monolithic` 仅供对拍作为全量参考。
- v2 wait 抽样为**每标签 seed=0**，标签内仍按原档案/帧顺序消费 RNG；新增其他标签不改变既有段。多段装载按全局 seed/标签档案序合并 CSR，batch 内容、训练/验证划分、shuffle 输入顺序不变。v1 跨标签抽样与之不同，所以升级首次必须建 v2 段，不能声称与 v1 历史训练逐位相同；本任务的逐位门禁比较同一 v2 行契约的全量与增量路径。
- 后台串行处理每轮快照，每个快照内部先打包后训练；标签构建可多进程，不会嵌套开预处理池。小语料冷启动允许 1 个标签构建进程（2 GiB 预算），随后按配方上限和语料内存估计扩大并发；CLI 单独打包也按 MemAvailable 限并发。
- 内存公式：`worker = clamp(floor((MemAvailable - 6GiB - headroom) / 实测worker峰值), 1, 上限)`；`headroom=max(0, 后台预测峰值-后台当前进程树RSS)`。预测峰值为 `3×紧凑段总字节+2GiB`，覆盖段装载/CSR 合并和训练主机内存；后台开始每个阶段前也检查 MemAvailable。当前游戏 RSS 已反映在 MemAvailable 中，不再次扣除。

### 采集学生落后一轮的含义

第 k 轮结束后，训练 k 版学生，同时第 k+1 轮先用上一版成功学生继续采；k 版训练成功后，在下一组开始前启用，绝不改组内/局内模型。DAgger 的执行动作仍是 beta=0 的行为学生，标签由搜索老师给，滞后主要改变学生到达的状态分布，并不会把旧学生的执行动作冒充老师标签。现行老师的续走也使用该组学生，因此不能进一步声称“同一状态跨学生版本的搜索标签一定相同”。每组保存 `student` / `student_round` / 起止时间，可按行为版本审计。

如果后台训练慢于整轮采集，滞后可以超过一轮：队列保留各轮快照，不丢数据、不冒用尚未成功的模型；这是吞吐与新鲜度的实际取舍，任务书的小规模验收不等同于学生质量评估。

### 部署说明（仅主控操作，本任务没有重启 qc）

1. 主控在 qc 两轮之间合并 `origin/qcpipe`，沿用现行生产命令及其 state / log / frames / 引擎 / value 参数，将控制器脚本换为合并后的版本，`--recipe` 指向合并后的 `recipes/dw4i.json` 绝对路径。不覆盖现有学生模型文件。
2. 已有状态的最后完成轮会自动入队（如果从未训练），新轮立即采集；失败/中断的后台快照重启时恢复。后台目录是 `<state父目录>/<state文件干名>.pipeline/`，每轮独立配方、日志、学生和完成标记。停止标志只在组间检查，退出前等待已保存轮的后台任务完成。
3. 首次启动会重建 v2 标签段，之后每轮只构建新标签。原配方与课程帧通过状态目录里的 `frames/` 链接视图合并；已确认缺失的两个传送带标签可从 dw4 原配方的 `training_frames` 读到。链接只引用原档案，包与缓存写状态目录，不改动来源语料。旧 v1 包不会被当作 v2 复用或被新 prune 删除。
4. 检查新日志同时出现 `round ... workers=... background headroom ...` 和 `background round ... pack/train started/done`；检查后续组 `student_round` 前进及 pack 日志的 `built` / `reused`。若后台失败，控制器在组边界报错并将快照标为 failed，不能把失败轮当作已换学生。实测时间与完整测试数字见上方最终验收。
