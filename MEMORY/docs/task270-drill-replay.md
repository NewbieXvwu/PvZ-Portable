# task270：drill 前缀重放与单题故障退役

2026-11-15，分支 `fix270`，基于 `5fbe4e31`（pkg238k）。未部署，未修改生产状态。

根因：task268 将前缀恢复与 token 回填统一到 `replay_actions()` 后，对所有 `action_rejected` 帧追加等待 60 tick。`search_play` 确实在补等后记录帧，人工记录器则在拒绝动作后立即记录帧。五个人工转换存档缺少 `ticks.jsonl`，因此进入动作重放路径，重复补等导致时间不匹配。转换后的帧仍保留人工记录器的 `operation` 编号。

改动：同一个 `replay_actions()` 仅对没有 `operation` 的拒绝动作帧补等，保留采集与回填原有时间语义。队列在恢复探针成功后，将连续零有效局涉及的格标记并保存到状态。同格再次 0/N 时调用 `retire_cell()`，记录失败原因及子进程 stderr 最后一行，跳过已退役格并继续其他格。出现有效局即清除标记，探针失败仍保持暂停。

台式机复扫：分支源码放在独立临时目录，使用生产引擎，单进程低优先级运行，内存上限 8,000,000 KiB。从状态文件只读合并在用与退役的全部 drill 格，逐题恢复当前 ladder decision，**90/90 成功，仍坏 0 题**，耗时 92.77 秒。手动退役的 8 题全部成功，覆盖五份存档：L32 snow（866、916），L39 cactus snow（1159），L33 cactus snow（640、612），L33 cattail snow（745），L34 cactus snow（732、615）。
