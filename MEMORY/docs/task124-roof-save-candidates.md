# task124：屋顶关的“攒够再种”——让搜索看得见西瓜

主控 2026-10-27 派给 Mac codex-plus2b。分支 `roofsave`，基于 `origin/blindspot`（task120 的 `--save-candidates` 实现）。Mac 跑，最多 10 个游戏进程。

## 背景

- 记分板：屋顶 L41–44、L46–49 学生、老师都是 0–1/16（task115）。
- task120：屋顶 L42 决策时阳光从没到过 150；西瓜（300）、冰西瓜（200）、樱桃（150）从未合法、从未进候选。`--save-candidates` 现行触发条件是“阳光 ≥ 卡价 50%”、等待上限 1800 tick，在屋顶根本不触发。

## 要做的

1. 只调 `--save-candidates` 已有的参数（触发比例、等待上限、每决策探测张数、同卡冷却），不写针对卡 / 格 / 关的规则。先在 L42 上看漏斗：参数放宽后探针是否触发、贵卡是否进入候选、未来值与当前最佳的差。
2. 预登记 A/B（先写判据再跑）：L42/L43/L44，记分板卡组，种子用记分板块 offset 32 的 16 个；基线 = 现行参数，臂 = 你选定的一组参数；对照关 L7（同上种子）不退步。
3. 如果屋顶仍是 0，给出下一步判断：是经济本身起不来（学生开局把阳光全花在花盆等），还是看见了也打不过。可引用 task102 / task104 的结论。

### 下一步判断

**当前证据指向冷启动经济与该分布下的搜索估值。** 正式屋顶两臂前6000刻度的支出完全相同：花盆8725阳光，向日葵3550，土豆雷2050，窝瓜1850。花盆占总支出53.9%，平均每局已买7.27盆，仅种1.48株向日葵。各局最大决策余额范围50～175，全部未达到200或300，B仍没有实际种出西瓜或冰西瓜。西瓜693次等待中551次仍买不起，经济约束持续存在。少数等到300并进入评分的计划，增益也远不足门槛。

因此这里尚未测到“种出西瓜后依然打不过”的真实对局结果。放宽候选参数解决了进入探针的问题，当前政策仍无法建立持续火力。后续方向沿 [task104](task104-demo-opening-rows.md) 的真实开局示范行补训与新种子冷启动评价，同时让经济建立至火力成型的续走进入价值数据。task102中的示范用预置花盆建立十株向日葵、再转西瓜，与本次开局消费记录形成直接对照。本任务未追加参数臂或训练。
