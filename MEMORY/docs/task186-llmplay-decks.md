## 任务族与计数

新增 `llmplay_decks_l{level}_m100`，原族定义与种子表保留。
用 `pvz_tasks.player_deck_levels` 统一复用源码解析的传送带跳过判定，
并排除打僵尸 L15 与砸罐子 L35。共40个普通选卡关（L1–49非5的倍数），
加现有接口已支持的L50 Boss，共41关；原版1.0倍、不截波、二周目解锁配置。
Boss使用既有任务卡组覆盖开局卡槽的支持，不改变Boss逻辑。

每项=(关卡,种子)。GPT Pro选6–10张牌，须与本关全部已登记胜利卡组至少差2张。
差异沿用原接口定义：两边独有卡数量的较大值，卡序不计，替换一张算一张。
一胜即登记该组；同组最多三个不同种子的真实败局，第三败存档的`note`必须写失败原因。
中途导出、放弃和重复导出不增加败局数。前两败后可以提前换组。
取消稳健、打法层和加压；`reason`原样写为存档`deck_reason`，要求一句话说明
经济、主力、防守、应急与地形专用卡。`strategy`/`deck_review`不再是分层必填项。

默认沿用llmplay5随包carry的1411条结论记录；原版1.0倍胜组按关登记并参与新组差异判断。
不搬旧对局文件、不重放；当前合法且非留出签名的胜组计入基础数量与覆盖。
旧带禁卡的胜组仅保留为历史登记，仍须避开其近似组，不冒充当前合法胜组。
旧任务定义保留，旧存档恢复仍读自身的实际卡组与环境。
只含结论的carry记录带`carried`标记，在后续out.zip续跑时继续保留，
不会因为旧对局文件本来不在包内就丢掉已登记胜组。

基础目标：白天、泳池每关12套；夜间、雾、屋顶、Boss每关16套，总计592套。
每关至少3套6–7张、3套8张。新组先补6–7张，再补8张，之后自由选6–10张。
每地形每张合法非禁卡至少进入2个不同胜利卡组签名；同组跨关获胜只算一次覆盖。
基础数量达到后，当前数量目标以4套为步长继续增加，队列优先提示覆盖缺口，永不返回完成。
按≥10小时持续设计，只有用户在GPT Pro会话明确说停才停；本开发任务交付后停止。

## 分片与种子

环境变量`LLMPLAY_SHARD`/`LLMPLAY_SHARDS`，0起编号，默认0/3。
也可调用`next_task(shard=i, shards=N)`或`configure_shard(i,N)`；参数影响当前进程，
以后每个新进程都保持原设置。N=1–41；N不是3时按完整关卡列表轮转分配。
多个独立会话须用不同片号；共用文件系统时指定不同`LLMPLAY_OUT`。

| 默认片 | 关卡地形 | 首批种子范围（跳过小游戏空窗） |
|---|---|---|
| 0 | 白天+夜间 | 186000000–204999999 |
| 1 | 泳池+雾 | 206000000–224999999 |
| 2 | 屋顶+Boss | 226000000–235999999 |

每关初始窗口100万种子，起点`186000000+(level-1)*1000000`；
窗口用尽后加50000000进入下一窗口。生成下一批候选而不物化全部种子。
不同关卡及不同分片的窗口不重叠。沿用原有claims锁、租期与释放；恢复中盘继续持有原项。

进度显示每关胜组数、当前目标、大小配额、登记卡组，以及每地形逐卡次数、目标与缺口。
结论只从progress和元数据计算，启动与续跑均不重放。第三败原因放原存档note，
不再创建旧C/E诊断文件。
