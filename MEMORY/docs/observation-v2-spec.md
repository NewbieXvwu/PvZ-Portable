# 观测 v2 规格草案

草案日期：2026-10-17。仅定义数据契约与编码，不改正式观测、模型或训练路径。目标是让学生与价值网络获得和老师续走一致的决策状态，同时把玩家可见信息与已生成但未出场的特权信息区分开。

## JSON 字段

保留现有字段含义，增加 `observation_version: 4`。Lean 与完整观测对新增公共字段保持同名、同单位；Lean 可以不返回诊断用非决策字段。

|对象|新增字段|单位与范围|用途|
|---|---|---|---|
|根对象|`sun_countdown`|剩余 tick，无天降太阳时为 `null`|直接读取 `Board::mSunCountDown`，让网络预估自然收入窗口。|
|根对象|`wave_timer_start`、`wave_refresh_threshold`、`wave_refresh_early`、`huge_wave_timer`|tick；生命阈值比例 0–1；提前触发布尔值|区分正常计时、低血量提前刷新和旗帜大波等待。现有 `wave_timer` 保留。|
|根对象|`pending_wave_zombies`|34 项非负计数数组，仅当前波和下一波|描述已抽好但未出场的类型构成。标注 `information_scope: "privileged"`，不得混入玩家可见字段训练。|
|植物实体|`id`、`state`、`state_countdown`、`launch_counter`、`launch_rate`、`shooting_counter`、`wake_up_counter`、`asleep`、`target_zombie_id`|整数/布尔，保留现有完整 JSON 字段命名|由当前完整 JSON 字段直接沿用；新增稳定 `id` 用于跨帧跟踪。`target_zombie_id` 在没有目标时为 0。|
|僵尸实体|`id`、`phase`、`phase_counter`、`velocity_x`、`body_health`、`helm_health`、`shield_health`、`flying_health`、`chilled`、`buttered`、`ice_trap`、`has_object`、`target_plant_id`|整数/浮点/布尔；生命非负、计时 tick 非负|标准 JSON 已含主要字段，需确保 Lean 或帧归档不丢失；目标 ID 仅用于实体关系，不作为类型特征。|
|弹道实体|`id`、`motion`、`x/y/z`、`vx/vy/vz`、`ax/ay/az`、`age`、`target_zombie_id`、`damage`|浮点/整数；tick 与引擎单位|已有完整观测字段保留，补充加速度和唯一 ID，使弹道可跨帧追踪。|
|掉落实体|`id`、`type`、`x/y`、`vx/vy`、`age`、`pickup_state`、`disappear_countdown`、`value`|浮点/整数/布尔|替换目前仅有 type/x/y 的信息，区分正在落下、可收取和即将消失。|
|割草机/格物|割草机增加 `id`、`state_countdown`；格物增加 `id`、`state`、`counter`、内容物类型|当前类型范围内枚举和 tick|Lean 可保留简单格位字段，完整 JSON 输出完整状态，供跨关任务特征编码。|

`id` 只需在一局内稳定，不要求跨重置稳定。`pending_wave_zombies` 是教师可用的特权信息；任何学生实验必须把该字段排除，除非训练和部署明确选择相同信息权限。

## 学生与价值网络特征

保留 92 个旧通道的索引与含义，追加 8 个通道，不重排旧权重：

|通道|内容|每格聚合|
|---|---|---|
|92|僵尸水平速度|有符号速度的均值，按最大步速归一化到 −1…1。|
|93|僵尸格内精确位置|同格僵尸相对格左边界的均值，归一化到 0…1；屏幕外僵尸仍放第 9 列。|
|94|护具生命|头盔+盾牌+飞行部件生命和，除以 200 后截断到 0…1。|
|95|带杆/持物威胁位|同格此状态僵尸数量，除以 4 后截断到 1。|
|96|植物即将行动数量|当前 tick 可发射/触发的植物数，除以 4 后截断到 1。|
|97|植物最短动作剩余|该格可行动植物的最小剩余计时除以上限，截断到 0…1；没有计时中的动作时为 1。|
|98|在途弹道伤害|按弹道当前格累加预计伤害，除以 200 后截断到 1。仅用于表示已有伤害，不混入僵尸当前生命。|
|99|可收集太阳|按太阳所在格累加太阳价值，除以 100 后截断到 1；其他钱币不计入此通道。|

普通植物专属阶段、特殊僵尸 phase、格物状态等高基数状态不应编码成一个任意整数热图。它们保留在 JSON 以及帧归档的实体字段中；CNN v2 首版只对第 7 关关键状态做聚合通道。跨关模型若评估显示这些状态仍造成明确混淆，再换实体 token 编码器，不能把这个未来改造混进当前规格。

全局标量保留旧 113 项：阳光、波次比例、tick、阳光收入、总波数、54 种卡牌就绪位和 54 种冷却进度。续走现有的两个历史标量（上一决策是否种植、两次采样间隔）继续追加。再追加 39 项：`wave_timer`、提前刷新位、大波计时、天降阳光计时、下一波 34 类计数、未收集太阳价值，共 39。基础 v2 输入因此为 `100×6×10 + 154`，即 6154 个数；若使用现有 35 项任务上下文（倍率+34 类可生成僵尸多热表），输入为 `100×6×10 + 189`，即 6189 个数。这里的 35 项上下文继续沿用既有接口，不把已抽好的波次名单混入其中。

当前 Python 编码器定义 `BOARD_CHANNELS=92`、`SCALARS=113`，见 `python/pvz_value_net.py:20-45`；C++ 续走特征定义同样写在 `EnvironmentRollout::Features()`，并在 113/114 索引写入两个历史标量，`src/EnvironmentRollout.cpp:106-166`。实现时 Python 和 C++ 必须共同固定通道索引、归一化公式、空值约定和聚合顺序；模型输入权重维度变更后须使用新特征版本训练，不尝试把 v1 权重静默加载到 v2。

## 旧数据兼容

旧帧保留僵尸精确 `x` 和 `vx`，见 `render_episode._frame()` 及 `pvz_value_net.featurize_numpy()` 的僵尸元组；旧网络仅忽略它们。因此历史帧可以无损回填新速度和格内位置通道。历史帧的僵尸健康值已合并身体、头盔、盾牌，无法拆出护具生命；撑杆阶段可按类型与速度做近似分类，但跳跃/受阻/冻结时不可靠，不能当作真实 phase 标签。

旧植物帧只存类型、格位与健康值，不能还原土豆雷 state、植物攻击冷却、睡眠或引信。若完整连续轨迹记录了种植动作及后续每帧，可以估算“首次被看见后经过的 tick”，但不能把这种估计冒充内部状态。旧帧不保留波次计时器、预生成波表、金币/太阳实体、弹道、格物内容与僵尸部件生命；这些特征只能由新观测版本采集。新旧数据应按 `observation_version` 分组，训练时只让能确定的字段进入特征；不具备的字段填明确缺失值并配套缺失位，不填虚构的零状态。

`render_episode._frame()` 当前也会丢弃标准 JSON 已公开的植物、僵尸、弹道和硬币内部字段。实现 v2 时先扩展帧归档 schema，再接 Python 训练与推理编码，最后同步 `EnvironmentRollout.cpp`；环境 C++ 的公开完整/Lean JSON 行为与版本号需要同时更新。纯离线旧数据可回填部分通道，但无新采字段不可通过猜测补齐。

## 边界

本草案不新增观测调试开关，不改训练数据和正式模型。第一层已存在的原始 `x/vx` 足以先做轻量实验；完整 v2 的价值在于把内部状态、波次节拍和已在途结果稳定写入新帧，并保证续走与 Python 编码同构。
