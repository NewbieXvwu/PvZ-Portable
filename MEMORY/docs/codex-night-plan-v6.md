## 2. 轨道 A（★ 最高优先级）：**熵守卫 —— 把因果钉死**

### A1 先复核并扩展"熵—崩溃"关联（纯读，便宜）

**本机 Agent 已算出上表（12 个 run）。你要做的是：**
1. **独立复核**（别只信我给的数）：对每个 run 读 `output/training_state.json` 的
   `update_history[*].losses.entropy`，重算"首/末/最大/中位"。
2. **扩展**：把 `bc_eval_1024_v1`、`bc_roll64_v1`、`bc_seq32_s1`（若有）等**所有**能找到的 run 都纳进来。
3. **找更好的判据**：比较"末次熵 / 中位熵 / 最大熵 / 连续 N 次超阈"哪个对结局分类最准。
4. **产出**：一张全 run 表 + **推荐阈值 + 它的分类准确率（要写出混淆矩阵）**。

### A2 ★★ 核心因果实验：**在已知会崩的种子上加"熵守卫"**

**思路**：`bc_seed1_v1` 是已知会崩的（100k = 50.78%）。
**如果在同一个种子上加一道"熵守卫"就不崩了，那熵爆炸就是因，不是果。**

**实现**（**这是本次唯一允许的源码改动**）：
- 在 `python/train_pvz_ppo.py` 的优化循环里，**每次 `optimizer.step()` 之后**计算当前策略的熵；
- 若熵超过阈值（配置项，默认建议 **0.02**，即基线的 ~4 倍），**回滚到本次更新开始前的参数**
  并**终止本次更新**（保留其余逻辑不变）；
- **必须做成配置开关**（例如 `ppo.entropy_guard: {"enabled": true, "max_entropy": 0.02}`），
  **默认关闭** → 对既有实验零影响。
- **改前先备份**（`python/train_pvz_ppo.py` → `.bak`），报告里**单列一节**写清：
  改了哪几行、怎么回滚、以及**它会不会影响配置指纹/续跑身份**（若会，要一并处理并在报告里说明）。

**实验**：
| arm | 配置 | 预算 | 对照 |
|---|---|---|---|
| **G1** | seed=1 **+ 熵守卫(0.02)** | 100k | **对照 = C2（seed1 无守卫）100k = 50.78% / 39.06%** |
| G2（可选） | seed=0 **+ 熵守卫(0.02)** | 100k | 对照 = v3 100k = 84.77% / 81.64% |

**判据（写清四种情形）**：
- **G1 显著优于 50.78%** → **熵爆炸是崩溃的原因**，守卫有效 ✅
- **G1 ≈ 50.78%** → **守卫无效**（可能阈值不对，或熵只是症状）
- **G2 显著优于 84.77%** → 守卫对好种子也有增益（意外收获）
- **G2 显著差于 84.77%** → 守卫**妨碍了正常学习**（那就要调阈值，而不是放弃）

**统计口径**：与 v3/C2 同预算节点、256 个相同 validation seed、精确 McNemar + Holm。

### A3 若 A2 成立，做**阈值扫描**（便宜，串行）

在 seed=1 上跑 `max_entropy ∈ {0.01, 0.02, 0.05}` 各 100k，**找最优阈值**。
（若 A2 不成立，**跳过 A3**，并在报告里写明。）

### A4 便宜补充（纯读数据）

- **熵尖峰 vs 崩溃的时序**：对 C2 / B9 / B10 / criticwarm / B8 / B5 逐个看
  "第一次熵尖峰在第几次更新" vs "评估成绩第一次掉下来在第几次更新"。
  **谁先谁后？** 如果**成绩先掉**，那熵是症状（H1 被削弱）；如果**熵先尖**，支持 H1。
- **C2 的 50k 到底坏在哪**：50k = 72.66%（掉 12pp）但那时熵已回落到 0.0061。
  **说明损害发生在第 1 次更新。** 把 C2 的 update 0/1/2 三次更新的
  `advantage_std`、`gradient_norm`、`clip_fraction`、`max_log_prob_change` 列出来，

## 4. 轨道 C：**修 I7 的触发点并重跑**（优先级低于 A/B）

**上次失败的原因已查明**：触发点选在"首次裸路"，而它总在 wave 1 / 僵尸 c9，
**ahead 和 behind 都没有合法空格**。

**改法**：触发条件改成 **"首次出现同时满足以下三条的帧"**：
1. 某路有在场上僵尸，且该路 `_reachable_dps(...)[1] == 0`（承压裸路）；
2. **该路存在合法落点**：`col < front_col` 的空格（ahead）**和** `col >= front_col` 的空格（behind）**都有**；
3. **阳光 >= 豌豆成本**（否则必然退化成等待）。

**arm**：I7（ahead）/ I7b（behind）/ I7c（向日葵）各 15 局，窗口仍 10 个决策。
**必须报送达率**；**送达率 < 50% 的 arm 标注"意向处理、剂量不足"**。
**判据同 v5b**（四种情形都要写清）。
