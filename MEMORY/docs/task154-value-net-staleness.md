### 1. 价值网校准：v5 在屋顶 / 开局格上不是"偏乐观"，是**没有排序信号**

v5 自 2026-10-24 13:24 起未换（`scripts/curriculum_queue.py` 的 `DEFAULT_VALUE`），
而这 5 天里课程加了屋顶、雾、随机卡组与示范起点格。

| 组 | 帧数 | Brier | AUC | 预测胜率 | 实际胜率 |
|---|---:|---:|---:|---:|---:|
| 全部 | 36096 | 0.314 | 0.631 | 0.558 | 0.721 |
| 白天 | 3648 | 0.119 | 0.865 | 0.710 | 0.724 |
| 夜间 | 5568 | 0.209 | 0.799 | 0.819 | 0.655 |
| 泳池 | 9792 | 0.210 | 0.720 | 0.746 | 0.671 |
| 雾 | 6720 | 0.240 | 0.812 | 0.464 | 0.695 |
| **屋顶** | 9792 | **0.566** | **0.495** | **0.261** | **0.812** |
| Boss | 576 | 0.912 | 0.635 | 0.017 | 0.944 |
| 倍率 2.0 | 10752 | 0.534 | 0.539 | 0.298 | 0.841 |
| 卡组见过 | 18240 | 0.237 | 0.652 | 0.759 | 0.742 |
| 卡组没见过 | 17856 | 0.392 | 0.626 | 0.352 | 0.700 |
| 示范起点格 | 12288 | 0.559 | 0.525 | 0.283 | 0.857 |
| 其中 GPT Pro（`*_llm`） | 2688 | 0.356 | 0.660 | 0.464 | 0.667 |

（AUC = 随机取一局赢的帧与一局输的帧，赢的那帧打分更高的概率；0.5 就是掷硬币。）

三点：

1. **白天仍然好**（预测 0.710 / 实际 0.724，AUC 0.865）。夜间、泳池、雾单调但被压缩：
   预测 0.4–0.6 的帧实际胜率 0.68–0.86，即叶值"不敢给高分"，但排序方向对（AUC 0.72–0.81）。
2. **屋顶是反的**：预测 0.0–0.1 的 5,274 帧实际赢了 80.1%；预测 0.9–1.0 的 986 帧实际赢 79.1%。
   AUC 0.495 —— 叶值对"这局会不会赢"完全没有区分力。Boss 更极端（预测 0.017 / 实际 0.944）。
   倍率 2.0 与示范起点格是同一形态（AUC 0.539 / 0.525），因为它们几乎都落在屋顶/雾/新卡组上。
3. **不是"整体偏保守"能解释的**：如果是常数偏移，AUC 不会掉到 0.5。同局内预测的标准差
   屋顶中位数 0.064（白天 0.134、雾 0.223），有波动，但波动与结果无关。

**机制**：v5 语料里没有屋顶、没有雾区大范围格子、没有随机卡组、没有起点格
（`MEMORY/docs/task78-value-v6.md` 已记录"v5 的训练语料里没有雾区和屋顶"）。
搜索只在"最优候选比学生选择高出 MARGIN=0.02"时才推翻学生；叶值在屋顶上没有区分力，
推翻率就塌了：task148 在 L42 d1 上量到 `overrides_per_game` 57.1（r29 学生），本次同种子同卡组只有 8.9–23.1；
task129 的两套屋顶卡组则恒在 0.0–0.4 —— 搜索一次都没推翻过学生。

**这不是"校准偏乐观/偏悲观"的旧问题**（DESIGN 里监测的那条），是**分布外**问题：
新地形/新卡组整片落在 v5 没见过、也没被标注过的区域里。

### 1b. 用最近数据快速重训，能不能修好？

同一编码、同一上下文，从 v5 热启动，只用第 30 轮以后 9,000 局的整局胜负（91,728 训练行，
3 epoch）。读帧+编码约 12 分钟、训练约 1 分钟，全程 13 分钟。按对局整局切分的留出集：

| 地形 | 留出行 | v5 Brier | 重训 Brier | v5 AUC | 重训 AUC |
|---|---:|---:|---:|---:|---:|
| 全部 | 16272 | 0.291 | **0.144** | 0.644 | **0.869** |
| 白天 | 1428 | 0.113 | 0.087 | 0.904 | 0.941 |
| 夜间 | 3456 | 0.208 | 0.172 | 0.735 | 0.816 |
| 泳池 | 4740 | 0.217 | 0.171 | 0.731 | 0.830 |
| 雾 | 2904 | 0.295 | 0.136 | 0.719 | 0.871 |

注意这只是整局标签的分布内校准，不等于决策级排序（见 §3 的上线门槛）。

### 2. 老师失败归因：真正卡住的是**续走深度**，不是价值网

设计：从 task129（2026-10-27，老师在这些卡组上 0–1/8）与 task148（屋顶 GPT Pro 卡组）里挑卡组，
**同种子配对**跑四臂，每格 8 局，四臂只改一处：

| 臂 | 与 base 的差别 |
|---|---|
| base | v5 叶值，horizon 2500，samples 3，per-card 1，student-candidates 2（= 生产参数） |
| value | 只换叶值网为 §1b 的重训网 |
| continuation | horizon 2500→4000，samples 3→5（续走更长、更多随机未来） |
| width | per-card 1→2，student-candidates 2→4（候选更宽） |

其余全部相同：verify-samples 9、margin 0.02、min-gap 300、同一学生（生产 r36）、
同一静态估值（value_branch1）、同一引擎（prodint16 build16）。种子用各卡组原实验的种子段
（task148 148001000+，task129 129000000+ 对应段），所以 base 臂可与原报告直接比。

| 关卡 | 地形 | base | value | continuation | width |
|---|---|---:|---:|---:|---:|
| L42 task148 d1 | 屋顶 | 1/8 | 1/8 | 1/8 | 1/8 |
| L24 d06 | 泳池 | 0/8 | 0/8 | 0/8 | **1/8** |
| L37 d04 | 雾 | 0/8 | 0/8 | 0/8 | 0/8 |
| L14 d02 | 夜间 | 0/8 | 0/8 | **4/8** | 1/8 |
| L42 d01 | 屋顶 | 0/8 | 0/8 | 0/8 | 0/8 |
| L48 d01 | 屋顶 | 0/8 | 0/8 | 0/8 | 0/8 |
| **合计** | | **1/48** | **1/48** | **5/48** | **3/48** |

（另有 L9 白天 6/8、L26 泳池两格没有进四臂：前者在 r36 下已经赢 6/8、没有提升空间；
后者与 L24 同地形，单格 8 局在满负载下要 20 分钟，跑到一半中止，未计入。）

顺带一个前提变化：**L9 这一格 base 已经 6/8，而 task129 当时是 1/8** —— 现在的学生（r36）比 r11 强得多，
"老师输"已经只发生在特定地形上。

逐格看，三种失败机制是不同的：

1. **屋顶两套（L42 d01 / L48 d01）根本不是搜索问题。** 四臂全部 0/8，`overrides_per_game` 恒为 0.0 / 0.4，
   终局在第 3.9 / 6.0 波 —— 老师的搜索连一次推翻都没有发生，局在开局就结束了。
   这类卡组（无便宜攻击手、经济起不来）在动作层怎么调都救不回来，正是 AGENTS §8 说的
   "先考虑换卡组，再考虑改策略"。换价值网、加深续走、加宽候选在这里全部无效。
2. **夜间 L14 是唯一一个"搜索才是瓶颈"的格子。** base 只推翻 5.6 次/局、10 秒就打到第 12 波：
   horizon 2500 在夜间这种长局上，叶子离终局太远，叶值又压缩在 0.5 附近，搜索几乎不敢推翻学生。
   把续走拉到 4000 tick / 5 个随机未来后，推翻升到 19.5 次/局，**0/8 → 4/8**。
3. **泳池 L24 / 雾 L37：换价值网让局变长，但没有变成胜局。** L24 的 value 臂把平均终局从
   16.1 波推到 25.9 波（推翻 24.9→44.6 次/局），仍然 0/8；width 臂拿到 1/8。
   L37 的 value 臂反而更短（17.2→10.2 波）。也就是说：§1b 那种"校准修好了"确实改变了搜索行为，
   但在这两格上改变的是"输得慢一点"，不是"赢"。

**直接回答任务书的问题**：在这批老师输掉的卡组上，
**换价值网一项都没有把败局变成胜局（1/48 → 1/48）**；
**续走深度最能把胜率拉起来（1/48 → 5/48，全部来自 L14）**；
候选宽度次之（1/48 → 3/48，L24、L14 各 +1）。
但这两项的收益都只在"局还能打到中后段"的格子上出现 —— 屋顶那两格连推翻都没发生过。

这与 §1 并不矛盾：价值网**确实**过时了（屋顶 AUC 0.495、预测 0.26 / 实际 0.81），
但"叶值没信号"和"叶值没信号导致输"是两件事。在搜索根本没有机会介入的局里，
修叶值不会赢；在搜索有机会但看得太短的局里，修续走立刻见效。

**统计口径**：每格 8 局、配对同种子，不做显著性宣称；四臂各 48 局（6 格 × 8），
continuation 相对 base 的净胜 +4（全部集中在 L14 一格），width 净胜 +2。
期间生产 qc 16 进程满载（load average 20+），单局耗时被拉长约 2 倍，但四臂同条件。

### 3. 建议：把价值网重训放进每一轮管线

**结论先说**：值得做，而且成本比想象低 —— 本次从零编码 9,000 局到训完 3 个 epoch 一共 13 分钟，
其中 GPU 只占 1–2 分钟。真正贵的是读帧，而帧本来就在盘上。

#### 3.1 数据来源

- **只用流水线自己的帧**：`~/pvz-logs/curriculum_state.pipeline/frames/<seed>/<label>_fast_search/`，
  每局 `meta.json` 里有 `outcome.won`。不新开采集，不碰生产状态。
- **滚动窗口，不是单轮**：建议最近 5 轮（约 3,800 局）。单轮 768 局只有约 9,200 行（每局 12 帧），
  太少；5 轮约 46,000 行，编码约 5 分钟。
- **标签粒度**：整局胜负足够修"分布外压平"（本次屋顶 AUC 0.48 → 0.92）。
  决策级标签（`value_ranking_check.py --dump`）贵得多，只对仍然全败的格子补
  （泳池 L24/L26 这类，v5 就是这么做的：64 个种子、约 1.5 万决策、1 天采集）。
- **隔离**：训练种子必须与当轮的挑选/门禁/记分板种子段不相交（照 `value_widen_audit.py` 的机械核对）。
  本次重训脚本按对局整局切训练/留出，留出集不含训练局的任何一帧。

#### 3.2 时长与资源（实测）

| 步骤 | 本次实测 | 每轮（5 轮窗口，约 46k 行）估计 |
|---|---|---|
| 读帧 + 编码 | 9,000 局 / 108k 行 / 4 线程 ≈ 12 min | ≈ 5 min |
| 训练 3 epoch | 91,728 行 / RTX 5080 ≈ 1–2 min | ≈ 1 min |
| 峰值内存 | 3.0 GB（编码）+ 约 1 GB（训练） | 同量级 |
| 峰值显存 | < 2 GB | 同量级 |

正好落在"学生训完、挑选与门禁只用 CPU"的那 1–1.5 小时里，不占学生训练的卡。
编码是 CPU 密集的：**不要用线程池**（GIL 会把 4 线程压成 1 核，本次实测 12 分钟里有 10 分钟在等它），
用 4–8 个进程；或者在采集写入时顺手把 v2 编码存进帧归档（`pvz_frame_store.encode_frames` 已经有这个位置，
只是现在只存 v1）。

#### 3.3 上线前怎么比较新旧价值网（三步，缺一不可）

1. **候选级排序（最重要）**：`scripts/value_ranking_check.py --values <old>,<new>`。
   它从真实局面枚举候选、每个候选推演到终局拿真值，报成对一致率与"选错候选损失的胜率"（regret）。
   本次的 Brier/AUC 只是整局标签的分布内校准，**不能替代**这一步 —— v5 当年在泳池
   Brier 0.000 却排序 0.500，就是这个坑。
   要求：屋顶 / 雾 / 未见卡组上新网不低于旧网，白天、夜间、泳池非劣。
2. **同种子配对实战**：`scripts/value_widen_ab.py`（v4→v5 用的那套），
   每区 32 对、只有叶值网换臂；沿用 v5 的采纳线：净胜 ≥ −2 且配对检验不显著变差。
3. **本轮帧上的校准回归**：`scripts/task154_calibrate.py --value <new>`，
   按地形看 Brier 与 AUC，确认没有把白天从 0.865 拖下去。

三步都过才换；换的时候照 v5 的做法**在组边界切换**，旧网留作回滚。

#### 3.4 顺带建议

- **叶值网之外还有一个更便宜的修法**：屋顶/开局格的失败率里有一部分与叶值无关（见 §2）。
  如果 §2 显示"换叶值网也拉不动"，那就该先修卡组/起点，而不是继续调搜索参数（AGENTS §8 第 1 条）。
- **编码**：v5 用的是编码 v2，没有 v3–v5 的蹦极/睡眠/可见计时通道。重训时先别换编码，
  一次只改一件事；换编码是 v6 的议题。

### 4.4 切换脚本（已写好，**未执行**）

`scripts/task154_switch_value.py`，三个动作：

    python3 scripts/task154_switch_value.py status     # 当前默认网 sha、上次切换记录、队列是否在组边界
    python3 scripts/task154_switch_value.py switch --candidate artifacts/value_net/v6/model.pt
    python3 scripts/task154_switch_value.py rollback   # 一条命令回滚

- 生产默认是 `curriculum_queue.py` 的 `DEFAULT_VALUE`（`artifacts/value_net/v5/model.pt`），队列启动时
  解析一次，所以切换=**原子替换那个文件**：先复制到 `model.pt.bak-<UTC>` 并校验 sha256，
  再经 `.incoming` 临时文件 `os.replace`；回滚按 `switch_state.json` 记录的 sha 恢复并复核。
- **组边界门禁**：读队列自己的 `curriculum_state.json`，当前轮还有 `status != done` 的组就拒绝执行
  （`--force` 只给紧急回滚用）。现在这一轮已全 done，脚本报告 `collecting: false`。
- 脚本**不重启队列**：替换后由主控在下一次重启时生效，所以运行中的那一轮不会半途换网。
- 只写 `artifacts/value_net/`，不碰 qc、看门狗、生产状态文件。
