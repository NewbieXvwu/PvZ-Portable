# task154：价值网是否已经过时 + 老师在陌生卡组上输在哪

分支 `vstale`，基于 `origin/prodint16`。在台式机做（数据在台式机），只读生产数据，不改生产。

## 背景

- 老师 = 搜索：候选由学生给出，续走用学生，叶子用价值网打分。
- 生产叶子价值网 `artifacts/value_net/v5/model.pt`（`scripts/curriculum_queue.py` 的 `DEFAULT_VALUE`）自 10-24 起没换过；静态估值 `artifacts/hard/value_branch1` 更早。v5 训练时课程还没有屋顶、雾夜大范围格子、随机卡组格子（task137），也没有 GPT Pro 的卡组；学生已从 r11 换到 r36。
- DESIGN 写的是“每一轮都用搜索实际走到的局面重训价值网络，并监测它对选中叶子是否持续偏乐观”，生产里没做。
- task129（`origin/deckrules` 595e943b）：老师在 54 套 v5 卡组上只赢 63/432。task148：GPT Pro 屋顶胜利卡组上老师 5/112。

## 要回答的问题

1. **价值网校准**：用最近几轮 qc 采集的对局（`~/pvz-logs/curriculum_state.pipeline/frames` 下，每局有终局输赢），在局中若干时刻用 v5 打分，按地形、倍率、卡组是否在 v5 训练期出现过、是否 GPT Pro 起点格来分组，报告预测胜率与实际胜率的偏差（校准曲线、Brier、排序一致率）。重点看屋顶、雾、随机卡组格子。
2. **老师失败归因**：从 task129 / task148 里老师输的卡组挑 6–8 套，每套少量种子，做单变量替换：
   - 价值网：v5 vs 在这些地形上用最近数据快速重训的价值网（只用于本诊断）；
   - 续走：现行学生 vs 更长 / 更多续走；
   - 候选宽度：现行 vs 加宽。
   看哪一项最能把胜率拉起来。局数以能看出方向为准，不追求显著性。
3. **建议**：如果价值网明显过时，给出把价值网重训放进每轮管线的方案。参考：每轮学生训完后的挑选 + 门禁阶段只用 CPU，显卡约空 1–1.5 小时，可以用来训价值网。写清数据来源、时长、上线前怎么比较新旧价值网（复用 `scripts/value_ranking_check.py`）。

## 约束

- 台式机是生产机：先看 `free -g`；对局最多 2 个游戏进程，用 systemd 用户服务加内存上限（参照 task105 的 MemoryHigh / MemoryMax），Nice=10；GPU 只在生产训练没在跑时用。
- 不改 qc、看门狗、生产状态文件、生产配方；不 `pkill -f` 任何含 `curriculum_queue` 的模式。
- 测试只跑 `-k`，`ulimit -v 8000000`。不加自校验。
