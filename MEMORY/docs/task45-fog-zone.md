## 主控追加 B（2026-10-23 21:00，用户问"模型能否理解开雾的因果链"后补）
现行设计有三个缺口：学生只看当前一帧（外加上一动作与 tick 间隔两个标量），**没有记忆**；老师搜索从引擎**真状态**出发，**知道雾里有什么**；价值网也看真状态。第一阶段先把这三点量清楚，不急着改模型：

1. **推演里的学生必须看屏蔽后的观测**。C++ 续走里学生前向用的观测，要与正式对局同一套雾屏蔽。只有这样，"开雾以后学生打得更好"才会体现在推演胜率里，老师才会给路灯花 / 三叶草打出价值。加单测：雾关里续走学生的输入与 Python 侧屏蔽后的观测逐位相同。
2. **量老师的"特权信息"差距**：老师的候选、推演起点和叶值都是真状态，它不需要光也能下对。按学生的信息量看，它的标签里会有"无从推断"的部分（比如往一条看不见僵尸的行补坚果）。
   - 报告：不透视观测下，学生模仿老师的一致率比透视时降多少；有多少老师推翻发生在"相关行被雾遮住"的局面。
   - 若差距大，第二阶段要做**信息集搜索**：老师从"与学生所见一致"的多个状态出发推演，雾里的僵尸按可见信息重采样。现在先只量，不做。
3. **记忆实验**（为第二阶段做准备，本阶段只做最小对照）：三叶草吹散后雾会回来，回雾后"刚才看到的那些僵尸"就从观测里消失了。无记忆的学生只能靠先验猜，无法知道"它们还在那儿"。
   - 对照：同一份数据训两个学生，一个现结构；一个在输入里加最近 K 帧（如 K=4、间隔 ~60 tick）的僵尸通道堆叠。
   - 堆叠是通用的短期记忆，不是手写特征；**不要写"上次看见的僵尸位置"这类手工推断**。
   - 在不透视的雾关面板上比胜率和"回雾后行为"（被雾遮住的行有没有继续补防）。若堆叠明显有用，再考虑 GRU 之类真正的循环记忆（用户 10-20 讨论过，排在干扰测量之后）。
4. 第 3 条的训练如果占用超过 2 小时的 GPU 或 10 GiB 内存，先写"问题"等主控排期，与 task36 / task43 的训练错开。
