## 4. 学生输入里关于卡牌的特征

当前学生（`packet_head=identity`，round_000057 配方）每张卡只有**运行时状态**，没有静态属性：

- 每槽 4 维：`[卡牌 id, 可用(active), 冷却进度, 当前买得起]`，见 `python/pvz_rollout_policy.py:32-51`（`packet_features`）。
  - `cost` 只用来算“买得起”布尔（`frame['sun'] >= cost`），**费用数值本身不输入**。
  - `refresh` 只做冷却归一化分母，**冷却/充能数值本身不输入**。
- 卡牌 id 进 `nn.Embedding(54)`（`python/pvz_rollout_policy.py:111`）；出牌头把“全局特征 + 卡嵌入 + active/冷却/买得起”拼起来打分（`:171-182`），落点卷积也用同一卡嵌入（`:184-191`）。
- 棋盘上每格是**植物 id 的 one-hot 通道 × 血量比例**（`python/pvz_value_net.py:24,81-84`）；全局标量里每张卡两维“已就绪 / 冷却进度”（`python/pvz_value_net.py:100-113`）。这些同样只有身份索引与运行时状态。
- **没有**：伤害、射程/弹道类型（`launch`）、是否为蘑菇、是否需要睡莲/花盆、升级底座、最大血量、卡片冷却/费用数值、卡组整体费用曲线。
- 静态元数据其实存在：`scripts/pvz_constants.py:264-280`（`plant_defs` 的 cost/recharge/launch）、`:441-491`（睡莲 16、花盆 33、升级植物 40–47 及 `Plant::IsUpgrade`）；种植底座与升级规则由引擎在 `src/Lawn/Board.cpp:2774-2890` 执行，升级植物所有权在 `python/pvz_env.py:189-206` 校验。这些都没有进入学生输入。

含义：少见卡的嵌入只能靠“这张卡自己出现过的样本”学；没有费用/射程/底座等先验，模型无法从“常见卡”迁移到“陌生卡”，只能从“陌生卡组”的整局示范里学。要提升陌生卡组泛化，加静态卡牌特征是结构性改动；补示范只能补被覆盖的 `地形 × 卡` 组合。

## 5. 方向建议

1. **优先补三叶草示范**：日/夜/池三地形，生产卡组占比 0.02%–4.5%，GPT 胜局 60%–77%。这最像“有人会用、我们没学到”。
2. **屋顶补控制/经济体系**：玉米投手、南瓜头、火爆辣椒、寒冰射手、寒冰菇、双发/火炬/机枪。生产屋顶只有 32 套卡组，GPT 55 套。
3. **泳池补南瓜头、香蒲、杨桃、双子日**：生产泳池只有 24 套卡组，南瓜头全池只种过 5 次、香蒲 4 次。
4. **雾补“卡组里有但不种”的卡**：高坚果（3.2 次/千行）、寒冰射手、樱桃、魅惑、香蒲、玉米、西瓜、寒冰菇；其中樱桃/寒冰射手在 GPT 胜局占 48% / 26%，生产种下率仅 1.5 / 1.8 次/千行。
5. **不要按任务书的举例补数据**：雾的大喷菇/窝瓜/缠绕并不稀少，夜的小喷菇是核心；真正该修的是高坚果、双发（有卡不种）和墓碑吞噬者（生产种、GPT 不靠）。
6. 若目标是“陌生卡牌”而不只是“陌生卡组”，需要给学生加静态卡牌属性（费用、冷却、伤害/射程、蘑菇、底座需求、升级关系）；只补示范解决不了没见过的卡。
