主控 2026-10-29 定。只读审查，Mac 上做。

审查两个即将进入 deploy16 的分支相对各自基底的改动：
- `origin/sysfail`：基底 `origin/prodint`，task149 游戏进程全线崩溃时暂停采集；
- `origin/obstimer`：基底 `origin/obsup2`，task145/147 v2timer 输入与 C++ 第 9 号输入版本。

重点看：
1. 正确性 bug。例如暂停后能否恢复；探测局会不会被当成训练数据或计入胜率；v2timer 的 Python 与 C++ 编码在边界情况下是否一致（雾、传送带空槽、植物被吃掉的那一帧、升级植物）；缓存复用视图在父缓存被清理后的行为。
2. 会不会拖慢关键路径（AGENTS §6.5）。
3. 对生产的影响：旧特征版本、旧缓存签名是否真的不变。

发现真实 bug 就直接在对应分支上修，只跑相关 `-k` 测试，遵守 §6.5 第 8 条（`timeout 300`、`ulimit -f 2000000`、同时只开一个 pytest），提交并推送。只是风格问题的不改。结论写在本文件末尾，推送到 `pvz-env`。

## 审查结论（2026-10-28）

审查起点为 `sysfail` 的 `7285d1a2`（相对 `prodint/e2f8cc16`）和 `obstimer` 的 `4f243a98`（相对 `obsup2/8d18b4e5`）。发现两处真实缺陷，均已修复并推送到原分支。

### P1：生产面板没有种子，暂停后无法自动恢复

`GameHealth.probe()` 直接将晋升源面板传给 `search_play`。生产 `gate_v5_panel.json` 的任务没有 `seeds` 字段，种子由正式门禁另行分配，而 `search_play.main()` 直接读取任务的 `seeds`。因此系统库恢复后，探测仍会在启动游戏前失败，队列持续暂停。已有探测测试替换了整个命令生成函数，未覆盖真实面板的数据结构。

修复提交 `bc8ea702` 已推送 `sysfail`。探测在自己的临时目录生成只含原任务与单个种子的清单，再调用现有命令生成路径。源面板保持原样，探测结果及帧仍写入临时目录，不更新采集偏移或胜率，也不进入训练。新增用例使用生产面板结构与真实 `command_for()`，覆盖缺少种子时的恢复路径。

### P2：计时缓存的祖先被清理后，打包会失败

`v2timer` 可指向 `v2sleep`，后者又可通过零填充视图指向 `v2`。计时缓存命中只检查直接父文件是否存在，首次派生也直接读取父视图。删除 `v2` 祖先并保留其余两个文件后，已有计时缓存仍被判为可用，读取时抛出 `FileNotFoundError`。没有已有计时缓存时，首次派生同样会失败，无法进入原有完整编码路径。

修复提交 `745f146f` 已推送 `obstimer`。计时缓存命中复用现有读取器解析父引用，派生时将缺失或失效的父视图交还给既有完整编码路径处理。这里只打开引用链的元数据，没有解压完整棋盘数组，没有新增全量扫描或文件哈希。回归用例分别覆盖已有计时缓存和首次派生，删除祖先后都生成独立缓存，全部数组与完整编码结果一致。

### 编码边界、旧版本与关键路径

静态核对 Python 与 C++ 的计时状态表及归一化运算，未发现其余编码差异。雾中植物的公开倒计时为 -1，Python 写零，C++ 跳过同一植物。传送带按公开槽位索引编码，空槽负类型跳过，就绪条件均为 active 且冷却为 0。玉米炮升级植物使用相同的 `(47, 35) → 500` 状态满值。植物死亡或被压扁时，公开 v2 植物列表与 C++ 计时遍历使用相同的 `mDead/mSquished` 排除条件，因此同帧不会额外保留已删除植物的计时。

旧观测分支的特征计算和 C++ 版本 1–8 的通道数保持原行为。v1 的基础函数与参与指纹的数值常量未变，旧版本冻结签名保留，v2sleep 新增冻结项保持其原签名。v2timer 追加 4 个通道，使用独立缓存空间，未把新增通道塞入旧缓存。

健康状态下，采集与后台任务不会运行恢复探测。系统故障暂停时，前后台共用一个串行单局探针，探测等待符合 task149 的恢复要求。计时缓存派生只编码新增 4 个通道，完整编码仅用于缺少有效父缓存的档案。未发现新加的启动全量重放或阻塞式全库自检。

### 定向验证与交付

三次 pytest 串行执行，均使用绝对路径、`-k`、`timeout 300` 与 `ulimit -f 2000000`，单次耗时均不足 1 秒：sysfail 探测及暂停恢复相关 13 passed，计时缓存及旧签名相关 5 passed（另含 2 个祖先删除场景子测试），计时输入及导出相关 7 passed。4 个 C++ 原生对拍用例因当前审查工作树缺少独立引擎而跳过，本次没有重新编译或运行真实引擎对拍，其边界实现按上述路径静态核对。

两个修复均附对应回归测试，只修改实际缺陷。未部署，未连接台式机生产，未修改生产模型或状态文件。
