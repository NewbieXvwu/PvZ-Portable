## 为什么
- 雾夜泳池 L31–34 冷启动时，老师 0/384、学生 0/256 全败，没有任何胜局可学（task45）。
- 用户 10-24 用 `demo_fog_31_fume` 打通了 L31：20 波，874 个动作，含 22 次铲子。task63 修好引擎的确定性后，`demo_fog_31_fume_rebaselined` 已经 `verified: true`。
- 计划（Salimans & Chen 2018）：从示范中途的局面开始，让老师接手打完。
  - 示范越往后，剩下的路越短，老师越可能赢。
  - 找出"老师能接住的最早位置"，那里就是课程的起点，然后往前推。

## 要做的
1. **准备**：
   - 用户的局 `export` 成训练帧（标签来源 human）。
   - 老师、学生、静态网与 qc 生产保持一致：学生 dw4i_s1；静态网 branch1；叶值 **v5**（HF `transfer/value_v5.pt`，SHA 前缀 8a636d33，取回后核对）。
   - 引擎用本工作树刚修过确定性的构建。
2. **接手扫描**：
   - 在示范的决策序列上等距取约 12 个点，按 tick 覆盖整局：开局、第 1 面旗前后、中盘、最后两波前。
   - 每个点用 `search_play.py --demo-archive <rebaselined 绝对路径> --demo-decision N` 恢复局面，让老师打完。用 8 个不同的未来种子：恢复后的随机流要有变化，看工具是否支持；不支持就写清楚，只跑一个未来。
   - 记录每局：胜负、末波、丢车。
   - 同样的点再让**学生**（dagger-beta 0，只有学生）各打 8 局，作对照。
3. **报告**：
   - 画出"接手位置 → 老师胜率 / 学生胜率"曲线，用表格即可，标出老师胜率越过 50% 的最早位置。
   - 输局按原因分类：哪一波、什么僵尸破防、当时场上有什么。
   - 特别看两点：
     - 示范里用户铲掉小喷菇换强植物的那些时刻，老师接手后会不会照做；
     - 老师在哪些局面开始掉链子。
   - 结论写 `MEMORY/docs/demo-start-states.md`，提交并 `git push origin demo`。**是否把这些起点接进 qc 课程由主控定。**
