# task48：人类示范录制——用户亲手打的对局变成可重放、可训练、可当起点的数据

> 主控 2026-10-23 22:25（台式机时间）写。执行者：Mac 上的 Codex（Business 账号，tmux `codex-demo`）。工作树 `/Users/newbiexvwu/PvZAgent/.claude/worktrees/demo`（分支 `demo`，从 pvz-env 拉出，主控已建好）。
> Mac 上有泳池采集（10 worker）与 task47（`codex-mac`，构建优化）在跑：编译 `-j4`，最多 2 个游戏进程。

## 为什么
- 雾区（31–40）冷启动全败，强对策型僵尸（小丑、橄榄球、气球、海豚；屋顶的蹦极、投石车）靠随机碰撞学不会。用户愿意亲手示范，但只能打**几局到十几局**，不可能几万局。
- 所以示范的主要用途**不是**让学生直接模仿几百个动作，而是两件事：
  1. **当起点**：参考 Salimans & Chen 2018，用一局示范学会《蒙特祖玛的复仇》。从示范对局里的状态重开，让搜索老师从"已经布好局"的局面接着打，再逐步往前推（反向课程）。一局示范能提供几百个起点。
  2. **当先验**：示范动作进老师的候选集，并在训练里以小权重混入。对错仍由模拟推演裁决。
- 这两种用法都要求示范是**本引擎里逐 tick 确定可重放**的对局。

## 要做的
1. **能玩**：
   - 用本仓库的 GUI 构建（不是无头）让用户在 Mac 上正常打一关；
   - 关卡、卡组、倍率由任务清单指定，与我们的任务族一致（如 `artifacts/stage4` 里 fog 族的 L31 任务，AGENTS §8）；
   - 卡组由任务给定，不让用户在选卡界面改；要改卡组就新开任务族。
2. **能录**：
   - 录下每个动作：种植 / 铲子 / 收集阳光等用户实际操作的 tick、类型、格子；
   - 存成与现有存档同格式的动作带，`scripts/episode_query.py` 的 whatif / 重放能直接读；
   - 一局一个目录，含 meta：任务 id、种子、卡组、引擎 SHA、`label_source: human`。
3. **能重放**：无头引擎按动作带重放，逐帧与录制时的状态一致（终局波数 / 胜负 / 每 tick 状态哈希）。这是硬门禁；不一致就是确定性有漏洞，先修。
   - 注意 GUI 与无头的差别：收集阳光等 GUI 行为在无头环境里怎么表示，按引擎现有的环境动作口径。
4. **能转训练数据**：
   - 把示范局转成 `frames_v2` 的 npz 格式（`pvz_frame_store`），动作标签来源标 `human`，与老师标签区分；
   - 训练器要能按来源设权重。只加配方字段，不加开关。
5. **能当起点**：
   - 给出"从示范局第 N 个决策的状态开始一局"的入口：快照 / 恢复通道已有，见 whatif；
   - 让 `search_play.py` 能从这样的起点跑老师局，用于之后的反向课程实验。
6. **给用户的说明**：`MEMORY/docs/human-demo.md` 一页，写清：
   - 怎么启动、打哪一关、打完存在哪；
   - 打一局大约多久；
   - 卡组是什么、为什么不能改。
   - 用中文，面向不懂代码的人。
7. 测试：
   - 录 → 重放 → 转 npz 的端到端单测，用无头引擎模拟一串动作代替真人；
   - `python3 -m pytest python -q -p no:cacheprovider` 与合并前比不多出失败。

## 规则
- 只用绝对路径；不 `cd` 进别的工作树。
- 引擎若要改（录制钩子），非录制路径逐帧不变：4 个存档整局重放 0 差异。
- 禁止 `git add -f`；`.pt` `.npz` `.log` 和示范局原始数据不进 git（示范局走 HF `transfer/`）；不写字面密钥；不手写打法规则。
- 每完成一小步就提交、`git push origin demo`，在"结果"记一行。疑问写"问题"，按最佳判断继续。

## 主控追加 A（2026-10-23 22:35，用户提议）：同一关用不同卡组、不同解法各打几局
用户提出：对同一种威胁会用不同对策示范。比如对气球，可以用仙人掌、三叶草，二周目还能用香蒲。主控采纳，示范数据的价值很大程度上就在这种多样性：
- 当起点时，局面覆盖更广；
- 当候选先验时，搜索能看到"对策集合"，按局面自己挑；
- 学生的动作头是对"卡 × 格"的分类分布，能同时容纳几种解法，不会像回归那样把两种打法平均成四不像。

对工具的要求：
1. **每局的卡组来自一个已登记的任务族**（AGENTS §8 第 4 条）。同一关可以有多套示范卡组，用 `demo_<区>_<关>_<变体>` 这样的族名，在 DESIGN 登记。
   - 卡组只从引擎读到的已解锁植物里选：我们跑的是二周目进度，香蒲已有。
   - 过引擎整组检查。
   - 不手写"必须带 X"，是否有用由之后的实测判断。
2. **示范计划表**：在 `MEMORY/docs/human-demo.md` 里给用户一张表，列出每局打哪关、用哪套卡组、本局想示范的解法（如"气球：仙人掌"）。
   - 初版按雾区 L31–L34 的僵尸名单出（见 task45 的僵尸表：小丑、橄榄球、气球、海豚），每关 2–3 套卡组 × 1 局。
   - 主控审后给用户。
3. **每局可选一句备注**：用户可以写"这局试的是 X"，存进 meta 的 `note` 字段，供 LLM 教师和之后的分析用，不进训练输入。
4. 示范不要求故意打得怪，按用户自然的打法赢下来即可；同一局里保持一种思路。
