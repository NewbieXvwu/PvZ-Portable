## 2. Q2：老师（带搜索）在这些任务上的胜率

### 2.1 先纠正一个数据源

`curriculum.log` 的格子记录（`round N <label> <task> mult=... games=... wins=... rate=... beta=...`）是**学生采集**的胜率，不是老师：代码里 `item.update(..., student=str(args.rollout_policy))`，β=0 的组直接进学生窗口，β>0 的组进 `mixed`，不进学生窗口。日志里 1400 组 β=0、358 组 β=0.5，没有 β=1 的纯老师组。因此“从 curriculum.log 的格子记录里找老师胜率”这个前提不成立。

老师胜率的真实来源是：

- `MEMORY/docs/task115-teacher-arm-weak-levels.md`（2026-10-27，r11 学生 / v5 叶值 / branch1 静态网，Mac 引擎，每关 16 种子，带搜索）；
- `MEMORY/docs/task120-teacher-blind-spot.md`（气球关生产卡组，16 种子）；
- `MEMORY/docs/task102-roof-teacher-equals-student.md`（屋顶 L42 逐决策诊断）；

需要说明的是，门禁把 holdout 只当监控、不否决（`decision.json` 的 `monitor_note`：“heldout cells are reported, never vetoed and never counted in the overall rate”），所以 r52 在 holdout1 上 −64.6pp 仍然 `approved=True`。这是评测重做要处理的另一个事实：**留出监控目前只报告、不拦截**。

## 4. Q4：门禁的“现任”与组边界提交检查

### 4.1 门禁取的是开评时的当前现任，不是入队快照

代码路径（`scripts/curriculum_queue.py`）：

| 位置 | 内容 |
|---|---|
| `1185-1187` | `def incumbent(self): with self.lock: return Path(self.args.rollout_policy)` |
| `1193-1197` | `evaluation_contract(job)` 调用 `promotion_contract(Path(job['model']), self.incumbent(), ...)` |
| `1214` | `_evaluate(job)` 一开始就 `frozen = self.evaluation_contract(job)` |
| `1220` | 把 `--incumbent frozen['incumbent']` 传给 `promotion_gate.py` |
| `1201-1213` | `_seeded(job)` 只分配 `seed_block`；job 里没有 incumbent 字段 |
| `1111-1114` | 启动时 `if state.get('student'): args.rollout_policy = Path(state['student'])` |
| `1832-1840` | 轮询时若 `promotion['contract'] != current_contract`，重新排队并对当前学生重评 |

`scripts/promotion_gate.py:50-55` 的 `contract()` 会把 `incumbent` 和 `seed_block` 写进冻结契约，所以**契约内部是可复现的**；但 incumbent 的取值来自 `args.rollout_policy`，而它在运行期会被激活改写。因此：**入队时不快照，开评时读当前现任**。如果开评时现任已经是新的，门禁就对比新的；如果开评后现任又变了，`1832-1840` 的 stale 检查会让它重评。

### 4.2 组边界检查为什么不覆盖“学生激活已写入状态”

`scripts/deploy17_boundary.py:53-58`：

```python
def committed_boundary(log,state):
    event,label=last_group_event(log)
    if event!='finished': return False
    # rc is logged BEFORE completed_groups is saved. Only accept its durable label.
    return b'"label": '+json.dumps(label).encode() in state.read_bytes()
```

它只做两件事：确认最后一条组事件是 finished，并确认该组的 `"label": ...` 已经出现在状态文件字节里。它**不读 `student` / `student_round`，也不验证激活写入**。

而“组标签落盘”和“学生激活落盘”是两次独立的写：

| 写入 | 位置 | 执行者 |
|---|---|---|
| 组完成：`completed_groups.append(...)` + `save_state` | `curriculum_queue.py:2168-2169` | 采集主线程 |
| 学生激活：更新 `student`/`student_round` + `save_state` | `curriculum_queue.py:1852-1859` | 后台训练/门禁线程 |

激活的两次字段更新在 `self.lock` 内，但 `save_state` 在锁外；它和采集线程的 `save_state` 是两个独立的“写临时文件 + replace”。因此存在这样的窗口：组标签已经 durable，激活还没 durable（或激活的写被后一次旧状态 replace 覆盖）。

r52 的时间线正好落在这个窗口里：

| 时间 | 事件 | 来源 |
|---|---|---|
| 09:03:09 | `student activated at group boundary: round 52 .../round_000052/student/model.pt` | `curriculum.log:4892` |
| 09:14:39 | `background round 52 superseded by round 54; training and gate skipped` | `curriculum.log:4896` |
| 14:11:24 | `background round 54 evaluate started against .../round_000036/student/model.pt` | `curriculum.log:5096` |
| 现在 | `curriculum_state.json` 的 `student_round` 仍是 36 | 状态文件 |

task179 的记录是：“09:03:09 r52 在组边界被激活，同一秒压缩流程停掉了控制器，状态文件没来得及写。” 也就是激活日志已经打印，但激活的 `save_state` 没有变成 durable 状态；重启后 `1111-1114` 从 `state['student']` 恢复，回到 r36。`committed_boundary` 只看到 r52 的组标签已经落盘，于是认为边界已提交；它没有理由去检查 `student_round` 是否等于 52。

**修复方向（对应 task179 §3.8，本次只记录，不改代码）：**

1. 激活必须和组标签在同一个提交点上：要么先写 `student`/`student_round` 再允许 `committed_boundary` 通过，要么把“激活已落盘”纳入 `committed_boundary` 的断言（检查 `student_round >= 最后通过门禁的 round`）。
2. 激活的 `save_state` 应在 `self.lock` 内完成，或使用与采集线程同一把写锁，避免“旧状态 replace 覆盖新状态”。
3. 重启后如果 `state['student']` 对应的 round 小于某个已通过门禁的 job，应把该 job 标成“激活未提交”，重新激活而不是静默回到旧学生。
