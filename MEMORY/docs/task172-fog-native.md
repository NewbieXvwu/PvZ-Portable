# task172：雾关接入原生对局路径

基于 `origin/deploy18`（e60a951d），分支 `fognative`。任务依据为 `origin/fogspeed:MEMORY/docs/task166c-fog-profile.md`。本分支准备供 deploy19 默认启用，只提交代码与结论，不部署。

## 范围

门禁与学生挑选的纯学生对局复用现有 `env.rollout(None, 0)` 整局 C++ 路径。雾诊断改为按需启用，消除它对整局路径的阻挡。保留显式关闭开关，供主控做一次 45 种子 A/B。

采集复用 deploy18 已有 `ROLLOUT_PREDICT` 原生 CNN 根前向，搜索续走也沿用既有 C++ 实现。根节点的历史推进方式参考 task161 的接入，逐帧标签、DAgger 实际动作与 obs-v3 附件继续由原来的 Python 搜索循环写入。没有合法种植动作时直接等待，不增加跨进程预测请求。obs-v3 网络根前向继续走现有 Python 实现，观察器也保留其原路径。

这里接入的是“纯学生整局 + 搜索采集原生根前向”。搜索老师整局编排仍在 Python，deploy18 与 task161 都没有现成 C++ 整局搜索接口。本次没有移植整套搜索老师或给纯学生新增整局写帧协议。

## 开关与部署接线

`search_play.py`、`curriculum_queue.py`、`promotion_gate.py`、`select_student.py` 的 `--native-games` 默认打开，安装本分支四个脚本后供 deploy19 使用。课程控制器将同一个开关传给采集、挑选和晋升门禁，单独运行三个下游入口也沿用相同默认值。此改动复用既有引擎协议，不要求新二进制。

`--no-native-games` 关闭采集原生根前向，并恢复雾关逐决策诊断及 Python 前向。白天与夜间原本已经走的无帧原生整局路径保持。`search_play.py --fog-diagnostics` 显式打开逐决策雾诊断，会使用逐决策对局循环。存档输出没有增加字段或中间文件。

## 计时与交付

Mac 顺序跑雾、夜、白天的少量同任务同种子对局，比较切换前后的每局耗时。计算进程不超过 4，其他 Agent 的审计与地形训练保持原状。不新增校验、manifest 或 JSON 中间文件。已有 Python/C++ 前向的近似并列差异由主控上线前的一次 A/B 判断，本任务不增加常驻检查。

## 结论

实现已分两步推送：`0a55f776` 接通门禁/挑选的整局开关，`f3299e51` 接通采集原生 CNN 根前向。没有运行门禁质量 A/B，没有添加校验、清单或 JSON 中间文件。

计时尚未完成。Mac 当前有 Qoder 标签审计的 Python 与引擎，加一个地形训练进程。按严格的 4 个操作系统计算进程上限，计时所需的 Python 与引擎需等待地形训练队列自然结束，已顺序排队。计时沿用现有 r36 门禁任务定义与模型，雾 L31/L32/L36、夜 L12、白天 L7 各取前 4 种子，逐种子交替先后顺序，对比开关前后。使用同一引擎 `build-fogspeed/pvz-portable`，引擎已有优化在两侧保持相同。结果只落 CSV 和文本日志，不生成新的任务清单。
