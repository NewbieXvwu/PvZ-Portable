# task177：先抬教师——54 套陌生卡组面板复测与加深续走

分支 `teacherdecks`，基于 `deploy19`（`8eb35d86`）。Mac 上跑，最多 4 个老师游戏进程。
`bench_handoff` 轮询照旧在后台跑（`scripts/bench_handoff.py`，本任务未触碰）。

## 背景与要做的

task175 的 P0：老师本身不行，扩采只会把“怎么输”教给学生。task129 冻结了 54 套 v5 卡组
（9 关 × 6 套，每套 8 局、独立种子），当时的搜索老师只赢 63/432（14.58%）。
现在学生已从 r11 换到 r36，引擎从 sleepinput build 换到 deploy19，先要：

1. 用当前老师（搜索 + 生产续走网络 r36、v5 叶值、branch1 静态估值、deploy19 引擎）
   在**同一面板、同样种子**上重测，按卡组报胜局数。
2. 同一面板、同样种子，再测一个“加深续走”的老师变体（task154 里把夜间 L14 从 0/8 拉到 4/8 的开关：
   `--horizon 2500→4000 --samples 3→5`），看整体胜率能涨多少。
3. 列出老师零胜的卡组：这些卡组扩采只会教学生输。

## 结论（2026-10-30）

1. **现行老师仍是 14% 量级。** 用 r36 续走 + deploy19 引擎复测，62/432（14.35%），
   与 task129 的 63/432（14.58%）持平。老师在这批随机 v5 卡组上的总胜率对续走学生
   r11→r36 不敏感，换学生只重排了个别卡组的胜负。
2. **加深续走是唯一一个“全卡组不退化”的便宜提升。** horizon 2500→4000、samples 3→5，
   在 54 套里**没有任何一套低于 base**，总量 62→84（+22 局、+5.1pp、相对 +35%），
   老师计算量约 2.5×。收益集中在白天 L7（+7）与夜间 L14（+7，与 task154 的“续走是夜间瓶颈”
   一致），雾 +3、泳池 +4，屋顶 0。
3. **但加深续走救不了结构性零胜。** 零胜卡组只从 43 降到 39：54 套里有 39 套两臂全 0。
   这些格子局在 3–6 波就结束、搜索几乎不推翻学生（屋顶 12 套推翻 0.0–0.4 次/局、
   1–4 秒内终局、终局波 4–6），属于卡组×地形结构性输局（AGENTS §8：先换卡组再改策略），
   不是搜索参数能修的。task154 的四臂（换叶值 / 加深续走 / 加宽候选）在屋顶同样全部 0/8，
   这次用 r36 与全面板复核，方向一致。
4. **对“先抬教师”的直接含义。**
   - 现在按 task129 的随机 v5 卡组扩采，其中 39/54 的格子只会教学生输；扩采前应先把这些
     卡组从采集任务里剔除或重做，否则新数据只是在示范失败。
   - 可立刻采用的一步是老师加深续走：同样卡组上多拿 35% 的胜局，且没有负向卡组；
     代价是 2.5× 老师 CPU。按地形看，白天/夜间收益最大、屋顶零收益，可按地形分配预算。
   - 结构性零胜的根因分两类：屋顶 12 套（L42/L48）老师连一次推翻都没有、开局经济/出伤起不来，
