# 射手落点 vs 僵尸位置：错配率分析（2026-10-13）

**数据**：`artifacts/episode_samples/` 的 348 局逐步回放（116 seed × 3 检查点）
**方法**：复用仓库自己的 `scripts/render_episode.py::_reachable_dps()` —— 它的判据是
**"射手所在列 >= 最前僵尸所在列 → 打不到"**（植物朝右打、僵尸从右往左走）。
**统计**：局级置换检验 20 万次（同一局内的多个决策不是独立样本，所以按局聚合）。
**脚本**：`/tmp/lane2.py` `lane4.py` `lane5.py`（台式机）

---

## 一、结论

**它输的时候，不是"火力总数不够"，而是"火力放在了打不到僵尸的地方"，而且"有路正在裸奔承压时，它不往那儿补"。**

三个指标全部 **p < 0.0001**，且**在 initial / v3_1m / bc_seq32 三个检查点里各自复现**。

## 二、三个指标

### 指标 A：无条件「种在僵尸身后」（该行有僵尸，但射手种在僵尸右边或同列 → 一炮打不出）

| | 赢局 | 非赢局 | 差 | p |
|---|---|---|---|---|
| 射手种植中"身后"占比（局级均值）| **0.537** | **0.719** | −0.182 | **< 1e-5** |

（合并计数：赢 2666/5013 = 53.2%；非赢 3103/4502 = 68.9%）

### ★ 指标 B：条件概率 —— **当"别的路正在裸奔承压"时，它把射手种在身后的比例**

| | 赢局 | 非赢局 | 差 | p |
|---|---|---|---|---|
| P(种在身后 \| 别的路裸) | **0.485** | **0.789** | **−0.304** | **< 1e-5** |

**分检查点复核：**

| 检查点 | 赢 | 非赢 | p |
|---|---|---|---|
| initial | 0.490 | 0.818 | < 1e-5 |
| v3_1m | 0.549 | 0.742 | 0.00013 |
| bc_seq32_100k | 0.440 | 0.827 | < 1e-5 |

**★ 这里有个非平凡的细节**（不是"输局什么都差"那么简单）：

| | 无条件 A | 条件 B（别的路裸时）| 方向 |
|---|---|---|---|
| **赢局** | 0.537 | **0.485** | **压力下反而更少种在身后** ↓ |
| **非赢局** | 0.719 | **0.789** | **压力下反而更多种在身后** ↑ |

**→ 赢局在"有路裸奔"时会改变行为（往有效位置种）；输局不会，它照旧往打不到的地方种。**

## 三、抽查（确认指标不是算错）

seed_30003（**赢局**）tick=14400 / wave=8 / sun=125：
- 第 0 行**只有一只僵尸，x=380 → 正好在 c4 格里**
- 它种了一个豌豆射手到 **(行0, 列4)** —— **种在僵尸脚下**
- 该行已有射手在 c2、c3（这两株能打到它），**新种的这株一炮都打不出**

→ 指标判"身后"是对的。这类动作在赢局里也大量存在（只是不致命）。

| 来源 | 方法 | 结论 |

| **本分析** | 348 局逐步回放 + 局级置换检验 | "承压裸路"和"种在僵尸身后"的差异 **p<1e-5，三组复现** |

## 五、边界（还没证实的部分）

1. **仍是观察关联，不是因果。** "承压裸路"本身也是"要输"的一个几乎同义的症状
   （没火力打到僵尸 → 僵尸吃掉东西 → 输）。指标 C 的因果方向**无法从观测数据判定**。
   → **必须做定向干预**：在"某路裸奔承压"的那一刻，**强制把射手种在那条路上、且列 < 最前僵尸列**。
2. **指标 B 已经比 C 更接近"决策"层面**（它问的是"面对裸路，资源投哪儿"），
   但仍受"输局本来就有更多裸路"的影响。**上面那个"压力下方向反转"的对照缓解了这一点**，
   但不能替代干预。
3. **为什么之前的 I2g/I3g 干预失败**：它们只是"往火力最薄的行种射手"，
   **没有约束"种在僵尸前面"**。如果落点仍然在僵尸身后或同列，那株射手照样打不出伤害。
   **→ 这可能就是 I2g/I3g 剂量低且效果不显著的真正原因之一。**
