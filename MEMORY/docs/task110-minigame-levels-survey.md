背景：

逐关回答：

### 共用接口与边界

四关均已有冒险模式分支，判定集中在 `src/LawnApp.cpp:3474`（L5）、`:3501`（L25）、`:3506`（L35）和 `:3525`（L45）。本任务目标是冒险关，无须先新增可任意切换 `GameMode` 的通用系统。对应独立模式名分别为 `GAMEMODE_CHALLENGE_WALLNUT_BOWLING`、`GAMEMODE_CHALLENGE_LITTLE_TROUBLE`、`GAMEMODE_SCARY_POTTER_*` 与 `GAMEMODE_CHALLENGE_BUNGEE_BLITZ`，冒险关通过各 `Is*Level()` 判定复用玩法。

`RESET_V2` 当前限定二周目，在 `EnvironmentReset()` 中设置 `GAMEMODE_ADVENTURE`，调用 `Board::InitLevel()` 后通常把任务牌组写回种子栏。`conveyor_start='original'` 跳过覆盖，仅允许引擎本来就有传送带的关卡（`src/LawnApp.cpp:1329`、`:1398`、`:1407`、`:1423`）。`Board::HasConveyorBeltSeedBank()` 包含 L5/L25/L45，**不含 L35**（`src/Lawn/Board.cpp:8578`）。因此前三关可使用空牌组与原生开局，砸罐子不能套用该参数。重置随后确实走 `StartPlaying()` → `Board::StartLevel()` → `Challenge::StartLevel()`，原生保龄球首张坚果也会加入，相关入口在 `src/LawnApp.cpp:1456`、`:407` 与 `src/Lawn/Board.cpp:1644`。

现有执行器接受 `plant/shovel/wait/collect`，搜索分支编码只接受 `P/S/W`（`python/pvz_env.py:546`、`src/main.cpp:456`、`:498`）。`collect` 只处理阳光和金钱，不能拿起罐子掉出的植物卡（`src/main.cpp:480`）。生产老师从 `legal_actions.plants` 取候选，经静态网挑格，再做学生续走与叶值比较（`scripts/search_play.py:326`）。学生目前输出种植/等待、牌与格子，C++ 续走也只枚举合法种植（`python/pvz_rollout_policy.py:78`、`:194`、`src/EnvironmentRollout.cpp:635`）。L5/L25/L45 可以沿用这些动作头，L35 需要把新增交互贯穿执行、搜索与学习标签。

`SNAPSHOT/RESTORE` 保存棋盘与随机状态，`RESEED` 重抽尚未开始的波次，再切换局内随机流（`src/main.cpp:174`、`:258`、`:436`）。这个机制可复用于三种传送带关，已出现在盘面上的状态保持不变。砸罐子有额外的信息边界问题，见下文。

### L45：补原生任务与可见落点表示

**引擎与隐藏状态。** `IsBungeeBlitzLevel()` 将冒险 L45 纳入蹦极闪电战（`src/LawnApp.cpp:3525`）。牌表为花盆(33)、食人花(6)、南瓜(30)、樱桃(2)，权重 50/25/15/10（`src/Lawn/Challenge.cpp:1812`）。旗帜波加入五只蹦极，普通波中的其他僵尸由蹦极运送，见 `src/Lawn/Board.cpp:639`、`:4920`。

**落点由游戏选定，玩家只负责种植与防守。** 普通偷植物目标由 `Zombie::PickBungeeZombieTarget()` 抽取并写入 `mTargetCol` 与 `mRow`，有植物的合法格权重更高（`src/Lawn/Zombie.cpp:1085`）。空投运送走另一条路径：`Board::SetupBungeeDrop()` 枚举第 4–8 列、五行，再由 `BungeeDropZombie()` 抽取落点（`src/Lawn/Board.cpp:4784`）。所以无需新增“控制蹦极落点”的玩家动作。隐藏状态包括尚未发生的目标抽取、下降/抓取计数，以及运送僵尸和被抓植物的关联。已显现的下降、抓取和上升动作可以作为可见状态编码。

**环境缺口。** 原生传送带和免费种植可直接复用，任务需要空牌组及 `conveyor_start='original'`。屋顶花盆合法性继续交给 `CanPlantAt()`，不改牌表或手写应对规则。完整观测已有僵尸 `phase/target_col` 和植物 `bungee_state`（`src/LawnApp.cpp:2373`、`:2391`），但 `target_row` 不能直接当成蹦极行，目标选择写的是 `mRow`。完整观测也没有蹦极高度 `mAltitude` 和运送关系，现有字段无法完整区分下降、运送和偷取画面。

可见落点还需服从绘制条件：`Zombie::DrawBungeeTarget()` 对非在场、正在上升、受击以及关联运送僵尸等情况不画红靶，Boss 关也跳过（`src/Lawn/Zombie.cpp:5582`）。接入时只输出画面已给出的目标/空投信息与可见阶段，不能把所有内部关联和精确计时直接公开。

**老师与学生。** 动作头和合法候选类型保持种植/等待。实际缺口在状态表示：`_frame()` 丢掉上述目标与植物抓取状态，`v2_extra()` 也未编码普通蹦极目标/高度（`scripts/render_episode.py:146`，`python/pvz_student_observation.py:24`）。需把可见目标格、阶段与被抓植物状态贯穿完整/精简观测、紧凑帧、Python/C++ 学生及价值输入。沿现有输入版本机制新增兼容表示，旧检查点维度保持原样。叶值继续学胜负，使用原生 L45 的分叉样本重训，静态挑格网也需要该关数据。仅给 JSON 增加字段，旧网络仍看不到它们。

**示范、第一步与估计。** task85b/c 已确认的“点传送带牌→种植→回放”路径适用于本关动作。当前示范清单没有 L45，屋顶旧实验的固定初始牌也不能充当原生示范，区别见 `MEMORY/docs/task46-roof-zone.md:143`、`:268`。先登记原生任务并打通一次短录制，约 0.5 人日。补齐可见状态与双端输入、接上新数据，完整增量约 2–3 人日。这里没有原生 L45 新测胜率。

### L5：已有投掷动作，主要缺滚球表示

**引擎与隐藏状态。** `IsWallnutBowlingLevel()` 匹配冒险 L5（`src/LawnApp.cpp:3474`）。原生传送带十槽，开始时加入一颗坚果，后续普通坚果(3)与爆炸坚果(49)按 85/15 权重发牌（`src/Lawn/Board.cpp:8593`，`src/Lawn/Challenge.cpp:478`、`:1778`）。初始坚果属于 `StartLevel()` 的行为，因此原生 L5 的 reset 响应不应照搬 L25 的“十槽全空”断言。当前环境固定二周目，也不会包含首次冒险教学分支的预置豌豆，见 `src/Lawn/Challenge.cpp:378`。

**投掷可直接用 `plant(packet,col,row)`。** 合法落点只允许第 0–2 列（`Challenge::CanPlantAt()`，`src/Lawn/Challenge.cpp:2456`），`EnvironmentPlant()` 在格中心调用游戏自己的 `MouseDownWithPlant()`（`src/LawnApp.cpp:1481`）。选球、起始行、起始列与出手时机均可由现有动作表达。球的水平运动由动画轨道速度驱动，首次撞击后的上下转向包含游戏随机选择，后续转向和边界反弹也在 `Plant::UpdateBowling()` 中完成（`src/Lawn/Plant.cpp:2372`、`:2493`）。没有独立的玩家“向上/向下发射”参数。

爆炸坚果编号 49 已在模型容量内：Python 的植物种类宽度为 54，C++ 同样按 54 类处理，身份牌头和训练标签可保留该牌（`python/pvz_value_net.py:24`，`python/pvz_rollout_policy.py:48`，`src/EnvironmentRollout.cpp:165`，`scripts/pack_training_rows.py:241`）。Python 固定牌组校验拒绝编号 49（`python/pvz_env.py:476`），不影响空牌组原生开局后由引擎发出它，不应为了本关放宽全部固定牌组约束。

**环境、老师与学生缺口。** 当前植物观测输出 `mPlantCol/mRow/state`，没有运动中的 `mX/mY`（`src/LawnApp.cpp:2373`）。滚球横向移动后仍以出生列进入普通植物特征，跨行时真实纵坐标也无法恢复。紧凑帧只留格坐标，`v2_extra()` 对状态的使用集中于土豆雷和灰烬植物，没有滚球方向（`scripts/render_episode.py:146`，`python/pvz_student_observation.py:49`）。完整接入需要可见球体位置、当前运动方向与保龄模式标记，贯穿帧和 Python/C++ 学生/价值输入。内部碰撞随机数与尚未发生的转向保持隐藏。

动作头可保持原样，候选仍枚举合法投掷格。现有静态网把坚果当作格子里的静止植物打分，尚未学会保龄球物理，因此要用本关分叉数据重训挑格与叶值，不能把普通草地上的坚果价值直接视为投掷价值。搜索续走本身已经调用真实引擎，可继续复用快照、分支和 `RESEED`，无需另写保龄球模拟器。

**示范、第一步与估计。** `HumanInput::Poll()` 的选牌与格子点击会产出同一个 `plant` 动作，所以可以沿用现有录制和种植标签路径，出手时间由等待记录保留（`src/main.cpp:382`）。球随后自行滚动不影响投掷标签的可表达性。当前清单没有 L5 录制任务，也未找到现成示范证据。第一步约 0.5–1 人日，登记原生牌带任务并录制短投掷片段。完整滚球观测、双端编码和本关数据接通约 3–5 人日，无须新增方向动作头。

### L35：交互、信息边界与三阶段都要接通

**引擎与隐藏状态。** `IsScaryPotterLevel()` 匹配冒险 L35，背景特判为夜间草地，原生阳光为 0、种子栏只有一张樱桃，罐子由 `ScaryPotterPopulate()` 布置（`src/LawnApp.cpp:3506`，`src/Lawn/Board.cpp:874`、`:1355`、`:1506`）。冒险专属三阶段分别布置 15/20/25 个罐子，含绿色叶子罐等可见类别提示，第三阶段结束才完成全关（`src/Lawn/Challenge.cpp:3805`，`src/Lawn/Board.cpp:5146`）。这关没有常规传送带。

每个罐子的实际内容在布置时就写入 `mScaryPotType/mSeedType/mZombieType`，阳光数量也可能预先抽好（`src/Lawn/Challenge.cpp:3735`）。玩家应只见外观类别与实际可见的内容。路灯花造成的透明效果由 `GridItem::UpdateScaryPot()` 和 `DrawScaryPot()` 处理（`src/Lawn/GridItem.cpp:506`、`:314`），只有确实显示内部时才能公开对应内容。

**环境缺口有四项。**

1. **原生开局。** L35 不接受 `conveyor_start='original'`，默认 reset 又会覆盖单槽樱桃。现有底层校验允许单张牌配六槽 profile，因而可显式用 `[2]` 加 `seed_slot_count=6` 表达单樱桃栏，不能调用会返回一槽 profile 的 `profile_for_deck([2])`（`python/pvz_env.py:192`、`:445`、`:474`，`src/LawnApp.cpp:1423`）。任务装载和录制配置必须保留原生阳光及单槽语义，禁止塞入常规六/十卡。保留原生特殊栏也可做成窄范围支持，无需建设任意小游戏重置系统。
2. **敲罐与掉卡。** 原生点击走 `Challenge::MouseDown()` → `ScaryPotterMalletPot()`，动画完成后才开罐（`src/Lawn/Challenge.cpp:1351`、`:4034`、`:4056`）。现有 `shovel` 会先要求格内有植物，无法替代敲罐（`src/LawnApp.cpp:1504`）。开罐可能产生 `COIN_USABLE_SEED_PACKET`，它需切换到 `CURSOR_TYPE_PLANT_FROM_USABLE_COIN`，种下后消耗对应掉落物（`src/Lawn/Challenge.cpp:4127`，`src/Lawn/Coin.cpp:1250`，`src/Lawn/Board.cpp:3858`）。现有 `collect` 不支持这种卡，普通 `plant` 也只读种子栏。需新增敲罐、使用掉落卡的明确动作与合法候选，并保留锤击忙碌状态和掉落卡可用期。
3. **可见观测。** 当前完整 `grid_items` 无条件输出 `zombie_type/seed_type`，直接泄露未开的罐子（`src/LawnApp.cpp:2447`）。精简观测及紧凑帧又只保留位置和物件种类，丢掉外观类别提示（`src/LawnApp.cpp:2105`，`scripts/render_episode.py:179`）。硬币观测仅有类型和坐标，缺掉落卡植物身份、可引用标识与剩余可用状态（`src/LawnApp.cpp:2413`）。需要统一安全的可见罐子/掉落卡表示，并将其传给学生和价值网，完整观测不能充当当前可用的安全替代品。

**老师、学生与叶值。** 敲罐动作可用现有格子索引，但需要新的动作类别。掉落卡的选择和种植需要区分种子栏槽位与掉落卡来源。`branch_action_token`、C++ 分支解码、学生 Python/C++ 续走、存档重放与训练打包均要能表达这些动作。老师增加可敲罐和可用掉落卡候选，叶值输入增加可见罐子类别、掉落卡、阶段与交互状态，使用相同隐藏信息采样口径生成分叉数据。叶值目标仍为整关胜负，不引入手写“先敲哪只罐”的价值公式。
