**已确认的事实（不用再验）**：

1. **前 5 波，赢的和输的一模一样**（向日葵 ~10、火力 ~1/行、钱刚好花光）。**分水岭在第 5~8 波。**

3. **被吃植物的列分布**：赢局死在前排 c4-c5（46~50%）；**输局死在最后排 c0-c1（43~49%）——那是向日葵区**。
   （向日葵 98% 在 c0-c1；攻击植物 100% 在 c2-c5；c6-c8 从不种。）
4. **同一波时，输局少 0.5~1.1 个火力/行**；赢局在 w20 后把 c2-c5 填满（~3.95/行 = 20 个），输局从没填满。
5. **阳光余额（同一波）**：赢局 w20 ≈ 950；输局 ≈ 325（末波死的是 w20 575 → w29 175）。
6. **它从不升级**：赢局被吃的植物里寒冰 11~14%、双发 7~12%；**输局只有 1.5~3%**。
7. **输局累计种向日葵 25.6 个 vs 赢局 13.3 个，但结束时都只剩 ~10 个** → 反复补种、反复被吃。

**根因假设（本次要验证的就是它）**：
> **它对"防线被突破"的响应方式错了** —— 向日葵被吃就去补向日葵（恢复收入），
> 而不是"把钱全砸到前排、先把防线做厚"。于是陷入死亡螺旋。

⚠️ **样本有偏**：这 116 个种子按 v3_1m 失败簇抽的。**组内"赢 vs 非赢"对比可用**；
**"v3 变好还是变差"不可用**。

## 2. 轨道 A（★ 最高优先级）：**干预实验 —— 把因果钉死**

**问题**：观测数据只能说明"输局防线薄 + 向日葵被吃"，**不能说明这是原因还是结果**。
**唯一办法：在输局上做干预 —— 强制它在关键时点改做"正确"的事，看能不能救回来。**

### A0 先做两个**必做的前置校验**（不做完不许往下走）

1. **`whatif` / `render_episode` 能不能逐位复现原轨迹？**
   **已知缺陷**：`scripts/render_episode.py:436` —— 走 `prefix_actions` 时**不推进 GRU 记忆**
   （`ppo_state["hidden"]` 只在 `_ppo_action()` 内更新），前缀结束后策略会**冷启动**接手。
   **校验方法**：把"干预动作"换成**原动作**，看能不能复现原轨迹。
   **采样策略还要恢复动作随机数状态**才可能逐位一致。
   → **如果无法复现，干预实验的解释力就受限，必须在报告里写明。**
2. **`episode_query.py:742 _run_variant()` 不回传 `preplanted`**（`task_extra` 只有 `wave_cap` 和
   `zombie_count_multiplier`）→ 对**有预种植物的援助关**做 whatif 会从**空棋盘**开始。
   **本任务用的是 `train_full_level7_v1_d1`（第 7 关完整关）**，先确认它有没有预种植物；
   **有的话这个干预实验作废，要在报告里说清楚。**

### A1 ★ 核心实验：**"补火力"干预**

**选局**：`artifacts/episode_samples/` 里 **`v3_1m` 组、结局为"早死/中死"** 的局，
挑 **10~15 局**（`frames.jsonl` 里有完整动作序列，能定位每一步）。

**干预点**：**该局第一次有后排植物（列 ≤1）被吃掉的那一帧**（本机脚本已能算出这个位置）。

**干预内容**（三组，各自独立跑）：
| 组 | 干预 | 目的 |
|---|---|---|
| **I1** | 在被突破的**那一行**、**c4 或 c5** 强制种一个豌豆（若钱够） | 能不能堵住 |
| **I2** | 接下来 10 个决策**全部强制种豌豆**（往火力最薄的行） | 够不够翻盘 |
| **I3** | 接下来 10 个决策**全部强制种向日葵** | **反向对照**：证明"补向日葵"救不了 |
| **I0** | **不做任何干预**（只跑一遍） | **基线：确认能复现原结局** |

**统计**：每组各多少局最终**通关**（或推进波数变化多少）。
**判据**：**I1/I2 显著优于 I0 → 假设成立**（响应方式错了）；
**I2 和 I3 一样差 → 假设不成立**（问题不在响应方式）。

**产出**：**"在第一次被突破时改种火力，能不能救回来"** 的一句话 + 数字 + 显著性。

### A2 若 A1 判定"救不回来"，做第二个干预：**"提前加固"**
干预点改成**更早**（例如第 5 波开始时，强制把火力最薄的 2 行补到 2 个），
看能不能避免第一次被突破。**如果提前加固也没用 → 说明问题在更上游（比如它压根没识别到危险）。**

### A3 便宜的补充（纯读数据，随时可做）
- **"有钱却不种"检验重做**：本机那版判据太宽（98~99% 的"机会"在赢局也放弃）。
  **把判据收紧**：只在"**至少两行火力 <2**"或"**刚被突破之后的下 5 个决策**"里统计，
  看赢局和输局的"错失率"有没有差别。
- **末波死专项**：它 w20 有 575 阳光、w25 只剩 250、w29 只剩 175。
  **逐帧列出这 3 段的每一笔花费**，回答"**钱花在哪了**"。
