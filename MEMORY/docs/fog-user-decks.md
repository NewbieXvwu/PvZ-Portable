## 结论（一句话）

**L31 是卡组问题，L32–L34 不是。** 同一个老师、同一关、只换一张卡（路灯花 25 → 寒冰射手 5），
L31 冷启动从 **1/32 变成 25/32**（78.1%，95% CI 61–89%，配对 McNemar p < 1e-6）。
其余 7 个用户卡组族在 32 个种子上都是 0–9.4%，与对照卡组（每关 0/32）没有显著差异 ——
L32 的瓶颈是前期经济，L33/L34 的瓶颈是防空（气球僵尸）。

**建议**：把 `demo_fog_31_snow`（1.0 倍）接进 qc 课程，作为雾夜第一个冷启动起点；
L32–L34 不接，改用 task64 的示范起点做倒推课程。接不接由主控定。

## 7. task67b：4.3 株路灯花是谁种的（2026-10-24 重跑）

**问题**：两株路灯花就能照亮整片雾，为什么 `fog_user_l31_fume` 每局平均种 4.3 株，
而且带路灯花的卡组整局种植量只有 snow 卡组的 1/4？

**做法**：demo 工作树，生产参数原样（`--arms fast_search --dagger-beta 1 --verify-samples 9
--student-candidates 2 --workers 4`），只加两个只读诊断：`--frames`（逐决策帧，含 `targets`
全候选叶值与实际执行动作）和 `--leaf-probe`（每个被搜索的决策一行：学生首选 `policy`
与最终 `chosen`）。种子 20261101–04，fume 与 snow 各 4 局，共 8 局、4 个进程。档案在
`artifacts/task67b/`（本地，不入 git）。下文 tick 为游戏内 tick，决策号从 0 起。

### 7.1 路灯花的来源：86% 是学生自己种的

4 局共种下 **21 株**路灯花：**18 株是学生自己的动作**（决策里学生首选就是 packet 9，
老师搜索后原样通过），2 株是老师推翻学生"等待"后补种（seed 20261101 d932 tick 51129 →
(1,7)；seed 20261104 d341 tick 19339 → (0,3)），1 株是老师把学生选的路灯花挪到别的格
（seed 20261101 d692：学生 (0,4) → 老师 (4,5)）。反向也数了：学生一共提出 **25 次**
路灯花，18 次照做、1 次换格、5 次被换成别的植物、1 次被换成等待。

四局的第一株都出现在 tick 2040–2220，正好是路灯花卡（refresh 2000）解冻的第一时间 ——
学生不是"顺手种"，是**一解锁就种**。

### 7.2 存活、被吃与重种

- 同时存活最多：seed 20261101 **4 株**，其余三局各 2 株。21 株里 18 株被吃、3 株活到终局。
- 寿命中位数 **3210 tick**（均值 6980，最短 420，最长 33394）。
- 同格重种只有 2 次：(4,5) seed1、(4,2) seed3 —— 重种不是 4.3 株的主要来源，
  主要是"换格子再种"。
- 落点：第 0 路 9 株（平均活 6.6k tick）、第 4 路 7 株（3.8k）、第 1 路 3 株（17.0k）、
  第 2/3 路各 1 株；列 5 共 6 株、列 2 共 4 株、列 3/4 各 3 株。前排那 7 株最先被吃。

### 7.3 学生的首选动作分布

| | fume（2925 决策） | snow（3656 决策） |
|---|---|---|
| 等待 | 2814（96.2%） | 3399（93.0%） |
| 种植意图合计 | 111 | 257 |
| 小喷菇 / 阳光菇 / 大喷菇 / 睡莲 | 28 / 9 / 0 / 7 | 33 / 63 / 28 / 25 |
| 高坚果 / 窝瓜 / 缠绕海草 / 坚果 / 樱桃 | 0 / 23 / 19 / 0 / 0 | 6 / 53 / 41 / 6 / 2 |
| 路灯花 / 寒冰射手 | 25 / — | — / 0 |

- 路灯花可种（合法）的决策 702 个，学生选了 **25 次（3.6%）**；阳光菇可种 1112 次，
  只选 **9 次（0.8%）**。两者同时可种的 607 个决策里 **路灯花 24 : 阳光菇 3**。
- **不是"路灯花冷却逼出等待"**：同一阳光区间下，路灯花可种与冷却时的种植率几乎一样
  （阳光 25–49：6.0% vs 6.2%；50–74：16.3% vs 23.8%）。等待率在 snow 卡组上同样是 93–98%。
  路灯花改变的是**种什么**：阳光 25–49 且路灯花可种时，33 次种植意图里 22 次是路灯花（67%）。
- 整局大量等待是这个学生本来的行为（snow 上也一样），不是被路灯花卡住；带路灯花时它把
  **25 阳光的那一手**从阳光菇换成了路灯花。

### 7.4 老师的叶值：为什么很少推翻

- 556 次搜索里 **182 次**候选集里有路灯花。路灯花候选叶值均值 **0.1365**，同期最强
  非路灯花候选 **0.1907**（差 −0.0542，中位 −0.0154）；路灯花只在 **19/182（10.4%）**
  是全场最优，另有 21 次与最强非路灯花打平。
- 这 19 次里，路灯花相对**学生自己那一手**的领先中位数只有 **0.0088**，只有 3 次超过 0.02
  —— 其余 **16 次被 0.02 门槛挡住**，老师不推翻。
- 超过 0.02 的 6 次进入 `--verify-samples 9` 复核，**3 次通过、3 次被 9 个新未来否掉**：
  d512 0.0345 → −0.002、d604 0.0310 → 0.018、d851 0.098 → −0.077。通过的 3 次正是上面
  2 株补种 + 1 次换格。全场 143 次复核里 93 次最终推翻。

**结论**：路灯花本身不贵（25 阳光）、也不难种（一解冻就种），问题是**它顶掉了阳光菇** ——
学生把每局唯一稳定的 25 阳光经济动作换成了不产阳光的灯。经济掉到 1/4，付得起的动作变少，
种植量 167 vs 377，0/4 vs 3/4。老师那边因为叶值差通常不到 0.02（9 个未来复核还会把它抹平），
基本不会把这一手改回来。task67 的 32 局结论（1/32 vs 25/32）在方向上是同一件事。

**对课程的含义**：fume 卡组的问题不是"老师不会用路灯花"，而是"学生把路灯花当成了阳光菇"。
在学生在含路灯花的数据上训练过之前，不建议给这个卡组单独开族；要用 L31 的雾夜课程，
继续用 `fog_user_l31_snow`（task68 已接入）。

## 问题

   数值不可逐位比较。

   反过来 L31 snow 的区间下界 61% 仍远高于 50%，这一条结论是稳的。
3. **只测了 1.0 倍。** L31 snow 在 2.0 倍（`demo_fog_31_snow_m200`）下没测；
