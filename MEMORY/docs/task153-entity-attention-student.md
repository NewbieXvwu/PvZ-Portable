## 历史：这条路以前走过一半（先读）

- PPO 时期的策略 π 就是 token + 关系注意力 + GRU（`GameplayModelV1`，790 万参数，带 kind-pair / 行差 / 列差 / 同格偏置），代码已于 10-19 删除，tag `pre-cleanup-20261019` 可取回。
- `learn/05-fast-rollout-policy.md`、`learn/06-expert-iteration.md`：在 L7 固定卡组上，约 50 万参数、没有记忆的小 CNN 模仿 π 上场 56/64，π 是 58/64，速度快 4.7 倍。从零模仿“π + 搜索”的 CNN 学生 974/1024，π 是 937。结论是“在 L7 上那套大架构多余，瓶颈在训练信号”。
- 当时的代价（`MEMORY/2026-10-02.md`、`2026-10-14.md`）：完整关卡 token 数中位 121、最多 150，注意力按 token² 涨；Python 逐行组装 token 约 3.3 ms/行。
- π 的失败不在架构：PPO 线输在环境胜利判定 bug 和一次改太多；蒸馏失败是因为在 π 原参数上微调。
- 所以 L7 的旧证据不能回答本任务的问题。本任务只关心旧证据没覆盖的情况：**没见过的卡组**，以及空间关系类关卡（L5 保龄球、屋顶、蹦极）。

## 主控补充（10-29 用户追问后）

- **对照必须有等参数量的宽 CNN 臂**：现行 64 宽 CNN、加宽到与新架构参数量相当的 CNN（如 128 宽）、新架构，三臂同数据同轮数。新架构只有赢了宽 CNN 才算“结构”带来的收益，否则只是参数多。10-22 task23 的 128 宽同语料已显示容量能补回一部分。
- 指标按“训练见过的卡组 / 没见过的卡组”和地形分开报告，不只报总体。
- **速度的首选方案是角色拆分**：老师根节点出手、生成候选，用新架构；续走里的上千次前向仍用现行 CNN（AlphaGo 的策略网络 / 快速走子分工；计划里“出手学生与续走学生拆开”）。这样续走速度完全不变。C++ 前向只需支持根节点调用频率；先量一局里根节点调用次数与续走调用次数的比例。

## 要做的

1. **调查**：现行学生到底看到了什么（格子通道、标量、卡包特征、identity 头），引擎帧 dict 里还有什么没用上（僵尸精确 x/y、状态、投射物、滚动坚果、计时）。只放玩家在画面上看得到的东西。
2. **Python 实现**：配方字段（如 `arch: "entity_attn"`），默认不变，旧配方、旧检查点、旧打包结果逐位不变。
   - 个体 token：卡包、植物、僵尸、投射物等，类型嵌入 + 精确坐标 + 状态；注意力编码（建议 width 64–128、2–3 层，带行差 / 列差相对偏置），与现有格子分支并存，汇入现有的动作头与辅助头。
   - 训练、打包、热启动路径都要能跑通；旧格子分支能否作为初始化，由你判断。
   - **不手写轨迹特征**（例如算出坚果会经过哪些格子），物理推演交给老师搜索。
3. **C++ 前向**：新导出格式 `PVZRN007`，`EnvironmentRollout.cpp` 实现 CPU 前向；用几帧做 Python/C++ 对拍。
   - 推演是采集的热点：报告每次决策的 C++ 耗时，与 PVZRN006 对比。如果太慢，说明瓶颈和可选的瘦身方案（层数、宽度、token 上限）。
   - 不用 LLM 的稀疏注意力（NSA / DSA / MoBA 等）：它们针对上万到百万 token，DSA 每个 query 选 2048 个，比我们整局的 token 数（约 150）还多。在 n≈150、batch=1、CPU 的条件下，耗时主要在投影和 FFN（随 n 线性），QKᵀ 只占约三成。有效的瘦身手段是：只做实体 token（格子交给现有卷积分支）、按行局部注意力加少量全局 token、潜变量瓶颈（Perceiver 式）、减宽减层、int8。
4. **小规模对照（有真实信号才算数）**：
   - 可以从台式机只读拷一小份训练帧（≤ 500 MB，`ssh … wsl -d Ubuntu -e cat`，约 0.5 MB/s）。不碰台式机生产进程、状态文件、看门狗，不在台式机训练或跑测试。
   - 在 Mac（MPS/CPU）上用同一份数据分别训练现行架构和新架构，比较留出行的动作准确率；有余力就按卡组拆开看：训练里见过的卡组 vs 没见过的。
   - 这是方向判断，不是最终结论；最终由生产的 A/B 槽位和门禁决定。
5. **配方草稿**：`recipes/dw4i2_v2timer_entity.json`（基于 deploy16 的 A 配方 `recipes/dw4i2_v2timer.json`），以后可以放进生产的 alternate-recipe 槽位，跟现行架构同轮竞争。

## 调查与实现（2026-10-29）

现行输入为 92 个基础格子通道与 115 个标量，v2timer 追加 25 个通道和 9 个标量。僵尸按 80 像素落格，v2 已带格内位置范围、速度及可见动作进度。deploy16 的 identity 头按植物种类对称汇总卡包，评分和格子动作共用植物嵌入，已经消除了卡槽顺序依赖。实体分支要检验的剩余收益是精确个体关系。

帧存档保留僵尸精确 x、速度和投射物 x，植物主要只有行列。完整观测中的像素 y、部分动画状态及滚动坚果的位置尚未进入这些旧存档。本次仅利用已记录的公开字段，缺失字段保留标记，不构造轨迹或未来信息。

已实现可选 `arch: entity_attn`：保留格子主干与身份动作头，加入类型嵌入、公开实体坐标及状态的投影，接两层 64 维单头注意力，使用可学习的行距/列距分数。实体上限为卡包 10、植物 54、僵尸 40 和投射物 24，共 128 个，池化后加到原有标量上下文。旧配方、旧检查点和旧训练包的默认路径保持不变，实体训练包使用独立架构标识。格子模型热启动时将新增输出投影置零，保留初始动作函数。

训练、打包和检查点载入已接通。alternate-recipe 允许架构不同，分别打包并保留对方的训练包。配方草稿为 `recipes/dw4i2_v2timer_entity.json`。实体原生导出当前明确拒绝，草稿不能直接用于生产候选晋升。相关 Python 测试 5 项通过。

## 三臂小规模对照

使用 Mac 本地 `artifacts/hard_mac/frames` 的 d7/d8/d9/d10 扰动卡组真实搜索示范。标签内的实际卡组随种子变化，因此从每份 `meta.task.deck` 读取卡组，排序后按完整多重集划分。共取 152 局，压缩原始帧 17,798,386 字节：96 局训练，24 局作为见过卡组的新对局留出，32 局作为完全未见卡组留出。训练覆盖 23 个不同卡组，未见集覆盖另外 32 个卡组。每关选 6 个卡组组别，每组 4 局训练、1 局留出，跨关卡有一个重复卡组。所有样本均为白天草地 L7–L10，不含泳池、屋顶或保龄球。

三臂共用一次编码得到的相同监督行，共 37,699 行，其中训练 24,322 行，见过卡组留出 6,072 行，未见卡组留出 7,305 行。使用 v2timer 输入，旧存档缺少的新增计时字段沿用既有编码默认值。全部从零训练，随机种子 1，12 轮，批量 128，MPS，AdamW 初始学习率 0.002、余弦下降。监督损失统一为种植/等待加权二元交叉熵，加种植行的卡包和格子交叉熵。等待保留率 0.1，反向加权 10；本次不启用软目标或辅助损失。每轮训练行顺序相同。

“完整动作”要求等待/种植正确，种植时卡包和格子也同时正确，按等待抽样权重还原。“种植动作”仅统计老师种植行，要求出手、卡包与格子同时正确。卡包准确率和格子准确率均在老师种植行统计，格子头以真实卡包为条件，与现有训练器一致。

## 根节点与续走调用比例

用已有 CNN `identity_dw3_s1` 测量完整 L7 对局，任务 `day_l7_train_d7p`，种子 1844175，卡组 `[0,2,17,5,1,35,4]`。沿用搜索设置：horizon=2500，samples=3，student-candidates=2，verify-samples=9，min-gap=300，sim-skip=61。任务从现有 `day_panel_identity.json` 读取。该局获胜，950 次游戏决策、174 次搜索、3,225 条续走，耗时 30.0 s。

根节点实际网络前向 882 次，其中出手 708 次、候选生成 174 次。没有合法种植动作的决策直接返回等待，不算网络前向。续走实际网络前向 116,190 次，比例为 **1 : 131.73**，根节点占全部前向 **0.753%**。续走决策共 139,138 次，同样不能直接当成网络调用次数。续走网络耗时 7.045 s，平均每次前向约 60.63 μs，这是现行 CNN 的观测值。

已有 C++ `NetworkCalls()` 计数原先只随完整 `ROLLOUT` 响应输出，搜索使用的精简 `ROLLOUT_VALUE` 响应缺少它。本次仅为精简响应补出同一计数，测量脚本包装根节点 `encode` 累计实际次数，不改变搜索决策。结果支持根节点与续走分工的速度判断，但本次实体准确率未达到推进条件。
