## 背景

- 现行学生（`python/pvz_rollout_policy.py` 的 `RolloutNet`，导出 `PVZRN006`，C++ 前向在 `src/EnvironmentRollout.cpp`）的主干是 6×10 格子卷积，僵尸按 80 像素取整进格子。
- `MEMORY/notes/student-architecture.md` 定了顺序：先补输入（v2timer 已做，task145/147，deploy16 即将上线），再量差距，差距大再上个体 + 注意力。先读这份笔记，包括“不做的事”。
- task129：老师（推演用的就是学生）在没见过的卡组上只赢 14.6%，**卡组泛化是头号短板**。task148：GPT Pro 在屋顶的胜利卡组上，学生 1/112、老师 5/112。
- 假设：卡槽按位置编码、僵尸按格子取整，两者都限制泛化。改成“每张卡 / 每株植物 / 每只僵尸 / 每个投射物是一个带类型嵌入和精确坐标的个体，用注意力处理两两关系”，对卡组顺序不敏感，空间关系也更精确。

## 要做的

1. **调查**：现行学生到底看到了什么（格子通道、标量、卡包特征、identity 头），引擎帧 dict 里还有什么没用上（僵尸精确 x/y、状态、投射物、滚动坚果、计时）。只放玩家在画面上看得到的东西。
2. **Python 实现**：配方字段（如 `arch: "entity_attn"`），默认不变，旧配方、旧检查点、旧打包结果逐位不变。
   - 个体 token：卡包、植物、僵尸、投射物等，类型嵌入 + 精确坐标 + 状态；注意力编码（建议 width 64–128、2–3 层，带行差 / 列差相对偏置），与现有格子分支并存，汇入现有的动作头与辅助头。
   - 训练、打包、热启动路径都要能跑通；旧格子分支能否作为初始化，由你判断。
   - **不手写轨迹特征**（例如算出坚果会经过哪些格子），物理推演交给老师搜索。
3. **C++ 前向**：新导出格式 `PVZRN007`，`EnvironmentRollout.cpp` 实现 CPU 前向；用几帧做 Python/C++ 对拍。
   - 推演是采集的热点：报告每次决策的 C++ 耗时，与 PVZRN006 对比。如果太慢，说明瓶颈和可选的瘦身方案（层数、宽度、token 上限）。
4. **小规模对照（有真实信号才算数）**：
   - 可以从台式机只读拷一小份训练帧（≤ 500 MB，`ssh … wsl -d Ubuntu -e cat`，约 0.5 MB/s）。不碰台式机生产进程、状态文件、看门狗，不在台式机训练或跑测试。
   - 在 Mac（MPS/CPU）上用同一份数据分别训练现行架构和新架构，比较留出行的动作准确率；有余力就按卡组拆开看：训练里见过的卡组 vs 没见过的。
   - 这是方向判断，不是最终结论；最终由生产的 A/B 槽位和门禁决定。
5. **配方草稿**：`recipes/dw4i2_v2timer_entity.json`（基于 deploy16 的 A 配方 `recipes/dw4i2_v2timer.json`），以后可以放进生产的 alternate-recipe 槽位，跟现行架构同轮竞争。

## 调查（2026-10-28）

现行 `RolloutNet` 输入为 92 个基础格子通道与 115 个标量，v2timer 再加 25 个通道和 9 个标量。植物按种类累计血量，僵尸按 80 像素落格后累计血量、吃食与减速状态。v2 分支已有格内位置范围、速度、植物动作进度和投射物伤害，计时分支补充可见动作计时与传送带位置。任务背景可选，只含出怪倍率与僵尸名单。

deploy16 已使用 `packet_head: identity`：卡包特征为植物种类、激活、冷却进度和可支付，按种类对称汇总，卡包评分与格子动作共用植物嵌入。因此卡槽顺序问题已由 PVZRN006 处理，本任务主要检验个体空间关系能否带来增益。

精简帧保留僵尸精确 x 与横向速度，植物只留行列和血量，投射物只留行、x 与伤害。完整观测还有僵尸 y 和阶段、投射物种类与三轴位置，但帧压缩未保留。滚动坚果属于植物，当前输入缺少它移动后的像素位置与滚动状态。新增实体输入需同时接通公开观测、压缩帧与原生前向，遵循现有雾/风暴遮挡，不纳入目标 ID、随机数或未来轨迹。

实现采用独立 `arch: entity_attn`，保留格子主干和身份动作头，实体分支使用 64 维、两层注意力，再汇入原有全局上下文。实体特征附加在新训练包的标量存储中，复用现有稀疏存储与分段合并。旧配方不增加打包标识，旧网络不创建新参数。Mac 已有真实搜索示范，可直接开展小规模对照，无需传输生产数据。
