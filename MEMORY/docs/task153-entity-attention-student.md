- `MEMORY/notes/student-architecture.md` 定了顺序：先补输入（v2timer 已做，task145/147，deploy16 即将上线），再量差距，差距大再上个体 + 注意力。先读这份笔记，包括“不做的事”。
- task129：老师（推演用的就是学生）在没见过的卡组上只赢 14.6%，**卡组泛化是头号短板**。task148：GPT Pro 在屋顶的胜利卡组上，学生 1/112、老师 5/112。

## 历史：这条路以前走过一半（先读）

- PPO 时期的策略 π 就是 token + 关系注意力 + GRU（`GameplayModelV1`，790 万参数，带 kind-pair / 行差 / 列差 / 同格偏置），代码已于 10-19 删除，tag `pre-cleanup-20261019` 可取回。

- 当时的代价（`MEMORY/2026-10-02.md`、`2026-10-14.md`）：完整关卡 token 数中位 121、最多 150，注意力按 token² 涨；Python 逐行组装 token 约 3.3 ms/行。

## 主控补充（10-29 用户追问后）

- **对照必须有等参数量的宽 CNN 臂**：现行 64 宽 CNN、加宽到与新架构参数量相当的 CNN（如 128 宽）、新架构，三臂同数据同轮数。新架构只有赢了宽 CNN 才算“结构”带来的收益，否则只是参数多。10-22 task23 的 128 宽同语料已显示容量能补回一部分。
- 指标按“训练见过的卡组 / 没见过的卡组”和地形分开报告，不只报总体。
- **速度的首选方案是角色拆分**：老师根节点出手、生成候选，用新架构；续走里的上千次前向仍用现行 CNN（AlphaGo 的策略网络 / 快速走子分工；计划里“出手学生与续走学生拆开”）。这样续走速度完全不变。C++ 前向只需支持根节点调用频率；先量一局里根节点调用次数与续走调用次数的比例。

## 要做的

1. **调查**：现行学生到底看到了什么（格子通道、标量、卡包特征、identity 头），引擎帧 dict 里还有什么没用上（僵尸精确 x/y、状态、投射物、滚动坚果、计时）。只放玩家在画面上看得到的东西。
2. **Python 实现**：配方字段（如 `arch: "entity_attn"`），默认不变，旧配方、旧检查点、旧打包结果逐位不变。
   - 个体 token：卡包、植物、僵尸、投射物等，类型嵌入 + 精确坐标 + 状态；注意力编码（建议 width 64–128、2–3 层，带行差 / 列差相对偏置），与现有格子分支并存，汇入现有的动作头与辅助头。
   - 训练、打包、热启动路径都要能跑通；旧格子分支能否作为初始化，由你判断。
   - **不手写轨迹特征**（例如算出坚果会经过哪些格子），物理推演交给老师搜索。
3. **C++ 前向**：新导出格式 `PVZRN007`，`EnvironmentRollout.cpp` 实现 CPU 前向；用几帧做 Python/C++ 对拍。
   - 推演是采集的热点：报告每次决策的 C++ 耗时，与 PVZRN006 对比。如果太慢，说明瓶颈和可选的瘦身方案（层数、宽度、token 上限）。
   - 不用 LLM 的稀疏注意力（NSA / DSA / MoBA 等）：它们针对上万到百万 token，DSA 每个 query 选 2048 个，比我们整局的 token 数（约 150）还多。在 n≈150、batch=1、CPU 的条件下，耗时主要在投影和 FFN（随 n 线性），QKᵀ 只占约三成。有效的瘦身手段是：只做实体 token（格子交给现有卷积分支）、按行局部注意力加少量全局 token、潜变量瓶颈（Perceiver 式）、减宽减层、int8。
4. **小规模对照（有真实信号才算数）**：
   - 可以从台式机只读拷一小份训练帧（≤ 500 MB，`ssh … wsl -d Ubuntu -e cat`，约 0.5 MB/s）。不碰台式机生产进程、状态文件、看门狗，不在台式机训练或跑测试。
   - 在 Mac（MPS/CPU）上用同一份数据分别训练现行架构和新架构，比较留出行的动作准确率；有余力就按卡组拆开看：训练里见过的卡组 vs 没见过的。
   - 这是方向判断，不是最终结论；最终由生产的 A/B 槽位和门禁决定。
5. **配方草稿**：`recipes/dw4i2_v2timer_entity.json`（基于 deploy16 的 A 配方 `recipes/dw4i2_v2timer.json`），以后可以放进生产的 alternate-recipe 槽位，跟现行架构同轮竞争。

## 主控复盘（10-29 12:55）

用保存的三个模型在同一份数据上补测“种 / 等”的 AUC 和偏置（`$CLAUDE_JOB_DIR/tmp/diag153.py`，一次性脚本）：

| 架构 | 训练 AUC | 见过 AUC | 未见 AUC | 未见：等待行误判为种 | 未见：等待行平均 logit（见过） | 未见：种植行平均 logit（见过） |
|---|---:|---:|---:|---:|---:|---:|
| CNN64 | 0.922 | 0.915 | 0.889 | 4.0% | −2.43（−2.82） | 0.63（0.73） |
| CNN81 | 0.930 | 0.920 | 0.901 | 4.8% | −2.44（−2.93） | 0.87（0.86） |
| 实体64 | 0.934 | 0.925 | 0.886 | **11.0%** | −2.62（−3.49） | 1.55（1.19） |

- 排序能力（AUC）三臂相近，实体在见过卡组上最好。掉分来自**未见卡组上整体偏置上移**：实体把大量等待行判成“种”（11% 对 4%）。评分里等待行按 10 倍加权，所以完整动作准确率掉了 6 个点。
- 偏置来源（看代码）：
  1. 卡包 token 与盘面 token 一起做**均值池化**，开局盘面空，池化向量几乎就是“这套卡组”的平均嵌入，直接加到全局上下文 → 训练只有 23 套卡组，模型学会了“卡组 → 出手倾向”，遇到没见过的组合就偏。
  2. `group` 不进输入，卡包和植物共用嵌入行（offset 都是 0），卡包 token 的坐标是 (0,0) → 卡包和第 0 行最左格的同种植物几乎分不开，还会被相对位置偏置拉去关注第 0 行。
  3. 单头，相对偏置只是 |Δ行|、|Δx| 的两个线性系数，表达不了“同一行”这种离散关系。
  4. 旧存档植物 / 僵尸 y 都是 0、精确字段缺失，实体 token 相比格子没多少新信息，却多了一条记卡组的通道。
- 结论：这次对照测到的主要是实现缺陷 + 小数据，不足以否定“个体 + 注意力”。

## 修订 1：修正后重跑（交 Qoder）

1. 卡包 token 不进盘面池化：盘面实体单独池化进全局上下文；卡包只通过对盘面的交叉注意力进卡包头（或只给卡包头用），不给“种 / 等”加偏置。
2. 加 group 嵌入；卡包 token 不带坐标，也不参与相对位置偏置。
3. 多头（如 4 头）；相对偏置改为可学习的“同行 / 行差桶 / 列差桶”查表。
4. 训练时随机卡组增强：以一定概率随机遮掉 1–2 张卡包 token（不改标签行，只遮输入）。
5. 三臂各跑 3 个随机种子，报告均值和范围；同时报告 AUC 和等待行误判率。每臂约 1 分钟，Mac 上串行跑。
6. 修正后若实体仍不如等参 CNN81，就写结论停下。结果追加在本文件末尾，推送 `entityattn`。

## 修订 1 结果（2026-10-29）

### 实现

- `python/pvz_entity.py` 重写为 `entity1` 布局：第 0–9 行固定是 10 个卡槽（空槽标为无效，不再压缩），第 10–127 行是盘面实体（植物 54、僵尸 40、投射物 24）。卡槽 token 的坐标字段恒为 0，且不参与任何相对位置计算。
- 盘面实体单独做掩码均值池化后加到标量上下文；卡包 token 变成编码器的第二个输出，只经 `RolloutNet.card_projection` 进入卡包头，不经过“种 / 等”头。
- 新增 group 嵌入（0 padding / 1 卡包 / 2 植物 / 3 僵尸 / 4 投射物），植物、僵尸、投射物的种类嵌入分别偏移 54 / 108 / 142，不再与卡包共用嵌入行。
- 注意力改为 4 头（宽 64 时每头 16 维）。相对偏置换成按头查表：同行 2 项、|Δ行| 0–5 共 6 项、|Δ列|（以格为单位，0 / <1 / <2 / <4 / ≥4）5 项，仅作用于盘面–盘面 token 对；卡包查询只 attend 盘面，盘面查询也只看盘面。
- 训练期卡组增强：以 0.5 的概率每样本随机遮 1–2 张有效卡槽 token（置无效并清零表示，标签与卡包特征不变；推理期关闭）。
- 热启动把 `entity.output` 与 `card_projection` 同时置零，格子模型 → 实体分支仍逐位保持原动作函数。原生导出继续明确拒绝，未写 C++ 前向。
- `scripts/compare_entity_student.py` 改为三臂 × 3 种子，按种子保存检查点，报告均值与 [最小, 最大]，并新增 AUC、等待行误判率与平均 logit；`artifacts/student/task153/diag153.py` 用保存的检查点独立复核同一批指标。

### 对照设置

与上一轮相同的数据与划分：Mac 本地 `artifacts/hard_mac/frames` 的 d7–d10 扰动卡组示范，152 局、37,699 行（训练 24,322；见过卡组留出 6,072；未见卡组留出 7,305），23 个训练卡组、32 个未见卡组。v2timer 输入、硬标签、wait_keep 0.1、12 轮、批量 128、AdamW lr 0.002 余弦下降。三臂、每臂 3 个种子（1/2/3），种子同时决定初始化与每轮行顺序；Mac MPS 上串行跑。

### 结论

1. **上一轮的 11% 等待误判是卡包泄漏，已修好。** 实体臂未见卡组等待误判 11.0% → 4.0%，等待 logit −2.62 → −2.48，与两个 CNN 臂同一水平；未见完整动作从 84.68% 回到 90.96%。主控复盘指出的实现缺陷确实是那 6 个点的主因。
2. **但修正后实体仍不如等参 CNN81**：未见完整动作 91.0% 对 91.3%（范围重叠），见过 91.6% 对 92.6%，AUC 0.879 对 0.887，种植动作 16.4% 对 19.6%；实体训练/评估耗时约为 CNN81 的 2.9 倍（115.5 s 对 39.5 s）。没有任何一项在均值上领先。
3. 按修订 1 第 6 条**停止**：不做 `PVZRN007`、不写 C++ 前向、不进 alternate-recipe 槽位、不部署。`recipes/dw4i2_v2timer_entity.json` 仅保留为训练路径草稿，原生导出继续拒绝。
4. 这批数据全是白天草地 L7–L10，没有保龄球、屋顶、蹦极等空间关系关；在这类关卡上格子卷积本来就够用。若以后还想验证个体 + 注意力，应先补空间关系关卡与更多卡组的数据，而不是继续加架构或换着调超参；本轮的小数据只能作方向判断，不是最终结论。
