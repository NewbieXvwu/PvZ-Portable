# task69："替换"动作——在已占格上种 = 同一 tick 铲掉再种

> 主控 2026-10-24 写。执行者：台式机 Codex（plus 账号，`codex-mem` 会话，task58 已完成）。工作树 `/home/newbiexvwu/PvZ-search/.claude/worktrees/replace`（分支 `replace`，从 origin/pvz-env 拉出，主控已建好）。游戏进程最多 4 个；GPU 训练每次 ≤1 小时，开始前 `MemAvailable` ≥10 GiB；**不碰 tmux `qc`，不重建生产引擎 deploy3**。

## 为什么
- 用户 10-24 的心得：夜间关有零费小喷菇，前期种满，后期**必须铲掉换成更强的植物**，所以模型必须学会铲子。
  - 用户四局示范共铲 22+16+…… 次，全部是"铲小喷菇，随后在同格种大喷菇等"。
- task64：老师接手用户的局面 96 局，**一次也没铲过**。原因是生产搜索的候选集里根本没有铲子，学生也没有铲子输出，结构上就做不到。
- 10-18 已定的方向（计划文档 2026-10-18 10:50）：
  - 铲掉不补种在原版里几乎从来不是最优：铲子不退阳光，被铲的植物在被替换前一直在干活。
  - 所以铲子的正确形态是**"替换"**：在已占的格子上种 = 同一 tick 先铲后种。
  - 学生不用新输出头，只是格子的合法范围多了已占格。
  - 要防 9-29 和 10-01 两次出现过的"铲子成了噪声出口"：那两次是"只铲不种"、每步都合法，导致赢家诅咒。替换必须同时种下一张卡、付出阳光，这种激励在结构上不同；但仍要量。

## 要做的
1. **环境**：新增一个复合动作 `replace`（格子，卡）。
   - 同一 tick 内先对该格执行铲子，再种这张卡。
   - 合法性走游戏自己的判定：铲掉后该格 `CanPlantAt` 对这张卡成立，卡已冷却、阳光够用。不能种就整体不执行，也不铲。
   - 铲子作用于哪一株，照游戏自己的规则（顶层植物 / 南瓜 / 睡莲上的植物）。
   - 替换后的植物不能与被铲的完全相同（同卡同格无意义）。这是合法性，不是打法规则：要用游戏自身的语义判断，写清理由。
   - 引擎分支推演、快照、`static_scores` 都要支持这个动作。存档格式不变。
2. **老师候选**：每张可用的卡，在已占格里取静态网评分最高的替换格（与现有种植候选同一取法，只是多了已占格），加入候选。
   - 与现有候选一样走 halving 与验证，记录"替换"被选中、被推翻的次数。
   - 不加手写惩罚或打折。
3. **学生**：
   - 合法动作掩码里加入"已占格且可替换"的格子。学生的格子头选到已占格，就执行替换。
   - 训练标签：老师选的替换动作；人类示范中"铲某格后 N tick 内在同格种下"的配对，转成替换标签。N 取示范里实际出现的间隔分布，写清依据，不要拍一个数。没配上对的铲子单独统计。
   - 观测不变。
4. **预登记的 A/B**（先写进本文件、提交，再开跑）：
   - 老师有替换 vs 无替换，同种子配对、生产参数（叶值 v5）。两臂用改前、改后两个提交（两个构建），不加开关。
   - 任务：`fog_user_l31_snow` 的 1.5、2.0 倍（1.0 倍老师已 78%，要在它也会输的压力下比），每档 32 对；再加一个日间压力档，例如 day L7 的老师约 70% 档，32 对，检查有没有副作用。
   - 报：胜率配对检验、每局替换次数、被替换的植物类型分布（是否主要是"小喷菇 → 大喷菇"这类升级）、阳光用度。
   - 赢家诅咒检查：替换动作在验证阶段被推翻的比例，与普通种植对比。
5. 结论写 `MEMORY/docs/replace-action.md`：
   - 若老师有替换后显著更好且无副作用，建议接入 qc。接入需要重建引擎部署，由主控做。
   - 若无提升，写清原因。
6. 测试：合法性（各种底座、南瓜、睡莲、墓碑格）、确定性、快照分支、旧动作逐位不变。提交并 `git push origin replace`。
