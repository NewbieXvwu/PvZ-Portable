# 它到底输在哪：348 局逐步回放分析（2026-10-12）

**数据**：`artifacts/episode_samples/`（758 文件 / 374 MB / 348 局）
**方法**：解析每局 `frames.jsonl` 的逐帧棋盘 + 逐帧动作，**按波数控制**（避免"死得早→局短→累计量小"的混淆），并在**三个检查点内部**分别验证。
**脚本**：`/tmp/an_def.py`、`/tmp/an2.py`、`/tmp/an3.py`、`/tmp/an4.py`、`/tmp/an5.py`（都在台式机）

⚠️ **样本有偏**：这 116 个种子是按 **v3_1m 的失败簇**抽的，所以**不能**用它算"v3 的胜率"。
**组内**的"赢 vs 非赢"对比不受影响（同一检查点、同一波数、同一批种子）。

---

## 一、结论（一句话）

**它不是"不会种"，也不是"没钱种"，而是：中期（第 5~15 波）防线顶不住 → 僵尸一路走到最里面把向日葵吃掉 → 它开始反复补种向日葵 → 陷入"种下去就被吃"的循环，钱永远攒不起来，也永远没升级到更强的植物。**

**失败是一条死亡螺旋，不是某一个决策点上的失误。**

## 三、机制（把证据串起来）

```
前 5 波：双方一样（~10 向日葵 + ~1 火力/行，钱刚好花光）
   ↓
第 5~8 波：一波更强的进攻
   ↓
一部分局的前排（c4-c5）没顶住 ──┐
   ↓                            │  另一部分局顶住了
僵尸一路走到最后排 c0-c1          │      ↓
   ↓                            │  继续补火力到 4/行
把向日葵吃掉（占被吃植物的 42~47%）│      ↓
   ↓                            │  收入 > 支出，开始攒钱（w20 ≈ 950）
它开始反复补种向日葵              │      ↓
（共种 25 个，最后只剩 10 个）     │  升级到寒冰/双发
   ↓                            │      ↓
钱永远花在"恢复收入"上，          │  前排死的是"该死的"（c4-c5）
从不加固前排，也从不升级           │      ↓
   ↓                            └──→ 通关
防线更薄 → 更容易被突破 → 回到上面
（死亡螺旋）
```

**根因假设**：**它对"防线被突破"的响应方式错了**——被吃了向日葵就去补向日葵（恢复收入），
而不是"把钱全砸到前排、先把防线做厚"。

## 四、这条结论的边界（还没证实的部分）

1. **因果方向未定**。上面的机制是"螺旋"，但**无法从观测数据判断**"是防线先薄所以被突破"还是"被突破了所以防线看起来薄"。
   **要证伪必须做干预实验**（把某一局的某一步强制改成"种火力"，看它能不能救回来）。
2. **样本是按 v3_1m 失败簇抽的**，所以：
   - 组内"赢 vs 非赢"对比 ✅ 可用
   - "v3 从起点到 1M 变好还是变差" ❌ 不可用（样本偏向失败）
3. **每局只跑了一个检查点组合**（initial / v3_1m / bc_seq32_100k），没有覆盖 v3 的全部 10 个节点。
4. **"有钱却不种"这个检验失败了**：判据太宽（"等"本来就占 94% 的动作），
   98~99% 的"机会"在赢局和输局里都被放弃，**不具区分度**。要重做，判据必须更严
   （例如"至少两行火力 <2"或"刚被突破之后的下 N 步"）。
