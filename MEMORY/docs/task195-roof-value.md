# task195：用 task105 扫描标签训屋顶估值候选（v5 结构不变）

2026-10-31。离线，不碰生产服务。目标：老师叶值 v5 在屋顶区分力弱（task154 诊断 AUC 0.495，
v6 又因白天 L9 变差被否），用 task105 已攒下的「起点局面 → 老师胜率」补屋顶，其余地形只做不退步检查。

## 1. 结论

**屋顶估值网明显修好，其他地形没有可证实的变差；用它当叶值的从头对打方向为正、无逐关倒退，
但 36 对的功效不足以证明提升。**

1. 叶值排序：扫描留出屋顶 AUC 0.578 → 0.893（局内 9 点排序 0.649 → 0.919）；排练留出屋顶
   AUC 0.273 → 0.830（v5 原本低于随机）。两个独立标签源同向，校准同步修复（屋顶排练 ECE
   0.616 → 0.041）。
2. 非屋顶：白天 / 夜间 / 泳池 / 雾的 Brier 与 ECE 都改善或持平；AUC 点估计 白天 −0.005、
   夜间 −0.012（CI 含 0，但下界 −0.047 / −0.043 略低于我预设的 −0.03）。**task154 的 L9 回归
   没有重演**：L9 +0.061。
3. 从头对打（L41–L49 × 4 种子，同种子、only leaf value 换臂）：v5 胜 5/36，候选胜 9/36；
   逐对 gain 5 / harm 1，净 +4，McNemar 精确双侧 p = 0.219。没有任何一关候选净负；
   4 关（L44/L47/L48/L49）两臂全败，对局本身的胜率只有 14%–25%，这 36 对撑不起显著性。
4. 结论口径：**候选可以在屋顶替换 v5 作为老师叶值**（数据侧证据强、对打无倒退），但
   「提升胜率」这一条要拿去生产门禁验证，不能由这 36 对下结论。

### 2.2 排练 / 留出（生产对局）

**划分**：只按 seed 哈希分成 70 / 15 / 15，扫描与排练共用同一个 `split_for(seed)`。

## 4. 留出评估（v5 → 候选）

### 4.1 扫描留出（按 seed 留出；屋顶 16 种子 / 252 行）

| 指标 | v5 | 候选 | Δ | 95% CI |
|---|---:|---:|---:|---|
| AUC | 0.578 | 0.893 | **+0.314** | [+0.186, +0.447] |
| within-archive AUC（28 份存档内 9 点排序） | 0.649 | 0.919 | **+0.271** | [+0.182, +0.371] |
| Brier | 0.1859 | 0.0696 | −0.1163 | |
| ECE | 0.2289 | 0.0729 | −0.1560 | |

扫描集里除屋顶外每种地形在留出 split 都只有几行，不足以单独判定，非屋顶的检查以 4.2 的排练集为准。

within-archive 这一项是搜索真正用到的排序能力：同一局 9 个起点里谁更值钱。候选把
「跨存档排序」与「局内排序」一起修好了，不是只把不同档位的均值拉开了。

### 4.2 排练留出（学生整局胜负标签，按 seed 留出）

| 地形 | 行/种子 | v5 AUC | 候选 AUC | ΔAUC | 95% CI | ΔBrier | ΔECE |
|---|---:|---:|---:|---:|---|---:|---:|

要点：

1. **屋顶明确变好**：扫描侧 +0.314（局内 +0.271）、排练侧 +0.557，两个独立标签源同向。
   v5 原本在排练屋顶上**低于随机**（0.273），扫描侧也弱（本语料 0.578；task154 另一口径 0.495）。
2. **其他地形不变差**：四个地形的 Brier 与 ECE 都改善或持平（唯一持平是夜间 Brier +0.0003）。
   AUC 点估计 白天 −0.005、夜间 −0.012，CI 都包含 0；但 CI 下界（−0.047 / −0.043）略低于
   我事先设的 −0.03 线，如实记录。
3. **白天 L9 没有重演 v6 的问题**：L9 +0.061（CI 下界 −0.004），L7 −0.034 但 CI 很宽
   [−0.102, +0.053]、Brier 反而更好。排练集中 L9 只有 14 个留出种子，这一项功效有限，
   真正靠得住的 L9 判断应来自生产门禁。

## 5. 屋顶 A/B（候选 vs v5，L41–L49 × 4 种子）

设置：两臂只换 `--value`（老师叶值），从头开局、同种子对照；student `dw4i_s1`、
static `value_branch1`、verify-samples 9、student-candidates 2、dagger-beta 1；
`nice 19`、2 进程。评估种子为 1952000xx 独立段，与 v5/候选的 `trained_on`、
扫描集、排练集、生产 `frames_v2`、倍率面板全部零交集（36 个种子逐一核过，overlap = 0）。

| 关卡 | 对数 | v5 胜 | 候选胜 | gain / harm | 净胜 |
|---|---:|---:|---:|---:|---:|
| L41 | 4 | 3 | 4 | 1 / 0 | +1 |
| L42 | 4 | 1 | 1 | 1 / 1 | 0 |
| L43 | 4 | 1 | 1 | 0 / 0 | 0 |
| L44 | 4 | 0 | 0 | 0 / 0 | 0 |
| L45 | 4 | 0 | 2 | 2 / 0 | +2 |
| L46 | 4 | 0 | 1 | 1 / 0 | +1 |
| L47 | 4 | 0 | 0 | 0 / 0 | 0 |
| L48 | 4 | 0 | 0 | 0 / 0 | 0 |
| L49 | 4 | 0 | 0 | 0 / 0 | 0 |
| **合计** | **36** | **5** | **9** | **5 / 1** | **+4** |

McNemar 精确双侧 p = 0.219（n=6，gain 5 / harm 1）。两臂总胜率 13.9% → 25.0%。

怎么读：

- **无逐关倒退**：候选唯一输掉的一对在 L42（该关 gain 1 / harm 1 打平）；其余 8 关候选都不差于 v5。
- **提升集中在 L41 / L45 / L46**（3→4、0→2、0→1），与估值网在屋顶的排序改善方向一致。
- **L44 / L47 / L48 / L49 两臂全败**，L43 也只有各 1 胜：从零开局、playthrough 2 的屋顶关
  本身对老师极难，36 对里大部分是「谁打都输」，没有区分力。这不是候选的问题，也不是
  可用来证明「提升」的分母。

## 6. 下一步

1. 把候选取代 v5 作为老师叶值，走生产门禁 / 晋升面板验证——这是唯一能证明胜率提升的通道；
   36 对 A/B 只支持「不退步 + 方向为正」。
2. 屋顶需要更可区分的评估设计：换更低的倍率或更靠前的波次上限（避免 0–0 的死局），
   或者用相同起点（而非从零）的配对，把「谁打都输」的局从分母里去掉。
3. 若生产侧接受，可把「扫描起点 + 胜率」的生成做成常规管线（task105 已证明可行），
   屋顶之外也可以按同样方式补弱地形；但注意扫描标签是老师自打的结果，只适合补叶值排序。
4. 环境限制：本机 CUDA 在带 `ulimit -v` 的 shell 里不可用（`cudaGetDeviceCount` 报 OOM），
   gpuwindow 队列里的训练不受影响（实际 device=cuda）。
