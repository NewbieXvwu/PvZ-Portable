## 方法修正与证据

在查看任何模型汇总表前，代码复核发现原公共池虽集合对称，但插入顺序会在重老师均值完全相同时潜在偏向先插入的Mac候选。原106个部分点与日志完整保留作试跑，未纳入正式结论；新增交换两模型身份后公共池及顺序不变的回归，修正后用原32轨迹、256点和future种子从零重跑。见 [预登记](static-value-branch1-plan.json) 与 [修正记录](static-value-branch1-amendment.json)。

两文件及新程序SHA见预登记；Mac模型585243字节/MD5 cda25bfcf1b6dd58a226787fcccb9375，台式机584603字节/MD5 b16a75242bd98bd1f0bc2f791f2c8e3d。模型仅在本机读取，未入git。原始轨迹、64-future矩阵、命令与资源记录位于artifacts/cuda/task12/；[完整配对统计](static-value-branch1-validation.json)。

复现（使用同目录资源闸门驱动，最多4游戏，低于2GiB暂停自有子树、恢复3GiB后继续）：

```bash
export PYTHONPATH=python:scripts
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
~/.venvs/ml/bin/python3 scripts/static_value_compare.py generate --out artifacts/cuda/task12/comparison --workers 4
~/.venvs/ml/bin/python3 scripts/static_value_compare.py compare --out artifacts/cuda/task12/comparison --workers 4
~/.venvs/ml/bin/python3 scripts/static_value_compare_stats.py --data artifacts/cuda/task12/comparison --out MEMORY/docs/static-value-branch1-validation.json
```

实际正式打分由canonical_driver.py包装资源监视，生成轨迹先由compare_driver.py执行generate阶段；不要省略资源闸门直接并发运行这些命令。所有后续胜率/新标签训练由主控决定，本任务没有替换正式静态网。
