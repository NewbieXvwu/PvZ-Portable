### 编码与实现

`CompactBoards.compress()` 是共享 CSR 编码的唯一入口，由 `_read_segments()` 合并完成后调用。每 32 行组成一个独立 zlib level-1 块，原始载荷按顺序保存相对块起点的 int64 offsets、原 dtype 的 indices、原 dtype 的 values。块文件之外保留每行 uint16 非零项计数、每块 int64 文件边界、每块 uint32 解压大小。当前棋盘每行最多为特征格数，uint16 足够，写入时检查计数容量。

训练取批由 `CompactBoards._gather_blocks()` 对整批行号向量化分组，再为每个 CSR store 调用一次 `scripts/training_codec/csr.cpp` 的 C++ 入口。原生端每个不同块解压一次，直接批量写入 scatter 目标位置和浮点原始字节。没有 Python 逐样本解码循环。zlib 校验与块边界检查都只作用于本批实际访问的数据，没有启动时全量重放或全量解压。

`PacketStore` 的 active、affordable 两个布尔列由每行各 10 字节改为各 2 字节，取批时 `np.unpackbits` 向量化还原，单项访问保持 uint8。其余列保持原 dtype。plane 表和覆盖关系沿用已有逻辑，浮点转换与 scatter 的顺序不变。

共享目录改为 `.merge/shared-v2/`，沿用现有签名、文件锁及权重私有副本机制。生产 `shared-v1` 未改动。`pack_training_rows.py` 仍共用同一个 `CompactBoards` 实现，其 NPZ 分段格式保持原样，无需重新从游戏帧打包，也没有增加另一套打包入口。

## task257d：并行解码与原生库自动构建

### 并行解码与预取

`scripts/training_codec/csr.cpp` 用 `std::thread` 将本批不同压缩块等分给解码线程，调用线程也参与，默认总计 4 个线程，不依赖 OpenMP。每块仍只解压一次，选中行的输出顺序和浮点字节复制保持原样。Python 通过 `BatchSource(..., decode_threads=N)` 传入线程数，棋盘和标量先后调用同一个 C++ 入口。

保留 `BatchPrefetcher` 的深度 2：后台线程准备后续批次，主线程在 GPU 当前批计算入队后取下一批，沿用旁路 CUDA 流传输，因此已有队列能够形成解码与计算的流水。增深不能提高解码的持续吞吐，本次新增预取内存 **0**。生产子集每批准备结果中位数 4.80 MiB、最大 4.83 MiB，两批队列约 9.66 MiB，另有消费者与生产者各自持有的批次。修复了队列满时重试会重复调用 `prepare()` 的现有问题，改为保留已准备的同一批次。

在 task257c 的同一生产子集上测量：随机种子 257，从 `ab575ddf247cbeae.npz` 选取相同 128 个分段，共 608,290 行，输入 364,495,111 字节。每批随机取 2,048 行，使用相同 26 批索引，各批交替按 1→2→4 或 4→2→1 执行，去掉前两批后取 24 批中位数。仅测 `BatchSource.prepare(pin=False)`，PyTorch 自身线程数固定为 1，CPU 时间包含所有原生解码线程，计时区间不含一致性比较。

| 解码线程数 | 每批墙钟 | 每批 CPU | 20,317 批累计墙钟估算 |
|---|---:|---:|---:|
| 1 | 111.308 ms | 111.267 ms | 37.69 分钟 |
| 2 | 63.390 ms | 109.692 ms | 21.47 分钟 |
| 4（默认） | **37.230 ms** | **107.236 ms** | **12.61 分钟** |

4 线程的取批墙钟为单线程的 33.45%，约快 **2.99 倍**。累计 CPU 约 36.31 分钟，工作量通过多核并行完成。12.61 分钟包含整个取批准备，按已缓存子集线性外推，可与 GPU 计算重叠，不能直接加到训练时长上。r151 的每遍 40–63 分钟对应每批约 118–186 ms 的整体吞吐预算，4 线程准备时间低于这个预算。本次没有运行 GPU 训练，实际隐藏多少解码时间仍由生产计算间隔和资源争用决定。

三个线程配置的全部 53,248 个抽样行，其准备结果均与原始 CSR 逐字节一致。Mac 上原有三个定向测试通过，包含 1 / 2 / 4 线程 materialize 后逐位一致、共享复用与权重隔离、逐段复制。新增的队列满重试测试单独通过。测试均使用 `-k`、`timeout 300` 和 `ulimit -f 2000000`，未跑整套测试。

### 自动构建与台式机验证

`_csr_decoder()` 在加载前计算 `csr.cpp` 与 `CMakeLists.txt` 内容的 SHA256，在库旁记录 `libpvz_training_codec.so.sha256`（Mac 对应 `.dylib.sha256`）。库或标记缺失、源码摘要不一致时，在 `build/training_codec/build.lock` 的排他文件锁内重新检查并执行 CMake 配置及单作业构建。摘要匹配后直接加载，进程内仍缓存函数。构建失败抛出包含构建目录和编译输出的 `RuntimeError`，不回退 shared-v1。构建发生在全量共享合并之前。

### 上线时的加载顺序与容量
