## 测量与候选改动

`CompactBoards.prepare()` 随机选行后，从共享映射抽取 CSR 元素。Linux 默认预读会为局部元素读取相邻的大段页面。仅在生产 `board_values.npy` 上取四批、每批 2,048 行时，实际需要约 1.3 MB 数值，却出现以下读取量：

| 访问提示，按实际执行顺序 | 秒数 | 磁盘读取 |
|---|---:|---:|
| 默认 | 2.818 | 2,984,390,656 B |
| 随机访问 | 0.072 | 626,688 B |
| 默认 | 0.119 | 72,499,200 B |
| 随机访问 | 0.045 | 249,856 B |

这组交替探测受已有缓存影响，不能把 39 倍的首组差异当成训练提速倍数。

进一步复制了原映射前 3,934,397 行的数值，共 622,277,048 字节。每次只清除**实验副本**的文件缓存，重复读取完全相同的四批索引，得到：

| 访问提示 | 第一次秒数 | 第二次秒数 | 每次磁盘读取 |
|---|---:|---:|---:|
| 默认 | 0.318 | 0.317 | 622,063,616 B |
| 随机访问 | 1.038 | 1.092 | 33,636,352 B |

读取量下降 18.49 倍，但冷读变慢约 3.3 倍。默认预读在这份可容纳的小副本上能顺序读完整个文件，随机访问则需要等待分散的小读取。收益取决于生产页缓存竞争，不能仅凭读取量判断墙钟。

随后在 systemd 独立作用域中，将同一副本实验的实际内存限制为 512 MiB，禁止交换，继续使用 `ulimit -v 12000000` 与 `nice -n 19`。这次副本大于可用缓存，每组 32 批、每批 2,048 行，使用完全相同的索引。按默认、随机、默认、随机交替执行，结果如下：

| 访问提示 | 第一次秒数 | 第二次秒数 | 两次磁盘读取 |
|---|---:|---:|---:|
| 默认 | 43.929 | 63.628 | 67.980 / 68.228 GB |
| 随机访问 | 13.045 | 20.811 | 0.219 / 0.232 GB |

两组配对墙钟分别提升 **3.37 倍、3.06 倍**，读取量分别下降 311 倍、295 倍。每组真正抽取的数值仅 10,368,638 字节，各批数值的整数位模式校验和一致。作用域实际内存峰值为 512 MiB，622 MB 实验副本已删除。该结果支持缓存装不下时减少预读的方向，但它只测一个 CSR 数值列，不能折算成完整 epoch 的倍数。

候选代码只改 `scripts/train_rollout_policy.py`：在新建和复用共享映射时调用 `madvise(MADV_RANDOM)`，让内核按训练的随机访问模式读取。样本顺序、批次划分、损失函数、蒸馏前向及学习率日程均沿用原实现。没有增加训练入口。

## GPU 对照的阻挡

已经按固定间隔选择十分之一的分段，使用生产配方与冻结的 r146 学生，准备执行一个 epoch。进程遵守 `nice -n 19`、`ulimit -v 12000000` 与文件大小上限，启动前可用内存超过 8 GiB。加载和权重计算完成后，第一次 `net.to('cuda')` 即失败：

```text
RuntimeError: Unexpected error from cudaGetDeviceCount() ... Error 2: out of memory
```

生产 GPU 训练进程的虚拟地址空间约 88.7 GiB。任务要求的 12,000,000 KiB 虚拟地址上限无法容纳当前 CUDA 初始化，失败发生在训练之前。已请求将实验进程改为 systemd `MemoryMax=8G`、`MemorySwapMax=0` 的实际内存硬上限，继续保持低优先级及启动内存门槛，尚未获准替换该限制。

因此，数据组装以外的 H2D、学生前后向、蒸馏老师、验证及同步耗时尚无完整分布。前后 GPU 墙钟、利用率、逐步 loss 和最终权重对照尚未完成，全量候选的新墙钟也暂不作估算。

## 一致性与上线条件

独立副本四批数值按原始浮点位模式比较一致。Mac 上直接相关的 `test_incremental_pack.py` 中共享映射复用和逐段复制含映射的两个测试通过，涵盖复用及私有权重隔离。

候选改动仅影响操作系统读取策略，未改变浮点计算顺序。但 GPU 训练曲线与最终权重仍需按任务要求对照。当前不建议部署。尤其要测量缓存竞争下的整轮墙钟，冷读实验已经显示随机访问提示可能降低首次读取速度。单候选墙钟至少减半的目标尚未验收，deploy26 仍应由主控在完成对照并审阅后于组边界执行。
