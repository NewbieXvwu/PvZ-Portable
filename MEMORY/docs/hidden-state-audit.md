# 全游戏隐藏状态审计

审计日期：2026-10-17。范围以当前任务 day_l7_z15_eval 为第一层，以冒险模式 50 关实体机制为第二层。源码行号指本分支审计时的源码。

## 结论：第 7 关优先补齐的 10 项

最影响胜负的缺口集中在三个地方：网络把完整公开观测压成了粗糙栅格；植物与僵尸的行动阶段被合并；波次实际名单和刷新节拍没有进入普通观测帧。注意：JSON 完整观测已经含有不少计时器与状态，信息丢失主要发生在 `render_episode._frame()` 和 `featurize_numpy()`；Lean JSON 本身也会删去植物状态等字段。公开 JSON 与网络特征不能混为一层。

现行任务在 `playthrough=2`，第 7 关实际为 30 波。第 7 关可出的基础僵尸是普通、路障、撑杆跳；铁桶僵尸从第 8 关开放。波次的具体名单由随机数预先抽取，普通观测不公布名单，特权观测会输出完整 `hidden.zombies_in_wave`。任务倍率在 1.3–1.5；实测任务的 3 个快跑种子里，学生赢 2/3，平均到第 28.67 波，均使用 3 张卡组中没有的其他卡种时序不会改变规则，但数据中的额外卡种计数应按观测原样解释。

下表按第 7 关的潜在胜负影响排序。`完整 JSON` 指非 Lean 的 `EnvironmentObservation(false)`；`特征` 指学生与价值网络使用的 92×6×10 张量及 113 个标量。`Lean JSON` 列只在会改变可用字段时特别注明。

|4. 土豆雷布防状态|`Plant::mState/mStateCountdown`，`Plant.h:173-180`；`STATE_POTATO_RISING` 后转 `STATE_POTATO_ARMED`，`Plant.h:66-68`。进入状态时约 1500 tick，`Plant.cpp:344-347`。|同一格同一土豆雷，刚种时不能爆炸，布防完成后可立即爆炸。把两者看成相同植物会在急救时误把未就绪土豆雷当作可用火力，或错过已就绪雷的引爆窗口。|完整 JSON 有 `state/state_countdown`；Lean 只有种类、血量、压扁标志。既有训练帧不存植物状态；第 4 关特征只存植物种类/血量。|每株植物状态类目及倒计时剩余比例；若保持 92 通道，优先加“可立即触发”布尔通道和植物状态实体特征。C++ 已遍历植物，读取两个字段，O(植物数)。|
