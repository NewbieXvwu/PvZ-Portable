# task108：qc 轮中重启后，重启前已完成的组从轮日志和训练里丢失

## 现象（主控 2026-10-26 19:30 实测）

qc 在一轮中途重启（部署、热补、崩溃）后，`run_round` 结束时只把**重启后那份 plan** 写进 `state['log']`（`curriculum_queue.py` 中 `state['log'].append(dict(round=..., groups=[... for item in plan]))`）。重启前已经完成的组：

- 对局结果已进窗口（`windows.recent`），偏移已推进；
- 但**不在轮日志里**，所以：
  1. **从未进入训练**：训练配方的标签按日志累积。第 20 轮实际跑了 33 组，配方只含 16 组；
  2. 选择面板的窗口核对对不上，6 个格被排除（fd1a0b61 的排除分支在正式挑选里也触发了）；
  3. 其他依赖日志的地方也都看不到这些组。

按 `qc.out` 与日志对账，丢失的组（不同标签）：

| 轮 | 丢失 |
|---|---|
| 13 | 16 |
| 14 | 2 |
| 18 | 2 |
| 19 | 2 |
| 20 | 17 |

共 39 组，约 1500+ 局。其中第 20 轮包括 L36 / L38 雾夜、6 个雾夜示范起点格、3 个屋顶示范起点格、原生 L25 0.5 倍等。

## 要做的（工作树基于 origin/deploy14c，即现行生产代码 fd1a0b61）

1. **修根因**：每完成一组，就把该组记录（与轮日志 groups 同字段）追加进 state 里的“本轮已完成组”列表（组完成时本来就 `save_state`）。重启后，本轮结束时把这些组与本次 plan 的组合并写入轮日志，按标签去重，然后清空该列表。加回归测试：模拟“跑 2 组 → 重启 → 再跑 2 组 → 轮结束”，日志里应有 4 组。
2. **回填历史**：写一个一次性脚本 `scripts/backfill_round_log.py`：
   - 从 `qc.out` 的组完成行（`round N <label> <task_id> mult=... offset=... games=... rc=0`）以及磁盘上 `artifacts/hard/<label>_<games>/config.json` 重建缺失组的记录，字段与现有日志一致；
   - 只补 rc=0、`games.jsonl` 行数等于 games 的组；
   - 先 dry-run 列出将补的组，主控确认后再写。
   - 写入要在 qc 停在组边界时由主控执行，**不要自己动生产 state**。
   - 补回的组应在下一轮配方里出现。核对：配方标签数 = 日志组数。
3. 确认回填不会让窗口 / 偏移重复计数（这些组的结果本来已在窗口里）。确认选择面板的 suffix 核对在回填后通过。
4. 分支 `roundlog`，推送。部署脚本由 task98 / task99 一并做成 deploy14d；本任务只交代码与回填脚本。

## 约束

- Mac 本机已冻结，不跑游戏或训练；单元测试可以跑。
- 读台式机数据用 `ssh -p 22222 newbiexvwu@127.0.0.1 wsl -d Ubuntu`，只读。
- 遵守 AGENTS.md §6.5：只跑相关测试，不做重型审计。

## 结果（2026-10-26）

在 `fd1a0b61` 上直接修复，未合并 `pvz-env`。每组完成时与窗口同次保存 `completed_groups`，轮末按标签去重归档并删除该列表。轮末日志的组数和局数也包含重启前的记录，下一轮训练沿用原有 `pack_labels` 累积入口。

`scripts/backfill_round_log.py` 默认打印完整候选记录和跳过原因，只有显式 `--write` 才原子替换状态。记录从完成行和配置重建，校验成功退出、实际行数及配置对应关系，保留学生版本与示范未来种子。已结束轮按完成时间排序写进 `log`，当前轮已完成组恢复到 `completed_groups`，等待控制器正常轮末归档。回填与控制器均不再次累计旧组的窗口或 offset。

台式机只读预演时 `state.round=20`，第 21 轮正在采集。实际可恢复：

| 去向 | 轮次与组数 | 局数 |
|---|---|---|
| 历史轮日志 | 6: 2，13: 16，14: 2，18: 2，19: 2，20: 17，共 41 组 | 1584 |
| 当前轮待归档列表 | 21: 12 组 | 336 |

任务书列出的 39 组全部包含在内，另找到第 6 轮两个仍有完整文件的缺组。第 3/4/6 轮另外 34 组缺配置或对局文件，逐组列入跳过清单，不凭空重建。

仅补历史后，任务书中的六个失配格全部恢复：`day_l10_train_d7q` ×2.5、`night_l12_train_n10q` ×1、`night_l14_train_n10q` ×1、`night_l16_train_n10` ×1.5、`night_l19_train_n10` ×1、`night_l20_train_n10_orig` ×1。现场额外十个失配来自尚未归档的第 21 轮。将其已完成组在内存中按正常轮末归档后，直接调用生产 `current_cells`，后缀失配为 0，可入面板格数 9 → 16 → 19。此次调用只读对局结局，不启动引擎。

该内存预演中，日志 395 组，对应日志派生配方标签 395 个，全部恢复标签均在下一轮配方并集中。加原配方基础语料后共 566 个标签。窗口、offset 及其他原状态字段保持原值，磁盘生产 state 字节未变。上述数字对应预演时点，执行回填时以新预演输出为准。

相关单元测试：课程控制器与回填共 59 项，58 通过、1 项既有跳过。新增测试覆盖两组后停止并重载再跑两组、标签去重与示范字段保留，以及回填的时间排序、重复执行、默认只读和当前轮归档。

### 主控执行

在台式机含本提交的工作树根目录预演：

```bash
python3 scripts/backfill_round_log.py \
  --state ~/pvz-logs/curriculum_state.json \
  --qc-out ~/pvz-logs/qc.out \
  --runs ~/PvZ-search/artifacts/hard
```

确认候选后，qc 停在组边界时使用同一命令加 `--write`，随后用本修复恢复控制器。当前轮的恢复组会在正常轮末并入日志和训练配方。本任务未写生产 state，未部署或重启 qc。
