# task264：重点格现任执行、GPT 续走

基线为 `pkg238 / c0786173`，工作分支 `execsplit`。执行模型与老师续走模型已拆开，重点格开关保持 **false**。本次未部署。

## 1. 改动与模型身份

`scripts/search_play.py` 新增 `--execute-policy <checkpoint>`。不传时，执行与续走沿用 `_terrain_policy` 的同一路由。传入时，实际先验动作来自执行模型，搜索仍加载路由后的 GPT 模型。原有 β 控制搜索动作的执行比例，搜索标签继续按原格式保存。

执行动作仍由唯一的 `_fast_action` 入口产生，并作为 C++ 搜索的锚点。额外的 top-k 候选由引擎已加载的 GPT 网络排序，续走也使用该网络。执行历史与 GPT 历史分别按各自的观测版本维护，两者读取真实执行轨迹。相同检查点只加载一次，分离时每个检查点各加载一次，保留父进程预载及 fork 共享方式。

现有引擎每个进程只有一个原生策略槽。分离时，根动作复用已有 PyTorch 逐步推理接口，C++ 搜索持续持有 GPT 网络。没有新增游戏规则、特征编码或搜索实现。`fast` 单模型对局仍可使用执行模型的原生导出。

`configs/curriculum_focus.json` 新增 `execute_incumbent: false`。开启后，队列仅对 `cells` 中地形为雾或屋顶的格传入当前现任路径，现有清单恰好是 L32 / L34 / L36 / L47 / L49。其余格及 Boss 保留现行路由，配额和卡组未改。普通组与该格的复习组使用同一选择点。

分离采集的 `meta.json.task` 记录 `execute_policy` 与 `rollout_policy`，原有 `checkpoint` 保留 GPT 续走身份，沿用训练配方的 `teacher_gptbc` 来源权重 1。课程组从采集器的实际路由配置记录这两个新字段，并保留 `student_round`。可以按执行方、现任轮次及 β 分别统计成绩。

## 3. 对照结果

**A 合计 38/64（59.4%），B 为 0/64。B 确实进入学生自己的早期失误局面，并产出 2,081 条失误之后的纠正训练行。**

| 关卡 | A 胜率 | B 胜率 | 老师建议接管/局 A → B | 标签与执行分歧率 A → B | 结束波中位数 A → B |
|---|---:|---:|---:|---:|---:|
| L34 | 9/16（56.3%） | 0/16 | 73.5 → 32.0 | 9.75% → 4.94% | 30 → 12.5 |
| L36 | 1/16（6.3%） | 0/16 | 69.7 → 21.6 | 9.82% → 4.56% | 17 → 10 |
| L47 | 16/16（100%） | 0/16 | 172.9 → 42.9 | 13.94% → 12.61% | 40 → 6.5 |
| L49 | 12/16（75%） | 0/16 | 120.6 → 37.5 | 8.76% → 7.55% | 40 → 10 |

老师共搜索 A 14,379 次、B 6,245 次，建议接管 A 6,987 次、B 2,144 次。分歧率从帧内 `label` 与 `action` 的原生搜索动作编码比较得到，分母为有效决策数，因而与搜索计数口径略有不同。两组 β 均为 0，实际执行搜索动作的次数均为 0。

B 的结束波范围分别为 L34 的 9–27、L36 的 7–11、L47 的 4–10、L49 的 4–16。L36 有 14/16 在第 10 波及以前结束，L47 全部在第 10 波及以前结束。雾关首次损失就绪割草机的中位波数为 L34：A 第 7 波、B 第 6 波，L36 两组均为第 3 波。屋顶的结束波变化尤其明显，GPT 到达成熟阵型的轨迹无法代表现任的开局状态。

训练行统计调用现有 `pack_training_rows.build_from_archives`，采用现行 `wait_keep=0.1`、`obs=v2timer`、植物身份头和候选标签。每个标签独立使用既有抽样顺序，未重写筛选逻辑。下表的“失误之后”严格定义为：本局已有更早一步未采纳老师标签，当前训练行位于那一步之后。“纠正行”进一步要求当前老师标签与执行动作不同，首条分歧本身不计入这一列。

64 份 B 存档按最终元数据的 GPT 来源均获得现有配方权重 1。A 保留 19,487 行，其中相同“后续纠正”口径为 6,925 行。B 的局数相同但对局更短，训练行总量和分歧率均下降，价值在于覆盖现任实际到达的状态。这些是老师建议的纠正标签，本次没有逐个执行替代分支来证明它们能救回整局，也没有训练学生或运行晋升门禁。

**建议对这五个重点格启用现任执行，保留 GPT 候选与续走。** 本次四关均展示了执行身份造成的明显状态分布差异，B 也保留了可入训的后续纠正行，符合补充现任失误数据的目的。L32 仅覆盖配置边界测试，没有本次整局对照成绩。当前开关仍为 false，是否形成能力转移由后续正常纯学生门禁判断。

## 5. 启用与回退

本分支保持开关关闭。上线时，在审过的发布修订中将 `configs/curriculum_focus.json` 的 `execute_incumbent` 改为 `true`，保留 `focus_share=0.25` 与 `l29_start_share=0.25`，再使用已有入口：

```sh
python3 scripts/deploy26.py --revision <审过且开关为true的发布修订>
```

由既有部署流程等当前组结束后安装并重启，执行方取课程当时的现任，GPT 续走及价值路由继续使用原配置，无需重建引擎。配置在队列启动时读取，修改 JSON 后需经组边界重启生效。

课程的既有倍率窗口继续保留，启用初期的 β 仍可能受旧 GPT 窗口影响。分析新采集胜率时按 `execute_policy`、`student_round` 和 `beta` 分组，不将旧窗口归给当前学生。已有纯学生门禁继续负责衡量能力转移。

持久回退将同一配置改回 `false`，通过同一组边界流程重启。需要整版回退时使用 `python3 scripts/deploy26.py --rollback <该次备份目录>`。回退保留课程进度和已采标签。

本次模型、帧存档和临时驱动均已清理，只保留本报告与代码改动。
