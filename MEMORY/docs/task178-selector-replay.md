## 0. 结论摘要

1. **现行挑选不是"纯平均"。** `scripts/select_student.py:38-41` 的排序是
   `(预测门禁通过, 总胜场 if 通过 else 最差地形差值, 总胜场)`：先看挑选期的门禁预测，
   预测通过才按总胜场排，否则按**最差地形差值**排。纯平均只描述第 20–27 轮（那时 receipt 里还没有 prediction）。
2. **纯平均（A）与实际几乎一致**：13 轮里 12 轮相同，唯一分歧是第 29 轮——纯平均会选
   seed4（B 配方，总胜场 277 最高，但 night 差 −9.7pp），实际/现行规则选了 seed1，且 seed1 **真实门禁通过**。
3. **纯最差地形（C，绝对胜率）在本数据上退化**：屋顶格 16 局里各候选只赢 0–1 局，成了近似常数下界，
   "最差地形"实际由屋顶噪声主导，等价于"屋顶赢得多 + 总胜场"。它在 27/29/42/52 四轮改选 B 配方候选，
   而 4 个真实过门禁的轮次里它只命中 1 次。
4. **B（平均 + 各地形非劣下界）在 5 个现代轮次里 3 轮无可行候选**（29/42/52），根源是 day/pool/fog
   比现任少 5–6 胜（−4pp 到 −7pp），超过 2–3 胜的硬下界。可行时（28 两档、36 的 3 胜档）唯一合格者
   就是平均领头羊 seed1，所以 **B 的选中结果与纯平均完全相同**；要让它有独立价值，回退必须走
   "最差地形差值"（现行回退），这样 B 才在 29 轮避开 seed4、与现行一致。
5. **关键限制：挑选期的门禁预测基本失效。** 挑选面板总对局数只有 304–376，真实门禁是 1728；
   挑选期 predicted-approve 在 5 个现代轮次里只出现 2 次（都在第 28 轮），且与实际门禁只有 1/5 一致，
   方向还偏悲观（预测 fail、真实 pass 3/4）。所以「让挑选去预测门禁」在现有面板规模下先卡在统计功效上，
   不是卡在目标函数。
6. **配方 A（原配方）压倒性胜出**：实际选中的 13 轮里 A 配方 12 次、B 配方 0 次（第 20 轮未标注、单配方）；
   纯平均下 B 配方只赢 1 次（第 29 轮），纯最差地形下 B 配方赢 4 次（27/29/42/52），但那些轮次没有真实门禁佐证。

### 三种挑选器（重算口径）

| 记号 | 规则 |
|---|---|
| **A 平均** | 在全部候选里取 `total` 最大（平手取种子号小）。 |
| **Cabs 纯最差地形** | 取"各 adventure 地形绝对胜率 `wins/pairs` 的最小值"最大的候选（平手取 total 大）。即最坏地形表现最好者。 |
| **B@k 平均+非劣** | 先剔除任一地形胜场比现任低超过 `k` 的候选（`k=2`、`k=3` 两档）；在合格集里取 `total` 最大。**合格集为空时回退到"最差地形差值（相对现任）最大，再 total 最大"**（与现行回退一致）。 |
| **Cdelta 最差差值** | 取"各地形相对现任胜率差 `delta_rate` 的最小值"最大的候选。这是现行代码在预测不通过时的实际回退。 |

对 B 另外跑过"相对现任胜率下界 −2pp / −3pp"的速率口径，结论与胜场口径相同（29/42/52 同样为空），下文不另列。
B/C 需要"现任在同一批挑选种子上逐局结果"，只有第 28 轮起 receipt 里带 `incumbent` 与逐地形预测，所以
**B 与 Cdelta 只在 28/29/36/42/52 五轮可算**；Cabs 与 A 只依赖候选自身，13 轮全可算。

### 现行代码的实际规则（口径更正）

`scripts/select_student.py:38-41`：

```python
def selection_rank(score):
    prediction = score['prediction']
    worst = min(zone['delta_rate'] for zone in prediction['zones'].values())
    return prediction['approved'], score['total'] if prediction['approved'] else worst, score['total']
```

### 4.1 为什么"让挑选预测门禁"目前卡住：挑选面板与门禁面板功效差

第 28–52 轮，实际选中候选的**挑选期门禁预测 vs 真实门禁**：

| 轮 | 挑选期 predicted | 真实门禁 | 有/无 一致 |
|---|---|---|---|
| 28 | True | False | ✗ |
| 29 | False | True | ✗ |
| 36 | False | True | ✗ |
| 42 | False | False | ✓ |
| 52 | False | True | ✗ |
| 合计 | 1 通过 / 5 | 3 通过 / 5 | **1/5** |

- 挑选期 `decide_scored` 用的是**同一套门禁统计规则**（Holm 地形否决 + overall CI 下界 > −3pp），
  但挑选面板 **overall pairs 只有 304–376**，真实门禁 **1728**；每地形挑选 72–144 局、门禁 405–414 局，
  屋顶挑选 16 局、门禁 90 局。样本小 → CI 宽 → overall CI 下界落在 −3.5pp 到 −6.8pp，
  **几乎永远达不到 −3pp 而判 fail**（5 轮里只有第 28 轮出现 2 个预测通过，其余 4 轮 0 个）。
- 方向也偏保守：预测 fail 的 4 轮里真实有 3 轮 pass。预测与真实仅 1/5 一致，样本很小，但足以说明
  **当前挑选面板的门禁预测不可当作真实门禁的代理**。

### 4.2 逐地形差值在挑选种子与门禁种子上会翻号

实际选中候选，挑选期 vs 真实门禁的逐地形**胜场差**（候选 − 现任）：

| 轮 | day | fog | night | pool | roof |
|---|---|---|---|---|---|
| 29 | 0 / +6 | 0 / +23 | −4 / −14 | −5 / −15 | 0 / −3 |
| 36 | −3 / −3 | +2 / +11 | **−2 / +16** | **+6 / −20** | 0 / 0 |
| 42 | +5 / +4 | −3 / −15 | +5 / −2 | −5 / −14 | 0 / −1 |
| 52 | **−6 / +10** | +2 / +3 | +2 / +6 | +4 / +2 | −1 / −1 |

（左=挑选种子，右=真实门禁；加粗为翻号。）

- 第 52 轮：挑选期 day 比现任少 6 胜，真实门禁 day 反而多 10 胜——若用 2–3 胜的硬非劣下界，
  **会把这一轮真实过门禁的候选直接筛掉**。
- 第 36 轮正相反：挑选期 pool 多 6 胜，真实门禁 pool 少 20 胜（未触发显著性否决，整轮仍 pass）。

结论：挑选种子与门禁种子是**不同面板、不同规模**的两套对局，逐地形差值不能逐点迁移；
把"各地形非劣"做成对挑选种子原始胜场的 2–3 胜硬下界，会比真实门禁严得多，且会误杀。

## 5. 发现与建议

1. **先改口径认知**：现行不是"平均胜率选"。20–27 轮是纯平均；28 轮起是"预测门禁 → 最差地形差值 → 总胜场"，
   且预测几乎不通过，实际退化为"最差地形差值"。要做 A/B 回放，基线应取 `Aact`（现行排序），
   而不是"纯平均"。
2. **"平均主目标 + 各地形非劣"的方向合理，但不能做成原始胜场的 2–3 胜硬下界。**
   - 在这批数据里，硬下界在 29/42/52 三轮**无可行候选**（day/pool 比现任少 5–6 胜）；可行时也只挑出平均领头羊，不改变选择。
   - 它会误杀第 52 轮真实过门禁的候选（挑选期 day −6，门禁 day +10）。
   - 若要贴近门禁，非劣约束应复用**门禁自身的统计判据**（McNemar/Holm，或按地形 SE 伸缩的边际），
     而不是固定胜负场数。
3. **"纯最差地形"不可用（至少不能按绝对胜率）。** 屋顶格 16 局、各候选 0–1 胜，绝对最差恒被钉在屋顶，
   使 C 退化成"屋顶+总胜场"，并在 4 轮里偏向 B 配方。若保留最差地形思路，应**剔除屋顶或改用相对差值**，
   并把屋顶交给门禁已有的波数端点，而不是胜率。
4. **真正的瓶颈是挑选面板功效，不是目标函数。** 挑选面板 304–376 局、门禁 1728 局；挑选期门禁预测
   与真实门禁仅 1/5 一致、系统性偏 fail。想让"挑选预测门禁"成立，先做以下之一：
   - 把挑选面板每地形加局到接近门禁规模（day/pool 至少数倍于现在的 72–144）；
   - 或把非劣/通过判据改成**噪声感知**（按地形 SE 给边际，而不是固定 2–3 胜或 −2/−3pp）；
   - 否则维持现状：挑选只做候选内排序，最终 veto 交给真实门禁。
5. **配方 A 完胜**：13 轮实际选中里 A 配方 12 次、B 配方 0 次；纯平均下 B 配方也只赢 1 次（29 轮，地形更差）。
   在挑选层面没有证据支持 B 配方（rebalanced / rebalanced_p05 / history10）替代 A。
   若要继续 A/B，需要的是让 B 配方候选在**门禁/门禁规模面板**上过线，而不是改挑选目标。
