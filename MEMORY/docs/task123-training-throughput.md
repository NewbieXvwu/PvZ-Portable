# task123：学生训练吞吐——GPU 利用率 1%

主控 2026-10-27 派给 Mac codex-plus2b。分支 `trainspeed`，基于 `origin/rebalance2`。

## 现象

- 第 21 轮 K=2：02:07 排队，06:45 两个学生都还没训完（`~/pvz-logs/curriculum_state.pipeline/round_000021/seeds/*`）。第 22 轮采集 4.5 小时已经采完，**训练现在比采集慢，成了关键路径**。
- 两个 `train_rollout_policy.py` 进程各约 24% CPU、RSS 3.3–3.6 GB；`nvidia-smi` GPU 利用率 1%、显存 7.8 GB。配方 `threads: 1`、`precompute_workers: 8`、`device: cuda`、12 epoch、约 1700 万行。
- 采集同时占着 7–16 个 CPU 进程。

## 要做的

1. 在台式机上 profile 一个正在跑的或一个缩小版训练（只读生产文件，不动 qc 和正在训练的进程），找出时间花在哪里：数据装载 / 解压 / 特征 / 权重 / Python 循环 / GPU 前后向。
2. 给出并实现提速方案，目标是单个学生训练墙钟减半以上，且训练结果在固定种子下与现在一致（或说明为什么不能一致、差多少）。可考虑：数据常驻显存或内存映射、批量增大、把行权重 / 采样搬到 GPU、减少每 epoch 的 Python 开销、K=2 两个学生共享一次装载。
3. 不改训练目标、配方语义或模型结构。
4. 只跑相关测试与一次缩小版对照（AGENTS §6.5）。上线由主控安排；推送，结果写在本文件末尾。

## 主控 07:15 补充：根因已基本确定是内存抖动

- 第 21 轮种子 1 第 1 个 epoch 用了 **15 568 秒**（第 20 轮约 15 分钟 / epoch）。每个训练进程装载约 11 GB（board 6.5 GB + scalar 2.2 GB + packet 1.4 GB …，1965 万行），K=2 两个并行 = 22 GB，加上 7–8 个采集 worker（各约 1 GB），超过 WSL 的 25 GB；swap 8/8 GB 满，`/proc/pressure/io` full 约 26%，进程 D 状态，`read_bytes` 11.5 TB（每秒 1.2 GB 重读）。
- 主控已 SIGSTOP 种子 2（pid 1063870），种子 1 恢复（IO 压力降到 3%、GPU 15%）；tmux `resume-seed2` 在种子 1 退出后自动 SIGCONT 种子 2。
- **第 22 轮的 K=2 训练已排队，会重演同样的抖动。** 所以本任务第一优先：让 K=2 的两个学生不再同时各装一份全量数据——最低限度是控制器把两个学生改为**串行**训练（或训练开始前按 MemAvailable 判定能否并行）；更好是两个学生共享一份只读数据（同一进程训两个模型，或共享内存映射）。其次才是单进程提速。
- 这个修复要尽快随 deploy14h 上线（与 cbp-task121 的 task122 合到同一部署脚本，或单独 deploy14i，主控定）。

## 实现与缩小对照登记

`read_segments` 将同一组不可变分段的合并结果保留为一份共享文件映射。第二个学生复用同一组文件页，并跳过完整分段载荷的再次复制。缓存只保留最新一代，用分段路径、大小与修改时间区分代际，以文件锁串行发布。切代时取消旧文件链接，已持有映射的训练继续使用原来的文件页。

行顺序和所有数值格式保持原样。每次读取独立复制权重列，再应用原配方的来源权重与关卡再平衡，两个学生互不修改对方权重。卡槽特征也进入共享映射。未改变批大小、随机打乱、优化器或模型结构。

直接相关测试：`python/test_incremental_pack.py` 与 `python/test_compact_loader.py` 共 18 项通过，1 项因本机条件跳过。新增用例覆盖缓存复用、权重隔离，以及切代后旧读者仍可继续读取。

缩小对照使用第 21 轮真实不可变分段的子集，原 seed 1/2 配方只替换数据目录、输出目录并限制训练步数，A 为 `34b388ae` 原训练器，B 为共享合并版本。CUDA 训练依次运行，输出写入台式机 `~/pvz-logs/task123/`，不与生产共享可写缓存。比较每步损失、最终参数和加载/训练墙钟，完整生产轮不复跑。

## 准入修复与交付结果

`estimate_peak()` 原先只采用 `RssAnon` 实测峰值，把训练持续随机访问的文件映射页当作可随时回收的空间，导致双训练获准后反复换页。现在每个学生按“匿名峰值 + 数据工作集”预留。数据工作集取训练 `data_memory` 中所有 `_bytes` 字段之和，排除行数 `rows`。训练结束将字节数写入候选和轮次回执，重启时恢复。旧回执从已选学生的原始 `metrics.json` 获取，无实测时按现有未压缩分段文件体积预留。

沿用已有主存/显存准入和串行回落路径。匿名峰值 3.5 GiB、数据 11 GiB 时，K=2 估值为 29 GiB，再加既有 6 GiB 预留，25 GiB WSL 会选择串行。单学生需求为 20.5 GiB，当前采集占用未释放时继续等待，前台采集的下一组按修正后的预留控制并发。同代共享映射仍启用，准入按每学生完整工作集保守计数，不依赖共享节省才获准运行。配方、模型和训练目标不变。

一次缩小 CUDA 对照使用 20 个真实分段、720 份档案、265,145 行，每个种子 128 个训练步。两种子逐步损失、来源行报告及最终模型参数均逐位一致，最大参数误差 0。共享文件总计 153,119,579 字节。
