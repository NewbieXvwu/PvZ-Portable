# 随机卡组任务族：结构性修复换卡组泛化（task93）

> 2026-10-26，工作树 `deckvar`。前情：task84 发现 heldout 卡组 `[0,1,2,27,5,32,3]` 里的卷心菜(32)、三叶草(27) 只从一份冻结的旧扰动数据（legacy d7p/d8p/d10p，行占比 4.31%、r11 起零增长）里出现过；换训练种子 heldout 在 124–169/192 之间抽签（典型簇 166–169 + 灾难左尾）。修复思路：**不手写卡组、不调权重，而是让训练数据本身覆盖整个引擎合法卡组空间**。

机制（`scripts/make_random_deck_tasks.py` 生成，`scripts/pvz_tasks.py` 运行时解析）：

- 每种子独立抽样：均匀抽长度 6–10，再从候选池无放回均匀抽有序样本；长度在拒绝抽样期间固定，保证五个长度等概率。
- 候选池照 `perturb_family.engine_family` 先例：Crazy Dave 候选 ∩ [0,40)（非升级/特殊卡）∩ 引擎 `not_recommended==0`。**没有任何手写强度判断**；夜间经济等整组合法性只靠引擎 `deck_warnings`（夜间拒掉的 154/263 次全是引擎 `sun` 警告）。
- 泳池族地形覆盖由 `random_deck_covered` 强制睡莲(16)（实测 32/32）。
- 引擎校验收据：生成期逐种子过 `deck_warnings` + `env.reset`，通过后才把 `{attempt, deck}` 写进清单 `validated_decks`；运行时 `deck_for_seed` 回放收据并断言逐位一致——采样器或运行时被改动会显式报错，而不是悄悄换任务。
- heldout 排除：`day_panel_identity.json` 全部 `heldout_deck` 签名 + holdout1 本体机械排除，实测碰撞 0；96 收据/族内签名无重复。

## 课程接入方案（只写方案，不改 qc；主控裁定）

1. **倍率档**（照 task75b 规则：老师胜率 ≥50% 的最高档作为起始档）：
   - `day_l7_train_rand`：1.0 倍 53%（Wilson 下界 36%）已过线，**直接按 1.0 登记**，不需要低倍档。
   - `night_l12_train_rand`（16%）与 `pool_l21_train_rand`（22%）在 1.0 倍不过线。接入前先扫 0.5 / 0.75 两档（各 16 局，种子用各自 tiers 段 93_xxx_032..047，生产老师参数不变）。0.5 倍仍 <50% 则该族暂缓登记（照 task75b L30 先例交主控），不强行入课程。
2. **采样占比**：与被替换的旧扰动冻结数据同量级起步——legacy d7p/d8p/d10p 行占比 4.31%（label_weight 0.5 下有效 ~3.1%）。建议三族合计从 **~4% 行占比**起步（每族每轮 48 局老师局，与 d7p 台式机段每轮 48 同量级），`label_weight 1.0` 平权起步。不加权：task84 变体 B 已证明对冻结扰动数据提权 3 倍反而更糟（65/192），新数据先平权观察，不要重蹈。
3. **对 heldout 的预测**：新数据每个种子都是新卡组，卷心菜(32) 等稀有卡从"一份冻结快照"变成"每局都在见"，期望 heldout 均值从抽签区（124–169）回到典型簇（166–169）或以上，且**训练种子间的方差缩小**（不再依赖单一快照的运气）；对照 `day_l7_eval_d7`（标准卡组）应持平。可证伪判据见下节。
4. **保留旧族**：legacy d7p 冻结数据不动（旧档 whatif 重放走存档里的 deck，不受影响）；随机族是加法，不是替换。
