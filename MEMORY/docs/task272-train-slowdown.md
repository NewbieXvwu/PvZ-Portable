# task272：训练 epoch 变慢与抖动

2026-11-17，`fix272`，基于 `1be4eaba`。未部署，生产队列、采集及训练参数保持原样。

## 根因与证据

**主要瓶颈为内存争用引发的文件页缓存置换和匿名页交换，WSL 的 8 MiB 默认预读进一步放大读盘。** shared-v2 的 CSR 每块包含 32 行，每批只抽中少量行，却必须解压相应整块。训练同时随机读取 packet 和 candidate 载荷。segments 压缩只在首次合并时解压，不参与 epoch 取批。

r206 的 `train_data_bytes=20,940,627,480`，匿名内存峰值 `6,804,180,992` 字节。25 GiB WSL 还同时承担通常 12 个、每个约 0.85 GiB 的采集 worker。原调度只预留匿名内存，`MemAvailable` 中可回收的文件缓存会继续分给采集。

生产现有 `~/pvz-logs/metrics/train_rollout_policy-149165*.jsonl` 记录了 r206 A 臂。以下只累计相邻记录均在同一 epoch 训练阶段的区间，排除加载、验证和阶段边界，CPU 的 100% 代表一个核心：

| epoch | train.log 全 epoch 秒数 | 观测区间秒数 | 区间物理读入 | 平均训练 CPU | 每秒训练批数 |
|---|---:|---:|---:|---:|---:|
| 1 | 4106.9 | 4022.6 | 1417.60 GB | 138.7% | 7.31 |
| 2 | 1582.5 | 1530.3 | 58.19 GB | 261.3% | 19.15 |
| 4 | 4353.6 | 4291.4 | 1339.76 GB | 143.2% | 6.89 |

同一份数据，慢区间读盘量达到快区间的 23–24 倍，训练 CPU 使用量同时下降。B 臂也有相同关系：epoch 2 的 1410 秒区间读 45.08 GB、CPU 268.4%，epoch 4 的 3062 秒区间读 730.90 GB、CPU 173.5%。这些数字指 WSL 块设备读取，不代表 Windows 宿主机每次都读取了 SSD。`/sys/block/sd*/queue/read_ahead_kb` 实测为 `8192`。

r208 自然进入训练后，在 **2026-11-18 01:53:02–01:56:18 UTC** 的 196.4 秒窗口，实采 `/proc` 得到 **458,106 次主缺页、55.61 GB 读入**。训练 CPU 平均 **112.7%**，系统 CPU 空闲 **37.2%**。交换空间接近 **2 GiB 满载**，训练进程 `VmSwap=0.959 GiB`，系统换入 155,458 页、换出 520,478 页。预取线程 CPU 为 **51.4%**，等待 CPU 调度仅 **0.289 秒（0.15%）**。该慢段由 I/O 与交换主导，CPU 容量充足。`vmstat` 同时观察到持续换入。采样未与隔离实验重叠。

## 改动

`train_rollout_policy._open_shared_segments()` 的既有映射入口，对 CSR 压缩块、candidate 条目及 packet 列设置 `MADV_RANDOM`，关闭随机缺页的周边预读。加载期顺序扫描的元数据继续沿用原映射方式。抽样顺序、批次组成及训练权重不变。

`TrainingPipeline.reservation()` 在训练阶段额外预留最近实测的语料体积，沿用已有 `worker_count()` 与组内扩容 headroom。语料体积是保守的缓存软预算，两臂只计一份，两臂切换期间保留，训练结束即释放。当前数据规模会将后续采集组压到最低 1 个 worker，代价是训练期间采集吞吐下降，同时也给解压释放 CPU。已有组自然结束，不缩杀运行中的 worker。

缓存预算只影响采集调度。训练启动仍沿用匿名内存的硬准入，避免把超过总内存的保守缓存估算变成永久等待。没有限制数据量，也没有改学习配比。

## 量化验证

隔离实验只读生产输入，副本写在 `~/pvz-logs/task272/`。使用现有 `CompactBoards._gather_blocks()` 和已编译的 C++ 解码器，固定 221 MB、65536 个真实压缩块，每批随机取 128 行、共 96 批、4 个解码线程。按块间距模拟全量随机取批，并对同一批序列比较缓存条件，四组每批输出的 CRC 一致：

| 条件 | 96 批秒数 | 物理读入 | 批次中位 / 95 分位 |
|---|---:|---:|---:|
| 缓存受挤占，默认预读 | 5.082 | 14.318 GB | 53.70 / 71.38 ms |
| 缓存受挤占，随机提示 | 0.719 | 33.67 MB | 7.49 / 8.59 ms |
| 可驻留，随机提示 | 0.146 | 0 | 1.45 / 1.80 ms |
| 可驻留，默认预读 | 0.143 | 0 | 1.43 / 1.78 ms |

关闭预读使受压取块提速 7.1 倍，物理读入降低 99.76%。继续留出缓存后再提速 4.9 倍，证明两项修复各有必要。最初更密集的抽样中，单独关闭预读曾变慢，故没有仅凭读入字节数选择修复。

另取完整来源前缀构成 **1,004,740 行、257,314,972 字节**副本，复用现有 `_open_shared_segments()` 和完整 `BatchSource.prepare()`，每批 **2048 行**、96 批，保留 board、scalar、packet 与 candidate 取批。载荷驻留时总计 **3.649 秒**，中位 **38.01 ms**，95 分位 **39.54 ms**，变异系数 **5.15%**，物理读入和主缺页均为 **0**。按 r206 的 67,364,442 行折算，完整取批约 **1250 秒**，进入约 1300 秒的目标量级。

**1250 秒是取批路径的小样本外推，完整 GPU epoch 的端到端 ≤1300 秒尚未实测。** 小样本未包含 GPU 训练、锁页复制及全量索引的缓存开销，不能据此外推完整 epoch 已达标。

Mac 上 10 项直接相关定向测试通过，均限时并限制文件大小，单个 pytest 顺序执行。台式机实验先看可用内存，低优先级运行并限制虚拟内存，systemd 内存上限最高 1 GiB。诊断采样器已停止，二进制副本已删，原始数值记录保留在 `~/pvz-logs/task272/`。
