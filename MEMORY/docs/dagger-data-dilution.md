**当前状态：因果对照尚在运行，未形成最终训练集推荐。** 全量只读审计已确认，训练配方的各头纠正权重占比均未因D30→D35而下降；倍率配比和优化预算确实改变。七臂×两训练种子的前瞻对照已冻结，不能把原先按轮次抽60局的“97%自我标签”直接当作训练损失的有效占比。

这里是监督系数审计，不是实际梯度或对局胜率。各损失头还有各自归一化；纠正系数占比上升不能证明新轮次的自标签无害，I/R对照将继续检验信息内容和习惯混合。按原配方增加数据会把总优化步数从42,456增至52,272，增加23.12%；S控制同时匹配D30的步数和余弦调度长度。

另做[旧行与划分重叠审计](dagger-data-dilution-cohort-overlap.json)：D30的8,038,389个抽样行全部仍在D35中，wait抽样没有漂移；但每次按完整种子集合重做`Random(0)`验证划分，造成2,115个旧训练种子转入验证、2,127个旧验证种子进入训练。对应675,771个旧训练行退出、665,939个旧验证行加入；两组共同训练旧行仅6,568,515，占原训练行90.67%。全局packet/spread归一化也随语料改变。因此B−F评估整个旧配方扩集的效果，不能单独归因为新增自标签；M/T/I/R/S对F则固定同一D35行与划分。此为训练数据的探索性描述，未增加对照臂，也未据此宣布退化原因。

## 训练前冻结的对照

| 臂 | 数据与干预 | 训练种子 |
|---|---|---|
| B | 原D30，重新从零训练 | 1、2 |
| F | 完整D35，重新从零训练 | 1、2 |
| M | D35，各packet×cell-soft资格层内，观察到的倍率权重均匀 | 1、2 |
| T | D35，在同层内恢复D30倍率比例，保留原F层总权重 | 1、2 |
| I | 只筛选新增11轮的纠正/高spread行，恢复层总权重；无信息层保留原样，旧D30与验证行不变 | 1、2 |
| R | I的匹配随机控制，匹配层内保留数量、比较/soft资格与最终权重分布 | 1、2 |
| S | 完整D35、同D30的42,456步余弦预算 | 1、2 |

除指定干预外，统一queue85配方：width64、meanmax、obs v2、context关闭、packet-balance0.5、wait-keep0.1、spread-weight8/cap10、cell-soft3、AdamW与cosine、12 epoch、EMA关闭。训练串行，仅共享只读数据；每次都重置模型、优化器和随机种子，权重另行clone。实际启动顺序与源码/行身份/权重校验和见[启动清单](dagger-data-dilution-launch.json)。

七个主要对比B−F、M−F、T−F、I−R、I−F、R−F、S−F；两个训练种子方向一致、整簇bootstrap95%区间排除0、Holm7校正通过，才认定支持相应机制。每个模型在z15–z20六档各跑1024个共同环境种子，六档和两个初始化按环境种子联合重采样；区间只对这两个已训练初始化作条件推断，不把游戏数当作训练种子数。

预登记依次为[假设](dagger-data-dilution-plan.json)、[六臂原案](dagger-data-dilution-experiments.json)、[训练前补充T与加强R](dagger-data-dilution-amendment.json)、[评估源码冻结](dagger-data-dilution-evaluation-freeze.json)。原案均匀倍率M仍保留；T用于区分恢复原分布与更激进的均衡。

## 工程验收与资源

旧训练器、新默认、全1行权重及缓存重用的CPU短程checkpoint张量完全一致；部分步数停止、零权重分支也通过。权重/缓存/统计/旧特征共13个唯一检查全过；初次缺资源跳过的live-history已用冻结原生程序补跑，v1/v2lite/v2档案历史一致。此为兼容性检查，不声称大型GPU训练的逐比特复现。

GPU训练等待queue86优化器退出，并要求可用内存连续30秒≥12GiB后准入；只跑一个训练。全部14模型之后自动进行8-worker评估，要求无其他训练、外部游戏进程≤4、可用内存≥9GiB。所有自有阶段低于2GiB暂停、恢复至3GiB再继续。缓存、行数组、模型、原始日志均留在忽略的`artifacts/cuda/task15/`，不入git。
