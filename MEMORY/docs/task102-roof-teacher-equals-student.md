# task102：屋顶冷启动“老师 = 学生”异常

## 背景

task101 记分板（`MEMORY/docs/adventure-scoreboard.json`）在屋顶 L42 / L44 / L47 上：

- 学生（r11 `fast`）与老师（v5 叶值 + branch1 静态网，beta=1、verify=9、student-candidates=2）同一批 16 个种子；
- 两臂结果完全相同：都是 0/16，输局末波中位数相同，破防僵尸计数逐项相同（例：L42 都是普通 55、路障 20、撑杆 5）。

这说明在这几关，老师搜索没有改变任何一局。末波只有 6–8 波，破防的只是普通 / 路障，基本等于没在防守。同一批卡组在 qc 的示范起点格上能赢（24/24），用户和 LLM 也能从头赢。

## 要回答的问题

1. 在这些关，老师每局实际推翻了学生多少次？候选数是多少？verify 有没有把推翻全部否掉？还是搜索根本没被调用？
2. 学生在前 2 分钟种了什么、种在哪？阳光曲线如何？和用户示范（`demo_roof_42_melon_m200` 等，见 task87 / cb-demo 的示范目录）的前 2 分钟逐项对比。
3. 结论属于哪一类：
   - (a) 实现 bug：例如屋顶候选生成或合法性判断、花盆、档案或卡组设置、记分板脚本自身；
   - (b) 真实的模型 / 叶值问题；
   - (c) 卡组覆盖问题。

   依据 AGENTS.md §8，先排除 (c)，再归因到策略。

## 要求

- 用 Mac 本机引擎，最多 8 个游戏进程。
- 先复现 L42 的 2 个种子，学生和老师各跑一遍，逐步打日志（动作、候选、搜索价值、verify 结果）。
- 如果是 bug：
  - 修复，并配回归测试；
  - 修复后重跑 L41–L49 各 16 种子的老师臂，更新记分板；
  - 推到分支 `roofeq`，不要合进 pvz-env。合并由主控决定。
- 如果不是 bug：给出证据，并说明哪一项数据或训练能改变它。不要手写规则或打法。
- 报告追加在本文件末尾的“结果”一节，结论放在第一段。

## 结果

**2026-10-26，结论为 (b)：学生的屋顶冷启动策略与现有叶值搜索组合失效。** L42 的两个指定种子已用 Mac 本机引擎完成师生各一局复现。老师实际搜索 75 / 21 次，最佳候选相对学生的最大估值增益只有 0.003157 / 0.001509，始终小于生产门槛 0.02，独立复核从未触发，推翻均为零。学生不断购买花盆，前两分钟没有持续火力。卡组与成功示范相同，屋顶底座和合法种植均正常，未发现解释本次现象的实现错误。

### 哪一项数据或训练可改变它

直接针对本次缺口的数据是 **L42 同卡组从 0 到 12000 tick 的成功示范决策及其完整历史**。应将上述真实冷启动经济动作和转入火力的动作作为学生监督数据，保留相应观察与等待历史，排除人工种植被拒绝的操作。现有 `python/pvz_training_pack.py:44` 的 `training_rows` 可精确选择监督行并保留完整历史，无需写打法规则。补训效果应以同任务的新种子冷启动结果检验，不能用已成型的 `demo_start` 胜率替代。当前资料不能确认 r11 历史训练是否已经间接见过这段示范，不能将“从未训练过”作为已证事实。

叶值侧需要同一冷启动分布中、包含经济建立到火力成型过程的真实续走标签，覆盖成功与失败分支。当前搜索由同一弱学生续走 2500 tick 后评分，单个经济动作的候选均值最高也不足 0.007。在这个值域中，固定 0.02 门槛足以将所有更优候选挡住。这个观察能说明现有搜索为何不介入，不能单独证明叶值低估了该弱学生的真实胜率。提高学生的冷启动能力后再采续走和训练叶值，才能同时改变搜索所依赖的未来与估值分布。本任务未修改门槛，未进行新训练。
