## 为什么
目标是通关冒险模式，L50 是最后一关，现在完全没接入（`MEMORY/docs/adventure-gap.md` 第 91 行）。已知的情况：
- 原生 reset + 1 tick 能过，种下第一张卷心菜被接受，但还没有一局完整的 Boss 终局证据。
- 通用的僵尸血量 / phase 字段不足以表达 Boss 露头、冰球、火球、召唤、投车等状态。`mBossMode`、`mBossHeadCounter`、`mBossFireBallReanimID` 等字段没有序列化。
- 原生传送带，牌是固定的 6 种。

## 要做的
1. **引擎事实**：从 `src/Lawn/Zombie.cpp` 等源码整理 Boss 的阶段机：
   - 露头 / 低头；
   - 冰球、火球（落在哪一行、多久后落地）；
   - 召唤小僵尸、扔车、跺脚；
   - 血量阈值。
   每条注明源码行号。区分哪些是**人在屏幕上看得到的**（露头动画、球的颜色和所在行、Boss 血量阶段的外观），哪些是内部计时，不能暴露给模型。
2. **观测**：给完整 / lean / v2 / C++ 学生输入加一个 Boss 可见状态块，只放人可见的信息：
   - 是否露头；
   - 当前在哪一行出球、球的类型和位置；
   - 大致的血量阶段（按外观分档，不给精确血量，除非游戏界面本身有血条；请核对）。
   旧任务、旧族的观测逐位不变，用测试锁住。
3. **原生族**：照 task75 的 `*_orig` 做法登记 `boss_l50_orig_eval/train`：
   - 原生传送带语义，保留原生牌表；
   - 种子段与现有全部段不相交（机械核对）；
   - 登记 DESIGN 与清单。
4. **老师冷启动**：生产参数——叶值 v5、静态网 branch1（Mac 路径见 task75 任务书末尾）、学生用 r11，`--dagger-beta 1 --verify-samples 9 --student-candidates 2`。
   - 先跑 8 局看能不能完整跑完（终局判定、局长、崩溃）；
   - 再跑 32 局，报胜率、Wilson 区间、输局时 Boss 的阶段与死因。
   - 过 50% 就照 task75b 登记倍率课程；到不了就做 0.5 倍档；还不行就写清原因，交主控决定是否请用户示范。
5. **测试**：新观测的四类不变式（照 task66）；旧族逐位不变；Boss 局完整跑通的回归。
6. 结论写 `MEMORY/docs/boss-l50.md`，提交并 `git push origin boss50`。部署由主控做。
