## 挑选任务与隔离

均为白天草地、二周目、50阳光、1倍、全波，7槽且不含升级卡；两个卡组均通过build6的reset与整副牌警告查询。
与门禁L7 holdout1、L9 holdout2的无序初始卡组不同。两个集合都在d7p既有排除表中；
第一个含37，d7q采样器无法从其卡池添加37，第二个在d7q排除表中；三个随机训练族均已显式排除两集合。
因此没有修改训练任务语义或重写旧档案deck；“未见”指初始集合，不保证传送带中途从未形成同样手牌。

清单为`configs/student_selection_holdout.json`，通过显式参数接入。入队时合并进模板并冻结SHA，
后台生成面板仍使用挑选专池`[130000000,140000000)`的原加锁账本，每轮384种子，不回绕、不复用。
该池独立于训练、门禁与103M记分板段；未分配新用途池，也未追加全机扫描。
新族与现有每个任务等额分配局数，总胜局规则不变，不额外放大换卡组得分。

现场有效dry-run：25个现役窗口格＋3个随机族＋2个新族，共30任务，**每任务12局，共360局/候选**，
余下24个种子仍随384块烧掉。两新族合计24/360=6.67%的总分份额。
选择种子由真实入队的锁定账本分配；dry-run只预览、不分配、不起引擎、不写生产state。

## K=4与训练耗时

新增参数：`--candidates-per-recipe 2 --training-parallelism 1`。

- A=`dw4i2`：seed1、seed2。
- B=`dw4i2_rebalanced_p05`：seed3、seed4。

四候选各有独立seed目录；配方、seed和并发上限随轮任务冻结。即使重启时CLI变回K=2/允许并行，
已入队的K=4仍按原计划串行执行。复用一个打包结果及task123共享映射，保留工作集准入、失败隔离、断点候选复用。

轮报告的每个候选包含`recipe_family`、`source_recipe`、`seed`、`selection_score`（总分及逐任务wins），
另加`selection_unseen_deck`记录两个新族各自的胜局/局数与小计。训练失败候选保留失败状态，不伪造挑选分。

用现有r20 seed2完整训练记录测算：含加载2363秒（39.4分钟），其中加载105秒、18,811,791行。
按r22的19,799,497行线性外推并加20%余量，为**2984秒/49.7分钟**，低于70分钟，故交付K=4。
该估计以task123准入消除重复工作集换页为前提，并非新跑的整轮实测；未把旧双训换页造成的数小时停顿
当作串行基准。未为测算再启动训练。
