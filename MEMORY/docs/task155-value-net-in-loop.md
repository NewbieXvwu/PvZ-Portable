## 要做的

1. **后台作业**：在现有后台执行器里加一种作业“价值网候选”，开关默认关闭（如 `--value-retrain`）。
   - 数据：最近若干轮 qc 采集的对局帧和终局输赢（`curriculum_state.pipeline/frames`），窗口大小可配；说明窗口内各地形 / 卡组的占比，必要时按地形平衡。
   - 从在役价值网热启动还是从头训，由你按数据和耗时判断，写明理由。
   - 时机：执行器一次只跑一个作业。每轮学生候选训完后，挑选和门禁只用 CPU，显卡约空 1–1.5 小时，价值网候选应排在这个空档里，不能挤占学生训练。
2. **换不换**：新候选必须与在役价值网比较后才换。
   - 用 `value_ranking_check.py` 的成对一致率，并按地形分区比较校准（Brier 或类似指标）；总体更好且各区不显著变差才换。比较集要用新候选训练时没见过的对局。
   - 规则写死在代码里，不靠人工判断；每次决定写一条日志和一个小 json。
3. **切换**：只在组边界切换，进行中的组用同一个价值网到结束；保留上一版，可以回退。门禁评估若用到价值网，写清用的是哪一版。
4. **监测**：记录老师选中的叶子的预测值和该局实际输赢的偏差，按轮汇总，持续偏乐观时写警告。
5. 小测试覆盖：开关关闭时行为不变、作业排队顺序、换 / 不换判定、组边界切换与回退。

## 执行结论（2026-10-29，Mac，默认关闭，未部署）

### 作业与数据

`--value-retrain` 默认关闭，`--value-window` 默认取最近 3 个已完成课程轮次。学生各训练种子全部结束后，才在该轮后台流水线内部启动一个价值候选，与 CPU 挑选和门禁重叠。CPU 阶段结束即取消尚未完成的候选，清理其整个进程组后才允许下一个学生训练作业运行。价值作业失败只记否决，不影响学生门禁与前台采集。前台后续组额外给价值作业预留一个 CPU 名额。

数据直接来自该轮冻结的 `.pipeline/frames` 视图，只选窗口中成功采集组的标签，不重放历史存档。每次最多 2,048 局，每局均匀抽最多 32 个非终局帧，最多训练 8 个 epoch，沿用现有早停与压缩棋盘。先按地形轮转取样，再让各地形的总对局权重相等。`round_N/value/data.json` 保存原窗口、实际训练集和比较集的地形 / 卡组占比，也列出课程格份额。冻结任务定义时去掉长种子清单，避免把整个清单复制进控制器状态。

从在役网热启动，保留其编码器、宽度及上下文设置。窗口数据少、训练空档有限，热启动能保留既有覆盖并减少收敛时间。本任务没有用全量数据重新从零训练，也没有更换静态选格网。

### 自动换版与回退

种子的稳定散列固定留出约 20%，这些对局不进训练或早停。候选检查点的 `trained_on` 合并初始化祖先与本轮训练 / 早停种子，比较时排除祖先已见种子。示范起点局用实际重抽的未来种子分区，原示范种子仍用于恢复原局。新档案明确记录 `future_seed`，旧档案读取既有 `seed_N_fM` 目录中的未来种子。旧初始化检查点若记录见过原示范种子，该来源的比较局保守排除。

校准在未见过的真实采集局上逐波取首帧，每局先求 Brier 均值，再汇总，避免长局得到更多票。排序复用 `value_ranking_check.py` 的同根候选成对一致率，最多比较 40 局，每局最多 2 个位置，每候选 4 个随机未来。示范起点会恢复原存档和指定决策点，再重抽记录的未来，保留学生前缀历史。排序比较会产生新的分叉终局标签，全部位于后台空档内。

判定固定写在代码：总体 Brier 必须严格下降，成对一致率必须严格上升。每个窗口中出现的地形至少有 8 个独立校准种子、4 个独立排序种子及 16 对有效候选。任一区 Brier 退步超过 0.02，或成对一致率退步超过 0.03，均否决。小于该上限的退步若超过 1.96 个配对标准误，同样否决，标准误按种子聚合。缺少有效比较数据时保留在役网。每次决定写日志和 `value/decision.json`，应用结果另写 `value/activation.json`。

只有前台组边界的 `poll()` 能换在役网，当前采集进程一直沿用启动时的路径。切换时保存 `previous_value`，启动时用 `--value-rollback` 交换回上一版，检查点保持原路径不覆盖。历史作业的比较基准已经变化时，候选不再激活。学生挑选记录 `selection_value`，门禁合同保留冻结的价值网路径和 SHA256，价值网在其他组换版不会改变进行中的门禁基准。

### 监测

`--value-retrain` 自动启用监测，也可单独打开 `--value-monitor`。每个搜索点记录最终带锚选择的候选叶值均值，涵盖复核后的值与攒阳光候选，不取未被采用的裸最高分。这是现有推演分数的记录，不增加推演。已终局分支仍使用真实结果，分数口径与搜索一致。

档案逐点保存 `selected_leaf_value` 和该标签是否真正执行。对局结果分别累计全部搜索标签与真正执行的标签，按价值网版本逐轮汇总，`round_N/value_monitor.json` 包含均值、实际胜率与 Brier，并给出预测减输赢的误差。每局等权。连续 3 轮、每轮至少 8 局、同版价值网在实际执行标签上的平均误差均大于 0.10 时写警告。DAgger 未执行的标签单列，不触发这一警告。

### 耗时与启用条件

本任务只运行 Mac 小测试，没有运行真实规模训练或生产对局。按上述上限估算，读取与编码约 3–10 分钟，热启动训练约 2–10 分钟，排序分叉约 5–25 分钟，合计约 10–45 分钟。关卡终局长度和存档体积会影响实际时间，不能把这个估算当成 GPU 实测。作业统一设 2,700 秒预算，且 CPU 空档提前结束即取消。取消检查约每 2 秒一次，必要时等待 5 秒后强制结束进程组，后续学生训练只需等这一清理过程。预计可容纳于任务书给出的 1–1.5 小时空档，超出时否决并保留原版。

启用前仍需 task154 的地形校准 / 老师失败归因结论，并在允许的真实 GPU 空档测一次吞吐和有效比较覆盖。本次开始与完成前查询远端均没有 `vstale` 分支，尚无可读取的 task154 结论。没有连接台式机，没有部署，没有上传检查点或对局数据。

相关小测试合计 12 项通过，均逐次使用 `-k`、`timeout 300` 和 `ulimit -f 2000000`。覆盖默认关闭、训练后排队、CPU 重叠、空档让出、换 / 不换、组边界切换及回退，也覆盖示范未来种子、起点恢复和持续乐观监测。原有价值网行存储用例继续通过。
