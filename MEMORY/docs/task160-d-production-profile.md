## 瓶颈排序（按影响）

1. **分母陈旧。** 每轮只新增 0.4–2% 的行，包 98% 是旧数据；63.6% 的标签出自 v5 之前的老师。
   任何新格子（示范、随机卡组）都会被 1365 万行的历史块稀释 —— **不先给旧块降权，新数据永远追不上**。
   → 对照实验：`label_weight` 对 33 个 `z*` 历史标签从 1.5 降到 0.5（L7 有效占比 51.1% → ~29%）。
2. **卡组单一。** 82% 的行压在 32 套关卡默认卡组上，一套占 45%；task129 的 54 套 v5 卡组在训练里 0 行，
   随机卡组格只有 0.5% 的行。这是“没见过陌生卡组”的直接来源（老师与学生在挑选里都只会打见过的牌）。
3. **采集预算错配。** r42 起 75% 的局给了屋顶示范起点：教师胜率 88.7%、每局 96 行、1.4 s/局。
   时间上很便宜，但**行数上只买到 3.6%**，且这些行来自已经赢下来的局面（信息量最低的那一类）。
4. **门禁成本翻了 5 倍且通过率低。** v5 门禁 89–93 min/轮（v4 时代 8–19 min），11 次只过 3 次；
   屋顶 90 对永远是 0–9%，雾夜 405 对里波动 38–54%，**这两个区花掉约 1/3 的门禁时间却几乎不产生判别力**。
5. **训练拖住轮次。** 45 个轮次只有 14 轮训练完；训练中位 3.8 h/轮，比采集（1–2.4 h）长一倍，
   轮次每 1.5–2.5 h 就新开一个 → r30–33、r37–38、r40、r43 有 recipe 没有模型。
   显卡只忙 62%，说明瓶颈是训练的数据加载/CPU 侧，不是 GPU 算力。
