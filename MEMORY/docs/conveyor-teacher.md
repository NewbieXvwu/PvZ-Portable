# 传送带关搜索老师诊断

## 结论

传送带牌已经进入生产老师的候选集，推演过程中的发牌与真实续走逐 tick 一致。L30 的全合法候选反事实仍为 0/16，L50 也仍为 0/16，因此“老师几乎不改学生动作”主要落在传送带局面上的叶值尺度、学生覆盖与关卡推进压力，当前证据不支持候选漏项或推演发牌错误。

## 四种可能

### (a) 候选集缺少传送带牌

第1步的计数显示，L30、L40、L50 的候选中传送带牌分别占 83.34%、81.59%、81.31%。L30 的全合法候选配对实验中，基线与反事实都是 0/16，16 局状态哈希完全相同。L40 的既有反事实则从 6/16 提升到 15/16，说明全合法候选机制本身能救回确实被候选过滤掉的关卡，但它没有救回 L30 或 L50。

### (b) 静态网或叶值无法区分好坏

L30 的睡莲动作在全候选排序中的位次中位数为 119，叶值中位数为 0.00074。扩大候选集后仍一张睡莲都没有种，说明动作即使进入搜索，也没有得到足够高的续走评价。第1步还记录到 L30 的 top1−top2 平均差仅 0.01036，候选标准差仅 0.01848。L50 的全合法反事实同样没有胜局，且只有 6/16 局状态改变，表明改变动作后仍缺少稳定的可赢边界。

### (c) 推演与真实传送带发牌不一致

第2步从 L30 的三个决策点各走 3000 tick。真实续走与 C++ 推演分别得到 51、50、50 个共同观测 tick，三组传送带牌序列差异均为 0。当前没有推演发牌错位的证据，生产代码无需为此增加兼容分支。

### (d) 局面本来就难以挽救

L30 在候选补全后仍为 0/16，末波均值保持 9.06。L50 在候选补全后仍为 0/16，终局 Boss 体力范围只发生小幅变化，6 局状态改变也没有转化为胜局。两关都保留了原生传送带发牌和空槽开局，失败不能归结为固定卡组覆盖问题。L50 还包含 Boss 的持续召唤与其他终局压力，现有样本支持“局面推进压力很高”，不足以把某一个 Boss 动作单独定为根因。

## 处理决定

不在生产里强行加入全合法候选，不修改静态价值网，也不改任务语义。后续修复应沿学生数据、搜索标签与价值边界继续验证，先解决 L30 的水路动作评价，再单独评估 L50 的 Boss 终局覆盖。
