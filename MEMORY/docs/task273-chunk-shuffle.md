# task273：训练分块打乱

2026-11-18，`fix273`，基于生产 `35fce2c1`。未部署，生产采集、训练和配置未修改。

## 设计

在现有 `BatchSource` 中按 CSR **物理行**每 65,536 行切块（对齐 32 行压缩块），每轮随机打乱块序，最多 **64 块 / 4,194,304 行**组成一个窗口。窗口数向上取整后均衡分块，防止末窗只剩一两块。连续复制 board/scalar 压缩块、packet 列和 candidate 区段到窗口内存，再逐行打乱、切 batch，继续调用原 `prepare()` 与 C++ 解码器。保留压缩载荷，不展开整窗稠密棋盘。本样本每窗约 43 块、约 0.65 GB 读入，64 块约 1 GB。

连续区段先发 `MADV_SEQUENTIAL/WILLNEED`，复制后发 `DONTNEED` 并恢复 `RANDOM`。窗口内随机读访问自有副本，整个语料无需常驻页缓存。沿用有界批次预取线程，提前结束时关闭生成器以释放窗口。跨窗保留不足一批的物理尾行，只有整轮最后一批可不足 batch_size。

每轮种子来自训练既有的 PyTorch 随机状态，窗口内使用独立 NumPy 生成器。有效训练行每轮恰好访问一次，标签与样本权重逐值保留，验证取批路径不变。未增加训练配置或第二套解码实现。

## 正确性与混合程度

Mac 定向测试共 8 项通过。新增用例覆盖普通 / 共享存储，包含物理追加顺序与逻辑顺序不同、CSR 段尾填充及验证行排除。逐批比较棋盘、标量、标签、权重、packet、candidate 和辅助目标的原始字节，覆盖固定种子复现、换种子改变顺序及每行恰好一次。已有两轮训练逐位一致性测试通过。真实样本的全部 **7,568,121 条训练行**也逐行计数，遗漏和重复均为 0。

真实样本包含 2,095 个 segment、228 个任务族（按元数据 `task.task_id/id` 分组）。每批 2,048 行，旧方案取 256 批全局均匀随机样本，新方案统计全部 3,696 批。KL 为每批任务族频率相对于全部训练行频率的 `D_KL(batch || corpus)`，使用自然对数：

| 批内指标 | 原全局打乱 | 分块打乱 |
|---|---:|---:|
| 不同 segment，均值 / 5 分位 | 1,147.36 / 1,124.75 | 578.29 / 555 |
| 不同任务族均值 | 160.21 | 134.33 |
| 任务族 KL，均值 / 95 分位 | 0.04505 / 0.05279 | 0.15820 / 0.18838 |

百万行窗口从随机分散的数十个物理位置取样，每批仍混合上百任务族，足以打散连续对局的时间邻近关系。有限窗口带来可测的批次相关性：本样本任务族种类减少约 16%，KL 增加 0.11315。全轮样本配比保持精确一致，但这些数字不能证明学习效果与全局独立抽样等价。本次未做长训练，正式效果由生产候选门禁决定，打不过现任即否决。

## 冷缓存与内存受压速度

台式机只读生产 shared-v2 的完整 segment 前缀，复制 **8,402,318 行 / 2,129,936,116 字节**到 `~/pvz-logs/task273/sample/`，按种子留出约 10% 验证行。两种方案使用相同副本、行集合、batch_size=2048 和 4 个原生解码线程。每次开始前仅对实验副本发 `POSIX_FADV_DONTNEED`，未清全局缓存。单进程、最低 CPU/I/O 优先级、虚拟内存上限 8,000,000 KiB，独立服务限制 `MemoryMax=2300M/MemorySwapMax=0`，两组均触发内存回收，OOM 为 0。启动前系统可用约 13–14 GiB。

计时包含行排序、随机排列及全部窗口读取 / 复制，完整执行原 `BatchSource.prepare()`，不含 GPU 计算和锁页复制。旧方案采样 524,288 行以控制实验耗时，新方案完整走完全部训练行：

| 指标 | 原全局打乱 + MADV_RANDOM | 分块打乱 |
|---|---:|---:|
| 计时行数 / 批数 | 524,288 / 256 | 7,568,121 / 3,696 |
| 总秒数 | 67.941 | 148.347 |
| 批 / 秒 | 3.768 | 24.915 |
| 物理读入 | 2.418 GB | 1.946 GB |
| 每百万行物理读入 | 4.611 GB | 0.257 GB |
| 每百万行主缺页 | 1,106,142.04 | 4.23 |
| 平均 CPU（单核=100%） | 77.8% | 283.8% |
| 按 67,364,442 行外推取批秒数 | 8,730 | **1,320** |

吞吐提高 **6.61 倍**，单位行物理读入减少 **94.4%**。分块路径总计仅 32 次主缺页，窗口内连续数百批读盘字节不再增长。最大进程 RSS 为 **1.78 GiB**，整份实验数据约 1.98 GiB，另有训练元数据与窗口副本，结果来自受限内存下的顺序读取。

**约 1,320 秒是上述规模的取批外推，达到约 1,300 秒量级；全量 GPU epoch 端到端时间尚未实测。** 原始数值与实验脚本保留在 `~/pvz-logs/task273/`，实验数据副本已删除。正式部署由主控执行。
