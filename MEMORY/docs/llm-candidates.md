### 解读

1. **效果：96 对配对里胜负完全相同，末波逐对差全部为 0**（exact paired binomial p=1.000）。白天两臂 16/16 胜（末波固定 30，本来就没有提升空间）；屋顶两臂各 13/16（3 对败局在 wave 20/17/11）；雾两臂各 0/16（wave 7–10）。屋顶与雾的败局本来是可移动的观测，加 LLM 候选后一对都没移动。
2. **剂量很低**：312 次请求 / 144 局（2.17 次/局；白天 B_low 已打满 4 次/局预算），749 条建议全部通过引擎合法表（非法/畸形/超额/重复均 0）；510 条"仅 LLM 新增"里只有 8 条被最终复核采用（1.6%），9/96 对局至少改了一个决策。其中 roof B_low 52001000 的差异不是建议被选中，而是追加候选改变了平局/顺序裁决——这是"合入候选集"的固有副作用，解读时必须计入。
3. **被采用的建议只是略优**：8 次的叶值优势 0.0202–0.0836，都刚过 0.02 门槛，没有出现"老师漏掉的大动作"。
4. **单步反事实与整局不一致**：roof B_novel 8 对单步终局里出现 +4、+13 波，但同种子整局的末波差仍是 0。再次说明单步学生续走不能替代整局配对（预登记已写）。
5. **雾区提议组成**：合法建议只有阳光菇 63/105、坚果 20、土豆雷 19、睡莲 3（B_low）与阳光菇 60、土豆雷 11、坚果 5、睡莲 1（B_novel）；开雾植物（22 火炬树桩 / 25 路灯花 / 27 三叶草）与磁力菇/仙人掌/高坚果全部为 0。合法性过滤只放行卡组内动作，f8 里根本没有这些卡——这一项只能说明"现有卡组内 LLM 不提开雾/对策"，不能否定换卡组后的对策先验。
6. **费用**：正式 277 次 API 请求（另 1 次协议冒烟）、2 次失败重试、1,322,163 token（prompt 1,101,840 / candidate 28,185 / thought 192,138），约 9,181 token/局、1.92 次请求/局；312 次事件中 37 次命中缓存、未重复请求。网关没有可核验单价，金额未知。

### 结论与建议（主控决定是否采纳）

**不接进正式路径。** 就"提高现有老师的胜率"这一目标，本原型收益为 0（96 对配对、0 个胜负变化、0 个末波变化），成本约 9.2k token/局、最多 4 次/局延迟。16 局/场地当然不足以证明"LLM 一定帮不上"，但采用率只有 1.6%、被采用的建议叶值优势都在 0.02–0.08 的边缘，在没有看到任何配对改善之前把它接进关键时刻宽搜索，只会先付出成本与不确定性。

**这也不能否定"LLM 知道对策"这个假设**：实验没给它机会。f8 卡组不含开雾植物与四种对策卡，白天/屋顶卡组也不含对策卡，模型只能从引擎合法表里选，而合法表里没有它该建议的东西。要检验对策先验，必须换任务族（对策卡进卡组），那是主控权限内的决定，不属于本次原型。

若继续，按性价比排序：

1. **换卡组的对策局**（f9/f10 或对策练习局，新任务族）：同一模型、同一触发，主指标加"建议里对策卡的比例"。这是唯一能直接检验用户 10-23 那个问题的设计。
2. **提高剂量**：白天已打满预算仍只采用 1 次，瓶颈不是次数而是"建议与老师候选高度重叠"；可试更窄的触发（真正的新僵尸行且学生首选为等待），先离线统计命中率再上局。
3. **离线价值**：把 LLM 建议只当候选池扩充用于采集/诊断（不影响对局裁决），成本可控，可作数据增广。
4. **不要放宽 0.02 margin**：那会改变老师的裁决标准，等于换老师，不能归因给 LLM。

16 局/场地只是可行性测量，以上都不是非劣或泛化声明。
