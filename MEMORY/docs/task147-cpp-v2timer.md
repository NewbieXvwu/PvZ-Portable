# task147：C++ 采集器支持 v2timer 输入（第 9 号输入版本）

主控 2026-10-28 定。分支 `obstimer`，在 task145 之后继续。

## 背景

task145 在 Python 侧加了 v2timer（v2sleep 加 4 个棋盘通道：引爆/唤醒进度、状态进度、传送带卡序、传送带就绪）。但 C++ 单进程采集器没有对应的输入版本，`export_student` 遇到 v2timer 会显式报错。这样 v2timer 训出的学生上不了生产采集。

## 要做的

1. C++ 侧加第 9 号输入版本，编码与 Python v2timer 逐位一致（通道顺序、归一化、雾里未知 = 0）。
2. `export_student` 支持导出 v2timer 学生。
3. 对拍：在几个构造局面和一局真实对局的若干帧上，Python 与 C++ 编码逐位相同。只跑这一项相关测试；台式机测试限内存（`ulimit -v 8000000`，先看 `free -g`）。编译用现有构建脚本，不动生产二进制。
4. 冷缓存重编码 7–15 h 太慢。给一个可行的提速方案并估算，例如复用 v2sleep 的段只补 4 个新通道、多 worker 并行。实现与否看改动量，小就直接做。

## 约束

- 不训练、不部署、不碰 qc / 状态文件 / 看门狗 / `~/pvz-logs/qc_deploy*.sh`，不替换生产二进制。
- 不加自校验或哈希检查。
