# task58：记忆值多少——不靠胜负，直接量"能否推断出雾里的僵尸"

> 主控 2026-10-24 08:10（台式机时间）写。执行者：台式机 Codex（plus 账号，09:51 额度恢复后开 `codex-mem`）。工作树 `/home/newbiexvwu/PvZ-search/.claude/worktrees/memprobe`（分支 `memprobe`，从 pvz-env 拉出）。最多 2 个游戏进程；GPU 训练每次不超过 1 小时，开始前 `MemAvailable` ≥ 10 GiB；**不碰 tmux `qc`**。

## 为什么
- 用户 10-23 问过：模型能否理解"雾回来了，所以现在看不到僵尸"。主控的回答是：现在的学生只看当前一帧，没有记忆，所以不能。计划是先用"最近 K 帧堆叠"测记忆值多少：值得，再做 ConvGRU 与空间状态空间模型（SSM）的预登记对照（计划文档 2026-10-23 21:15）。
- task45 追加 B 做了堆叠对照：无记忆与 K=4 都是 **0/256 胜**，全败地板下测不出任何差别，记忆线因此卡住。
- 胜负信号要等雾区能赢之后才有，取决于人类示范和价值网。**换一把不依赖胜负的尺子**：记忆的作用是保留看不见的信息，那就直接量模型能否从观测历史里推断出雾中僵尸的真实位置。

## 要做的
1. **数据**：用雾区已有档案（task45 的冷启动、诊断、追加 E 的局，human 观测臂），必要时补采，≤2 进程。
   - 每一帧取两样东西：
     - 学生可见的观测（雾中已屏蔽）；
     - 引擎真状态里雾中僵尸的格占用（`PRIV.hidden` 或等价的诊断字段，**只作为标签，不进策略输入**）。
   - 按局划分训练 / 验证 / 测试，不同局不混。
2. **四种结构，同一任务、同参数量级**：
   - 输入都是学生现有编码（v2fog）；
   - 输出是雾中每格"有没有僵尸 / 什么类型"的概率；
   - 结构：(a) 只用当前帧；(b) 最近 K 帧堆叠（K=4、8）；(c) ConvGRU（格子级隐状态，按 tick 间隔喂）；(d) 空间 SSM（ConvS5 一类，Δt 直接用 tick 间隔）。
   - 参数量对齐，写清各自的单步推理开销（CPU，batch=1），为以后进 C++ 续走做准备。
3. **指标**，都在测试局上报：
   - 雾中格占用的 AUC 与 log-loss；
   - 按"距该格最后一次可见的时间"分桶：刚被雾盖住 / 几百 tick / 更久；
   - 三叶草回雾事件前后的对比；
   - 透视臂的上限：同结构输入真状态。
   - 关键问题：**记忆结构能把"只看当前帧"到"透视"之间的差距补回多少？**
4. **结论**：
   - 若 (b)(c)(d) 在回雾后明显好于 (a)：记忆有价值，按差距与开销排序，建议进入学生的是哪一种；
   - 若差别很小：说明雾区瓶颈不在记忆，写清楚。
   - 结论写 `MEMORY/docs/memory-probe.md`。**主控决定是否进学生。**
5. 只做探针，不改学生、不改生产、不加开关。
