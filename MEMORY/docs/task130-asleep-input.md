# task130：蘑菇“睡着”状态进模型输入（与 L45 v2bungee 合并成一个新输入版本）

主控 2026-10-27 派给 Mac codex-plus2。分支 `sleepinput`，基于 `origin/pvz-env`（已含 task116 的 `v2bungee` / 价值编码器 v3）。

## 背景

- 卡组规则 v5（`MEMORY/docs/deck-rules-v4.md` 末尾）解禁白天蘑菇，靠咖啡豆唤醒。引擎观测已导出植物 `asleep` / `wake_up_counter`（`src/LawnApp.cpp` 约 2432 行），但学生与价值网特征没用它：棋盘上醒着 / 睡着的蘑菇对模型完全一样，价值估计会错；只有合法动作掩码间接暴露“哪格能放咖啡豆”。
- 屏幕上能看到睡眠状态（头顶的 Z），属于可见信息，按“先补可见输入”的原则补上（`MEMORY/notes/student-architecture.md`）。

## 要做的

1. 在 `v2bungee` 之上新增输入版本（例如 `v2sleep`），棋盘加一个“植物在睡觉”通道（可另加一个“正在被唤醒”通道，用 `wake_up_counter > 0`），贯穿完整 / 精简观测、紧凑帧、Python / C++ 学生与价值输入（价值编码器 v4）。雾中隐藏的植物遵守现有遮蔽。旧版本逐位不变。
2. Python / C++ 对拍：白天关种蘑菇 + 咖啡豆的小样本局面，逐 float32 一致。
3. 训练接入：配方可选新 obs，打包能产出训练行。
4. 写清上线需要什么（引擎重建、生产配方切 obs、价值网是否重训），以及与 deploy14h / 14i 的先后关系。不部署。
5. AGENTS §6.5：只跑相关测试；**台式机上测试必须限内存**（§6.5 第 7 条，今天 12:09 刚因测试 OOM 停采）。结论写在本文件末尾，推送分支。

## 实施结果（2026-10-27）

主检出已执行 `git pull --ff-only`，从 `origin/pvz-env` 的 `426be576` 建立独立工作树与分支 `sleepinput`。本任务完成输入与训练接入，未部署，也未操作台式机 qc。

### 新输入与兼容

学生新增 **`v2sleep`**，原生观测编号 **8**，引擎能力号 **`rollout_version=6`**。它完整继承 `v2bungee` 的蹦极与 Boss 信息，再追加“睡眠”和“唤醒中”两个棋盘通道。睡眠取公开 `asleep`，唤醒中取 `wake_up_counter > 0`，两者均为 0/1，同格多植物取最大值。学生棋盘为 **113×6×10**，标量仍为124维，带任务上下文为159维。

价值网新增 **编码器 v4**，检查点标识为 `pvz_value_net.featurize v4`。它在编码器 v3 后追加同样两通道，棋盘为 **100×6×10**，标量119维，带任务上下文为154维。新引擎继续读取旧学生及价值模型，旧版本特征与检查点维度保持原样，旧学生缓存签名包括 `v2bungee` 原签名均保留。

完整观测继续使用植物的 `asleep` / `wake_up_counter` 字段，精简观测在原植物六元组末尾追加这两项。紧凑帧保留原五元组 `plants`，另存 `sleep`，每项为 `[row,col,asleep,wake_up_counter]`。雾中被遮蔽的植物公开 `asleep=false`、`wake_up_counter=-1`，两新增通道为零。C++ 学生和价值网共用遮蔽后的睡眠特征入口，暴风雨和压扁植物继续沿用现有可见性限制。

旧紧凑档案没有 `sleep` 时，新通道为零。旧完整观测若保留了睡眠字段，可以重新压成新紧凑帧。已经丢失字段的紧凑示范需要用新引擎重放生成帧，后续采集直接保留新字段。

### 训练与验证

训练配方和打包命令可选 `obs=v2sleep`，已用一个微型数值档案验证配方到缓存、训练行及学生前向计算的完整路径，两个动作头均能使用新输入。价值训练器可选 `--encoder-version 4`，检查点读取和原生导出同步支持该版本。生产配方的默认值保持不变。

Mac 独立引擎已用 Release 构建完成。相关 **13项测试通过**，包括旧版本输入逐位保持、睡眠通道与打包，以及既有 L45 蹦极对拍。白天第7关实际种下小喷菇，再使用咖啡豆，分别取睡眠、唤醒中与醒来后三个局面，完整和精简观测压成的帧相同，Python/C++ 学生全部棋盘与标量、价值网全部输入均逐 float32 位一致，预测输出比较通过。第31关另外验证雾中字段遮蔽及两新增通道的双端一致性，现有精简观测遮蔽用例也通过。测试均在 Mac 上运行，没有启动训练或完整胜率评估。

新增测试为 `python/test_sleep_inputs.py`。实现涉及 `src/LawnApp.cpp` 的观测、两套原生网络及其版本加载、Python 两套编码器和导出器，以及 `render_episode.py` 的帧保留。训练入口改动限于配方与打包的版本选项、价值训练的版本选项和缓存签名。

### 上线顺序

**deploy14h / deploy14i 可先按各自任务上线。** 它们处理挑选、训练调度及门禁，本任务无需改变其参数，也未修改两个部署脚本。`sleepinput` 应作为后续独立输入升级，合并后先重建采集与推演所用引擎，再生成含睡眠字段的训练数据，最后将新训练配方的 `obs` 切为 `v2sleep` 并重训学生。旧学生不能只修改配方标签直接当作新版本使用，首层输入通道数已变化。

现役价值网可继续运行，但无法利用睡眠通道。要启用新价值输入，需要用 `--encoder-version 4` 重训、导出并按现行验证流程切换权重。生产学生或价值权重的切换均由主控另行安排，本分支只交付代码与本次对拍结果。
