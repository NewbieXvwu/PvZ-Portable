# task121：关卡再平衡改为温和版（幂次 + 倍数上限）

主控 2026-10-27 派给 Mac CodeBuddy（cbp-task121）。分支 `rebalance2`，基于 `origin/rebalance`（7592889a，deploy14g 在役代码）。

## 问题

deploy14g 的 `source_weight.level_balance`（`python/pvz_training_rows.py` 约 30–67 行）按行数**完全反比**加权，结果各关有效份额几乎相同（第 21 轮：L7 948 万行，份额 2.0%、倍数 0.035；L40 只有 276 行，倍数 1190，份额 2.3%）。几百行的关被放大上千倍，梯度被极少样本主导，噪声大。

## 要做的

1. 配方加两个可选参数（缺省时行为与现在逐位相同）：
   - `source_weight.level_balance_power`：p ∈ [0,1]，质量 = 原权重 × inverse_rows^p。p=1 等于现行，p=0 等于不再平衡。
   - `source_weight.level_balance_max_multiplier`：每关训练行倍数的上限（超出部分不再分配，总训练权重可以因此略小于原值，日志记下）。
   - 25% 封顶逻辑保留。
2. 新配方 `recipes/dw4i2_rebalanced_p05.json`：在 `dw4i2_rebalanced.json` 基础上 `level_balance_power: 0.5`、`level_balance_max_multiplier: 20`。不改旧配方文件。
3. 单元测试：缺省逐位不变；p=0.5 时用第 21 轮 `level_shares.json` 的行数（在台式机 `~/pvz-logs/curriculum_state.pipeline/round_000021/seeds/seed_000002/student/level_shares.json`，可 scp 一份到测试夹具，几 KB）算出份额表，写进报告。
4. 只跑相关测试（AGENTS §6.5）。不写部署脚本，不动台式机 qc。推送分支，结果写在本文件末尾。

### 实现

`python/pvz_training_rows.py` 把第 21 轮算过的份额计算抽成模块函数 `balance_levels(levels, cap, power=1.0, max_multiplier=None)`，
`SourceRowCounts.rebalance()` 只负责统计行数、调用它、再把倍率乘回训练行。

- 质量 = `original_weight × inverse_rows^p`，p=1 走 `inverse_rows` 本身（不做幂运算），逐位等于 task119。
- 25% 份额封顶的注水循环原样保留。
- `max_multiplier` 在份额算完之后截断倍数，被截掉的部分不再分配；报告里多出
  `total_weight` / `allocated_weight` / `allocated_weight_ratio`，被截断的关另有 `multiplier_capped_from`。
  缺省时 `allocated_weight == total_weight`、比值恒为 1.0，其余键与 task119 完全一致。

`python/pvz_recipe.py` 放行两个新键并校验：`level_balance_power` ∈ [0,1]，
`level_balance_max_multiplier` > 0，两者都必须与 `level_balance` 同时出现（否则是静默失效的坑）。
`scripts/train_rollout_policy.py` 把两者透传给 `rebalance()`。

新配方 `recipes/dw4i2_rebalanced_p05.json`：`level_balance: 0.25`、`level_balance_power: 0.5`、
`level_balance_max_multiplier: 20`，`out` 改为 `artifacts/student/dw4i2_rebalanced_p05`。
语料、卡组、`wait_keep`、缓存路径与 `dw4i2_rebalanced.json` 逐项相同（测试里断言），旧配方文件未改。

### 读表

- **p=1（task119 现行）**：46 关份额全挤在 1.4%–6.7%。绝对份额均匀，但 L30/L40/L50
  分别只有 364 / 276 / 276 行，却被放大 903 / 1191 / 1191 倍，梯度里相当一部分能量来自
  极少数样本。
- **p=0.5**：L7 从 2.04% 回到 19.47%（它本来占 58.9% 的原始权重），L9/L10 各 6%，
  千行级小关降到 0.1%–0.7%。倍数区间从 0.035–1191 收到 0.33–61.3。
- **p=0.5 + 20 倍上限**：只有 L30/40/45/47/50 五关被截断，总训练权重损失 0.41%。
  这一档的实际作用是给「几百行的关」硬设一个天花板，p=0.5 本身并不会把 L40 拉到 20 以下。
- 25% 封顶在 p=0.5 下不触发（最大份额 L7 19.47%）；p=0 时才触发（L7 原始 58.9%）。
- 取舍点：p=0.5 把最大份额重新交回 L7（近 20%），换来的是小关不再被上千倍放大。
  若下一轮发现 L7 又主导梯度，应当调 p 而不是调上限——上限只管小关的天花板，管不住 L7。
