# 关键时刻终局分叉：task53

## 实施方案（实跑前登记）

统一入口为 `scripts/critical_forks.py`：读取冻结的档案、重置上下文及1起决策序号；前缀执行档案真实动作，在选点恢复学生历史、阳光收入历史与引擎状态，对全部引擎合法种植、铲除及等待动作接同一冻结搜索老师至真实终局。每个根的候选共享随机世界和老师搜索噪声，筛查与确认的未来分离。中断不计败局。

实现参考 task45 E 的全候选/共同未来/重放验证、task46 B 的静态候选与halving审计、task43第二轮的真实老师终局循环；fog/roof/v5工作树只读。采集实现只有一份，场地差异由档案与任务上下文表达，不改生产搜索和qc。

先冻结最近完整qc轮的白天、夜间各8场输局。最近完整qc轮没有泳池组，泳池暂取最近p9k老师采集的8场输局，来源差异单独报告；不把它们称作qc当轮泳池局。名单、档案与模型哈希在运行前冻结。所有引擎使用任务书指定的deploy3可执行文件。

选点只读档案事实：破防事件（割草机首次触发或败局终结）之前的N个决策，以及已记录候选叶值最大分差低于0.02的决策。参数控制N、平坦点数量、距终局窗口和每局上限，逐点保留入选原因。先检查前缀与合法候选，再用三场地试点计时；超过15%qc采集CPU的预测值时，只按成本收紧选点，不裁候选、不读取候选终局标签决定取点。

结构检查后的v2登记将两类点拉开：破防前第16个决策，以及末6000tick内平坦点的中位点；共47根。初始543条标签只读CPU作计时，未用其终局结果改取点；原试点保留但不并入v2结论。旧泳池档案的平坦性来自其原v3叶值，来源字段明确保存，所有正式排序对照均重新计算v4，不能把旧v3评分称作v4。

筛查每候选3个共同未来；筛选出的一个动作与学生原动作再接16个独立共同未来。终局胜率、末波、终tick、丢车分别记录，不混成手写战斗评分。纠正只在独立确认支持改善时输出，显著性按全部确认比较校正；置信度从配对差值的bootstrap得到。铲除标签保留在原始证据和价值数据中，学生当前无铲除输出，不能伪装成等待标签。

学生导出保留真实前缀与动作历史，通过档案元数据的精确训练行清单只保留纠正行；置信度使用现有label_weight接口。价值导出保留同根/同未来的候选分组、真实老师路径叶状态及终局胜负，兼容task43的decision-data字段。正式2500tick学生叶值另作v4排序对照，不能把它与真实老师路径混淆。

小规模微调配方、固定回放语料和同种子评估面板在标签产出前登记。初始化dw4i_s1，训练器与架构沿用现有实现；与冻结dw4i_s1在对应关面板配对评估，报告差值和区间。这个可行性试验不触发上线或换学生。

成本按父进程、worker及其游戏子进程实际CPU计量；qc基准优先使用只读metrics积分并明确测量缺口，折算768局/轮。自有游戏进程最多4，原始产物限5GB；结论层入git，检查点/分片/日志保持忽略。后续报告补充实测、训练与后台流水线接入建议。

## 结果

统一数据链已完成实跑：24局、47点、3241个合法候选、9723条筛查终局标签，12点另作16个独立未来确认，共384条确认标签；7/47点（14.89%）输出可训纠正。白天2点、夜间1点、泳池4点，动作全为种植。确认按48项比较作Holm校正，不把筛查最优直接当标签。

本次固定微调未得到“胜率不降”的证据：192对中原学生76胜、微调75胜，净差−0.52个百分点（95%配对区间−5.69至+4.65个百分点）；白天少4胜、夜间多3胜、泳池均0胜。3072旧行加7新纠正确实进入训练，7条新行全部在训练集，24次优化改变21个参数张量；但回到7个纠正根时，新学生0/7转向确认动作。因此这里只验证了采集→标签→训练→评估链可用，未观察到这次微调形成期望的纠正。保持生产学生，下一次训练方案由主控决定。

训练注册保留2epoch和64步上限。严格训练器要求max_steps不超过自然步数，执行配方只按min(64,2×ceil(2823/256))解析为24步；原注册文件与其他超参、回放/评估种子逐键核验不变。较早的schema问题也只修复描述性provenance字段，没有借失败调参。

## 后台流水线建议

每轮768局结束，冻结games/档案、学生与搜索老师SHA，按破防窗口和平坦点选点；对候选数预估费用，用本轮实际采集CPU的15%作硬账本。未知点价时先用最贵点配额，按确定性reservoir选择输局，不能处理所有输局根。

计量按阶段分账：分母只用该轮qc采集的进程树CPU；分子收齐终局采集器及已回收游戏子进程的累计CPU，不能把并发pack/train增加的CPU混进分母扩大预算。完整根成功后才发布，测到点价变贵就减少后续根数，保留所有合法动作及独立确认未来，不靠空面板或半截分叉达标。

终局采集在独立4槽后台队列中运行；完整根和独立确认通过后，原子发布export清单。学生纠正档案作为新增不可变label段，confidence进入label_weight；task49 pack→train队列冻结新增清单和权重，继续保留同种子换学生门禁。价值分片按kind分组送task43，保留seed/position/candidate与原始终局证据，不把真终局状态训练成叶值。

采集、确认或打包中断时保持原学生；预算/5GB门禁停止后不得把未完分叉计败局。正式上线前须补齐统一qc泳池来源与当时部署引擎的混合轮CPU测量。这里的192对是小规模可行性面板，不签发上线证书。主控决定是否上线。
