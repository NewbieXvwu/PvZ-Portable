## 开跑前登记（2026-10-26）

选择按 `select_student.py` 既有口径：C++ greedy fast，全部任务总胜局最多者胜，同分按候选路径稳定排序。独立面板含 day L7 d7、heldout L7 d7p1、night L12 n10、pool L21 p9k、fog L31 user snow（human）、roof L41 r7，各 32 局。保持原任务语义，只换种子；独立保留块 [120000000,120006000)，六任务分别取块内每 1000 槽的前 32 个。种子审计产物必须在模型评分前生成。评分后不根据 A/D2/C 的结果挑换种子。

离线模型冻结为 task84 已训好的 A、D2、C，复制到本任务忽略目录，源权重只读。先在上述面板上比较，再与已知 heldout 192 局结果 A=124、D2=169、C=135 核对排序。若不能选中 D2，照实报告，不用已知评估结果偷偷改评分。

K 优先考虑 2；最终由 GPU 单训/双训测量决定。新任务默认多种子，历史已入队的单种子任务按原配方恢复。训练失败的候选单独记错，仍有成功模型时继续挑选；全部失败才交原 B7 重试流程。门禁模块与合同不改。

## 离线验证（A / D2 / C，冻结面板 6 区 × 32 = 192 局，fast 臂）

| 候选 | 面板总分 | 面板排序 | heldout 192 局 | heldout 排序 |
|---|---|---|---|---|
| A（seed1 重训） | 144 | 3 | 124 | 3 |
| C（r11 续训） | **148** | **1** | 135 | 2 |
| D2（seed2） | 147 | 2 | **169** | **1** |

- 预登记判据“至少选中 D2、不选 A”：**A 未被选中（√）；D2 未被选中（×，被 C 以 1 局反超）**，照实报告。
- 分区饱和：day 30–32、fog 30–32、pool 27–31、roof 0–3 → **6 区中 4 区接近天花板/地板**，区分信息几乎全部来自 d7p_holdout1（极差 7 局）与 pool（4 局）。
- 每局面板总分的逐局二项 sd ≈ **3.4–3.7 局**；C−D2 实际差距 1 局 ≪ 1σ，属抛硬币。20k 次按观测胜率 bootstrap：P(再次选出 C 而非 D2) = 0.62，P(argmax ≠ D2) = 0.67，P(A 不是垫底) = 0.34。
- **K 增益蒙特卡洛**（候选真实质量 ~ task84 四次同源训练 {166,124,169,135}/192 经验分布，面板 192 局二项量测）：
  - K=2：E[选中−平均候选] = **+10.1** heldout 局，P(选中真实最优) = 0.94。
  - K=3：**+14.8** 局，P(选中真实最优) = 0.90。
  - 叠加 0.10 量测噪声（面板↔heldout 衰减的保守补偿）：K=2 +8.0 / 0.85；K=3 +11.8 / 0.77。
  - K=3 的 P(选对) 反而低于 K=2：候选质量分布重尾（124 与 166/169 两团），第三抽常抽到弱候选；K=2 性价比更高。

## 结论与移交主控

1. **方案采纳**：一轮 = 打包一次 → K=2 种子串行独立训练（单种子失败只记 failed.json 不连坐，全失败才走 B7）→ 冻结面板挑选 → 仅选中者进原门禁。测试 72 passed，实现与测试已入 multiseed 分支。
2. **面板需加局**：4/6 区饱和，1 局级差距不可分。要提高区分度，优先给 d7p_holdout1 与 pool 加局（如 32→96），或接受“近并列时选择近似随机、由门禁兜底”——门禁合同不变，选错只在两个近并列候选之间损失真实差距。
3. **K=2 起步**：K=3 增益（+14.8 vs +10.1 局）不及训练时间 ×1.5 的代价且选对率更低；先 K=2，积累多轮“面板分 vs 门禁结果”后再复核。
4. **可选加速**：双训并行实测 1.23x 墙钟、+2.4 GiB 显存；如轮节奏吃紧，可把 _train_selected 的逐种子串行改为 2 路并行（需把两份训练峰值计入 estimate_peak）。
5. 生产切换由主控在组边界合并时做（无开关：历史已入队任务无 training_seeds 字段，自动走原单种子路径）。
