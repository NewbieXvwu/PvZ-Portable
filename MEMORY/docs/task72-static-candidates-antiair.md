1. **候选覆盖**：用 task71 的 L33 接手局（cactus_snow 卡组，老师输的那些），逐决策记录：
   - 气球在场或即将出场时（看僵尸表），仙人掌是否可种；
   - 是否进了候选集，进了的话叶值排第几、为什么没被选。
   - 用 `--frames` / `--leaf-probe` 这类只读诊断，不改老师。
2. **反事实**：同样的局面，把"仙人掌放在静态网给它的最好格"强行加进候选（只在诊断构建里，不进生产），老师照常 halving 加验证。量两件事：输局能不能翻、叶值是否认可仙人掌。同种子配对，至少 32 局。
3. **判断**：
   - 若主要是"没进候选"、强加后能翻：提出静态候选网多区重训的方案。说清数据（决策级、多区，含雾/屋顶）、标签（老师全候选叶值）、评估（候选召回率 + 配对胜率），写成可执行的任务书草稿。
   - 若进了候选但叶值低：问题在叶值网（v5 雾区未测），给出叶值侧的证据与方案。
4. 结论写 `MEMORY/docs/static-candidates-antiair.md`，提交并 `git push origin demo`。
