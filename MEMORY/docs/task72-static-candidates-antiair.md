# task72：L33 防空——老师的候选集里有没有仙人掌？静态候选网多区重训的第一步

> 主控 2026-10-24 写。执行者：Mac CodeBuddy（`cb-demo` 会话，接着 task71 做）。工作树 `/Users/newbiexvwu/PvZAgent/.claude/worktrees/demo`（分支 `demo`）。游戏进程最多 4 个；不停 p5d。

## 为什么
- task67：L33/34 老师冷启动输局里，气球到家 29 次；仙人掌在卡组里，每局只种 0.4–2.7 株。
- task71：从 L33 示范中途接手，老师 47 局输局里气球到家 42 次。
- task46：屋顶上，静态候选网 branch1 漏掉合法好动作是最大缺口。branch1 只在白天 L7 分叉数据上训过（v1 编码）。
- 猜测：老师不种仙人掌，是因为静态网没把仙人掌放进候选，搜索根本没评估它，而不是评估过后觉得它差。**先量清楚再定要不要重训。**

## 要做的
1. **候选覆盖**：用 task71 的 L33 接手局（cactus_snow 卡组，老师输的那些），逐决策记录：
   - 气球在场或即将出场时（看僵尸表），仙人掌是否可种；
   - 是否进了候选集，进了的话叶值排第几、为什么没被选。
   - 用 `--frames` / `--leaf-probe` 这类只读诊断，不改老师。
2. **反事实**：同样的局面，把"仙人掌放在静态网给它的最好格"强行加进候选（只在诊断构建里，不进生产），老师照常 halving 加验证。量两件事：输局能不能翻、叶值是否认可仙人掌。同种子配对，至少 32 局。
3. **判断**：
   - 若主要是"没进候选"、强加后能翻：提出静态候选网多区重训的方案。说清数据（决策级、多区，含雾/屋顶）、标签（老师全候选叶值）、评估（候选召回率 + 配对胜率），写成可执行的任务书草稿。
   - 若进了候选但叶值低：问题在叶值网（v5 雾区未测），给出叶值侧的证据与方案。
4. 结论写 `MEMORY/docs/static-candidates-antiair.md`，提交并 `git push origin demo`。

## 结果

- **覆盖扫描（第 1 步）**：L33 仙人掌卡组接手局 N=229/306/382 × 8 未来 = 24 局，`--frames`+`--leaf-probe` 只读。1969 个搜索决策（874 个气球在场）：仙人掌能种的只有 24%（53% 阳光不够、23% 冷却）；**能种就几乎总在评分集里**（候选集按构造给每卡最优格），且 35% 的时候是全场叶值第一、55 次被执行。"静态网没把仙人掌放进候选"不成立。
- **反事实（第 2 步）**：诊断包装 `_halving_choice`（不进生产）把每个合法仙人掌格强加进候选（平均 8.2 格/决策），4 点 × 8 = 32 局配对：胜率 9/32 → 11/32（2 局翻转、集中在 N=382），气球破防 14 → 15，仙人掌 5.06 → 5.81 株/局。**没有可检出的胜率差异，气球照破。**
- **判断（第 3 步）**：落在"进了候选但叶值低"分支——气球在场的决策 75% 全场最优叶值 < 0.02（推翻门槛），仙人掌的第一名常在门槛之下或被 9 未来复核否掉；v5 雾区未测，气球威胁没有进叶值。**不建议为防空重训静态候选网**；下一步是 v5 雾区敏感性探针（数据本文已备）与 v5 雾区重训（qc 雾格的帧已在生产路径上积累），经济侧（53% 付不起 125 阳光）与叶值同样大。正文见 [static-candidates-antiair.md](static-candidates-antiair.md)。

## 问题

1. `targets` 只记 halving 幸存者的叶值；被第一轮砍掉的仙人掌格拿不到值。要看第一轮完整值得再记一个只读诊断，本次没做。
2. 9→11/32 不显著（2 局、集中在一个点），按置信区间是"无可检出差异"。
3. "气球在场"按可见口径计数，雾藏掉的部分使气球压力被低估（保守偏差）。
4. `verification.seconds`（墙钟）仍被写进帧——task71 问题 2 指过，注释说墙时间不进档案但没做到，本次仍未动。


## 主控追加（2026-10-25，task72b）
结论收到：不重训静态候选网；瓶颈在叶值与经济。下一步做第 5 节里的探针，另加一项视界检验：
1. **v5 雾区敏感性**：同一批气球在场的接手局面（task72 的帧），配对比较"种仙人掌 vs 等待"的叶值差与 9 未来复核结果；把 halving 每一轮的值都记下来（问题 1），让被第一轮砍掉的候选也有值。
2. **视界**：现行 rollout horizon 2500 tick。气球从出场到家的时间对照这个视界：若后果落在视界之外，叶值只能靠价值网"预见"。用同一批局面，把 horizon 改为 4000 与 6000 只做诊断（不改生产），看仙人掌与等待的叶值差、最优值尺度（中位 0.0005）是否变化。不加开关：诊断脚本里传参即可。
3. **终局对照**：每个探针局面另跑"种仙人掌"与"等待"各 8 个未来打到终局，作为真值，算 v5 叶值差与终局胜率差的一致率（照 task46 的做法）。
4. 判断：若终局真值支持仙人掌、而 v5 叶值不支持 → 写 v6 叶值训练方案草稿（雾区决策级标签，数据来源与评估门禁），主控定；若视界加长后叶值就对了 → 给出视界与成本的权衡。结论追加到 `MEMORY/docs/static-candidates-antiair.md`。
