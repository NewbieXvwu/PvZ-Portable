# task144：LLMPlay 接口补上可见计时与按卡种植（GPT Pro 反馈）

主控 2026-10-28 派给台式机 cbp-task139（llmplay3 包的作者）。分支 `llmplay4`，以 `origin/llmplay3`（516c3c1c）为底。GPT Pro 第二轮仍在跑旧包，这一版给下一次会话用。

## 用户转述的 GPT Pro 反馈（跑了 9 小时）

1. **很多数据没有暴露，模型只能自己测**，比如咖啡豆唤醒、毁灭菇引爆的动画时长。这些在屏幕上都看得见：动画在播、蘑菇在膨胀、樱桃在变红。
2. **传送带关**：用掉一张卡后，后面的卡自动前移，“按固定卡槽位种”的写法失效。

## 要做的

1. **可见计时进观测**：查清引擎里哪些植物有屏幕可见的阶段或倒计时，逐个导出到 llmplay 的观测，在 PROMPT 里说明字段含义。包括：
   - 毁灭菇、樱桃炸弹、辣椒、寒冰菇的引爆倒计时；
   - 咖啡豆唤醒进度（已有 `wake_up_counter`）；
   - 土豆雷武装进度、大嘴花咀嚼剩余时间、窝瓜起跳；
   - 卡片冷却剩余。
   原则同 `MEMORY/notes/student-architecture.md`：只给屏幕上看得见的，不给未来出怪、随机数这类隐藏状态。
2. **常量表**：在包里附一份静态参考表，列每种植物的阳光、冷却，以及上面这些动作的时长（tick），数值从引擎源码取，不要凭记忆。
3. **按卡种植**：`plant` 接口除了槽位号，也接受卡片类型，比如 `plant(card="doom_shroom", row, col)`，在当前卡槽里找到这张卡；传送带关尤其要能用。观测里给出当前传送带的卡片列表（含位置）。旧的按槽位接口保留不变。
4. **顺带核对学生输入**：上面这些可见计时，学生网络的特征里（v2 / v2sleep）有哪些、缺哪些，列一张表。只出结论，不改学生；这些缺口会排进下一个输入版本。
5. 测试只跑相关的（台式机：`ulimit -v 8000000`，先看 `free -g`，最多 2 个游戏进程）。不加任何自我校验（AGENTS §6.5）。重新打包到 `~/pvz-llmplay4/`，冒烟一次传送带关的按卡种植。结论写在本文件末尾，推送分支。
