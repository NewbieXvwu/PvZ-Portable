# task69：同tick替换动作

## 实施约定

本任务只在replace分支实现与评估，不部署、不修改生产默认或增加生产开关。完整预登记见[任务书](task69-replace-action.md)，改前构建和模型哈希见[冻结基线](task69-baseline.json)。

replace以游戏原有工具命中逻辑决定被铲植物，再以原生CanPickUp/CanPlantAt判断铲后是否能种。失败必须回滚全部引擎/RNG状态；成功等价于同tick的原shovel、plant两动作。原生已合法的升级/叠种等仍用plant，扩展格才映射到replace，保持单一格子头的可表达性。相同植物按游戏解析模仿者后的有效SeedType判断，不把重新铲同卡作为新动作。

先实现与验证正确性，再测候选生成的性能成本；不能为速度用手写植物搭配规则代替游戏合法性。所有旧动作、快照与档案格式均须回归。示范原动作带保留，训练替换标签须由真实铲后同格种间隔和铲前实际合法性支持，不把不能同时支付的后续种植倒贴到早期标签上。

## 已实现与验证

- 引擎新增REPLACE与分支R编码；使用原铲子ToolHitTest、MouseDownWithTool及原种植流程，同tick执行。失败恢复既有内存快照、RNG及玩家档案。合法掩码也通过原生试铲后CanPlantAt生成，排除同有效SeedType，查询前后状态一致。普通/精简观测只扩展legal_actions，特征与存档布局不变。
- 老师静态候选按“动作类型、卡槽”分组，各保留per_card个最高值格（生产为1），普通种植与替换分别进同一halving及独立验证。没有惩罚、折扣或策略规则。记录初选、验证进入/撤销、执行/拒绝、实际消失/新增植物类型与阳光产生/花费/剩余。
- Python与C++学生共用原plant/packet/cell三头；原本可直接种的格仍用plant，其余合法占格用replace。卡槽/格子同分顺序一致。训练把replace编码为原种植正标签，实际动作与label仍分开保存；原动作的训练数组已与冻结源在日/夜/雾/屋顶回放逐位比对，历史缓存指纹继续兼容。
- 人类导出按同格下一次成功种植配对；重复铲子中断配对。N取实际配对间隔最大值，并完整报告分布及未配对铲子。逐tick原带回放时验证铲前原生替换是否合法、训练输入帧是否对应当时tick；不合法或错位不贴替换标签，原带不改。测试样本间隔[0,3]只证明实现，不能代替四局真实数据的N。
- 测试涵盖预算/冷却/同类型（含模仿者）拒绝、空格/越界、睡莲/花盆/南瓜/香蒲原生层次、墓碑、原生铲后种等价、快照/分支/回放确定性、静态值网与v5叶值、Python/C++续演及学生一致性。检查记录见[验证记录](task69-implementation-checks.json)。
