# task137：课程里加入 v5 随机卡组的格子（卡组泛化）

主控 2026-10-28 派给 Mac codex-plus2。分支 `deckcells`，以 `origin/selinc`（task136）为底；生产代码在 deploy14j+14k 换上后等于该分支的控制器与挑选文件。

## 背景

- task129（`origin/deckrules` 595e943b）：54 套 v5 规则卡组，搜索老师只赢 63/432（14.6%），连白天 L7 都有 3 套 0/8。老师在搜索里用学生做推演，所以老师和学生都只会打训练里见过的那几套卡组。**卡组泛化是头号短板。**
- 现在的课程格子几乎都是固定卡组：白天和泳池是 `[0,1,2,3,4,5,7]` 加地形卡，外加少量 d7q / 示范卡组。
- 课程控制器已有按胜率升降倍数的机制（auto curriculum）。随机卡组局输得多，产出的大多是老师赢不了的局，学不到东西。

## 要做的

1. 用 task129 的生成器（`deckrules` 分支）为白天、夜间、泳池、雾夜四区生成**一批固定登记的随机卡组族**：每区若干关 × 若干套，登记进 DESIGN，符合 AGENTS §8 第 4 条“换卡组就是换任务族”。
2. 把它们加进课程面板，作为新格子。允许倍数**低于 1.0**（例如从 0.5 起），让老师先能赢，再按现有升降规则往上走。查清引擎的出怪倍数是否支持 < 1；不支持的话，说明能用什么等价办法降难度，例如开局多给阳光，但不能改游戏规则以外的东西。
3. 格子的数量和采集占比要有上限（例如不超过每轮局数的 15%），别挤掉现有课程。写清每轮多花多少局。
4. 训练侧无需改动：这些局按普通课程行进入训练。但挑选和门禁里的“随机卡组族”要换用另外一批**没进训练**的卡组，避免拿训练过的卡组来评估泛化。
5. 小测试 + `scripts/qc_deploy14l.sh`：未激活和回滚分支照抄台式机最新 deploy 脚本的 `start_qc`；改面板或参数要说明是否需要排空流水线（尽量不需要）；部署前检查要便宜。
6. 只在 Mac 跑测试和少量冒烟对局（最多 4 个游戏进程）。结论写在本文件末尾，推送分支。不碰台式机 qc、状态文件和看门狗。
