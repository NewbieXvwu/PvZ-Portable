## 3. B 为什么不赢

A/B 从 **r26** 开始（不是 r27），每轮 A 两个种子（1、2）、B 两个（3、4）。
B 与 A 的唯一差别是 `source_weight`：

```
level_balance=0.25, level_balance_power=0.5, level_balance_max_multiplier=20
```

| 轮 | A 总胜 | B 总胜 | 选中 | B 的否决理由（selection.log 的 prediction） |
|---|---:|---:|---|---|
| r26 | 202 / 223 | 176 / 191 | A s2 | （无 prediction，gate v4 时代） |
| r27 | 217 / 220 | 202 / 197 | A s2 | — |
| r28 | 225 / 208 | 197 / 196 | A s1 | `overall_ci_lower` + `zone_regression:night` |
| r29 | 270 / 273 | 253 / **277** | A s1 | s3 带 `zone_regression:night`；s4 只差 overall |
| r36 | 284 / 278 | 238 / 246 | A s1 | s3 `zone_regression:pool,day`；s4 `night,day` |

分地形（r36，每格局数见括注）：

| | day (160) | night (88) | pool (88) | fog (88) |
|---|---:|---:|---:|---:|
| A s1 | **130** | 66 | **50** | 38 |
| A s2 | 121 | **71** | **52** | 34 |
| B s3 | 119 | 55 | 27 | 37 |
| B s4 | 119 | 53 | 34 | **40** |

**结论（三条，都有数字）**

1. **B 只在它抬权的区赢，在其余区大输。** B 把雾夜从 4.8% 抬到 16.2%、屋顶从 2.3% 抬到 10.3%，
   r36 的雾区确实略好（37–40/88 对 A 的 34–38/88），但池子 27–34/88 对 50–52/88、夜间 53–55 对 66–71。
   净效果是 `significant_zone_regression`，门禁直接否。
2. **平衡单位选错了。** B 用“关卡”做平衡，可问题是“卡组”：L7 一套卡组就占 45% 的行，
   按关卡压 L7 会连带压掉 L7 上**别的**卡组（L7 有 731 套），而真正稀缺的池/雾/屋顶卡组并没有变多。
3. **它抬权的是最脏的行。** 雾夜/屋顶那部分行大多来自失败局（r36 屋顶 0/16）和 v5 之前的旧标签，
   抬权等于放大噪声。B 从 r26 到 r36 六次全败，不是种子噪声（每轮 2 个种子同向）。

> 所以“加宽 B”不是解法。若仍想动宽度，那是容量实验（task158 那条线），不该混在数据配比臂里。

## 4. 建议（三个单变量对照，只写方案，不训练）

基线：22.6M 行 / 12 epoch / width 64 / batch 2048 → **单候选约 56 min**（42 次训练的中位数），
4 候选墙钟约 **3.8 h**（最多 2 个并发）；近 48 h 内有训练的分钟占 **62%**，整卡显存 2.9 GB / 16 GB。

### P1（首选）把 33 个 `z*` 历史标签的 `label_weight` 从 1.5 降到 0.5

- **改什么**：一个字典里的 33 个数，`recipe.json` 的 `label_weight`；不动代码、不动数据。
- **效果**：L7 有效占比 51.1% → **约 29%**；历史块权重 25.1% → 10.4%；其余格子相对权重自动上升。
- **成本**：行数不变，**训练时长与显存不变**（3.8 h / 4 候选）。
- **怎么判**：走现行挑选（task136 v5，456 局/模型，约 54 min）+ 门禁 v5（1920 对，约 92 min）。
  通过 = 门禁 `approved` 且**无任何 zone_regression**；同时看 `selection` 里 day 不掉超过 2pp
  （A 现在的 day 是 130/160，有 30 局余量）。
- **风险**：L7 是唯一“老师能稳定赢”的大块（白天 94/93），压太狠可能连 day 一起掉。0.5 是先验中间值，
  若 day 掉超过 2pp 就回到 1.0 重跑。

### P2 随机卡组格 96 → 576 局/轮，并把 8 套 rd137 评估卡组并入训练

- **现状**：16 个训练格 × 24 局/轮 ≈ 96 局（12.5%），只有 0.06% 的行；8 套评估卡组上学生 **3/64**。
- **成本**：每局约 19 s、15 worker → 多 480 局约 **+10 min/轮采集**；行数 +85k/轮（0.37%/轮），
  **训练时长不变**。
- **怎么判**：`selection_random_deck`（8 套评估卡组、每套 8 局）从 3/64 提到 ≥12/64（Wilson 下界 > 0.1），
  门禁不出现新的 zone_regression。
- **诚实的提醒**：每局只有约 177 个监督行（`wait_keep=0.1` 之后），所以**即使把整轮 768 局全给随机卡组，
  也才 0.6%/轮**，要 5% 得连续跑 8 轮。**P2 单独做不可能翻盘，必须和 P1 一起做**（P1 把分母压下来）。

### P3 按值网代次降权：v5 之前的标签 ×0.5

- **改什么**：`label_weight` 批量生成（1000 多个标签，脚本一行），不动代码。
- **效果**：pre-v5 权重 65.5% → 47.7%；v5 从 34.5% → 50% 左右。
- **成本**：行数、时长、显存都不变（3.8 h）。
- **怎么判**：同 P1 的挑选 + 门禁；重点看雾夜与泳池（v5 在这两区有 +67/−9 的实测收益，
  见 `MEMORY/2026-10-24.md:224`），这两区不涨就算无效。
- **风险**：v5 之前的行里包含 L7 早期最干净的 DAgger，降权可能同时削掉 day 的稳定面 → 与 P1 二选一先跑。

**不建议现在做的**：B 配方加宽到 128。B 的失败是配比方向错，不是容量；而且宽度翻倍会把
3.8 h 拉到 8–9 h，把每轮的训练/门禁节奏拖垮，属于架构实验（task158），不进数据配比臂。

## 瓶颈排序（按影响）

1. **分母陈旧**：每轮只 +0.4–2% 新行，包 98% 是旧数据；63.6% 的标签出自 v5 之前的老师。
   任何新格子（示范、随机卡组）都被 1365 万行的历史块稀释，**不先降旧块的权，新数据永远追不上**。
2. **卡组单一**：82% 的行压在 32 套固定卡组，一套占 45%（加权后 51%）；task129 的 54 套 v5 卡组训练里 0 行。
   池/雾/屋顶各只有 10–16 套。
3. **采集预算错配**：r42 起 75% 的局给了屋顶示范起点，教师胜率 93%、每局 96 行——
   花 75% 的时间买 3.6% 的行，而且这些行来自“已经赢了的局面”。
4. **门禁成本翻 5 倍且通过率低**：v5 门禁 89–93 min/轮，11 次只过 3 次；屋顶 90 对、雾夜 405 对里
   屋顶永远是 0–9%，这 90 对基本不产生信息。
5. **训练与轮次脱节**：45 个轮次里只有 14 轮真正训练完；r30–33、r37–38、r40、r43 有 recipe 没有模型，
   r39 与 r42 训练完却没有进挑选。训练中位 3.8 h、采集 1–2.4 h，**训练是轮次节奏的实际限速**。
